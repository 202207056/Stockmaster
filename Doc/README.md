## 처음 읽는 팀원에게

실행부터 확인하려면 [저장소 README](../README.md)의 팀원 실행 가이드를 먼저 읽습니다. 환경 설정, 로컬 DB 준비, 오류 확인까지 필요한 경우 [팀원 API 연동 실행 가이드](./팀원_연동_실행가이드.md)를 따라 진행합니다.

프론트는 실제 API를 호출하도록 연결되어 있습니다. 다만 **코드 연결 완료와 배포 서버에서 모든 기능이 정상 동작하는 것은 별개**입니다. 로그인·DB 조회·KIS 시세 조회를 각각 확인해야 합니다.

## 현재 구현 상태

| 항목 | 현재 상태 |
|---|---|
| 데이터 연결 | 목업을 제거하고 실제 API 응답을 사용. 실패 시 목업으로 대체하지 않음 |
| 인증·계좌 | 회원가입·로그인·사용자 정보·계좌 조회 연결. 데이터는 선택한 백엔드 DB에 저장 |
| 현재가·차트 | KIS 모의투자 API를 사용하는 백엔드 경로에 연결. 관심종목·차트 연결 오류는 실제 인증 요청과 서버 로그로 추가 확인 필요 |
| 홈 순위 | 거래대금·급상승·인기 종목 3개 영역, 각각 최대 5개 표시. 백엔드는 KIS 실전투자 키 사용 |
| 상단 주요 시세 | 해당 지표 API 미구현으로 `— / 준비 중` 표시 |
| 갱신 시점 | 화면 진입·종목 선택 등에 조회. 주기적 자동 갱신 없음. 트레이딩의 시세 새로고침은 현재가만 갱신 |
| 시세 기준시각 | 백엔드가 가격 기준시각을 전달하지 않아 정확한 기준시각·지연 여부 확인 불가 |
| 관심종목 목록 | 계정별 브라우저 로컬 저장. 기기 간 서버 동기화 없음 |
| 주문 | 백엔드 검증 보완 전까지 프론트 주문 전송 기본 비활성화 |
| 검증 | 프론트 린트·빌드·자동 테스트 14개 통과. 실제 로그인 후 모든 배포 API의 성공을 검증한 것은 아님 |

현재 우선 확인할 것은 관심종목·차트 요청의 실제 실패 원인, 서버의 KIS 설정과 오류 처리, 화면별 연동 결과입니다. 상단 지표 API와 주문 검증 보완은 별도 작업으로 관리합니다.

## 역할별 확인 순서

| 역할 | 확인 순서 |
|---|---|
| 팀장·전체 팀원 | 저장소 README → 연동 가이드의 화면별 점검·완료 체크리스트 |
| 프론트엔드 | 프론트 README → API 연동 구현기록 → 연동 가이드의 Network·Swagger 비교 |
| 백엔드 | 연동 가이드의 실패 요청 기록 → 대상 서버 로그·API 응답 → 프론트와 계약 확인 |
| DB 담당 | 연동 가이드의 로컬 DB 준비 → 마이그레이션·종목 데이터·계정 저장 확인 |
| AI 담당 | API 연동 구현기록 → 대상 백엔드의 설문·AI API 계약과 설정 확인 |

API 경로·입출력은 연결할 서버의 Swagger와 해당 버전의 코드를 함께 확인합니다. 배포 서버 명세 주소는 `https://gp-mock-inv.onrender.com/docs`입니다.

### 로컬 참고자료

이 작업 폴더의 `자료/`에는 기존 `00`~`13` 문서와 중간발표 PDF가 있습니다. 프로젝트 개요, 아키텍처, API·DB·KIS 설계, 과제 평가 등을 참고할 수 있습니다.

**`Doc/자료/`는 현재 `.gitignore`에 포함되어 있어 clone·pull로 전달되지 않습니다.** 따라서 이 README의 공유 문서 목록에는 해당 파일의 링크를 넣지 않습니다. 자료가 필요한 팀원은 별도 전달 여부를 확인합니다. 기존 문서는 작성 시점의 설계·계획을 포함하므로 현재 구현 상태로 단정하지 않습니다.

이전에 안내했던 `Doc/구현기록/`와 `Doc/_archive/`는 현재 작업 폴더에 없습니다. 새 프론트 기록은 `Doc/frontend 구현기록/`에서 관리합니다.

## 프로젝트의 기본 방향

- KIS는 외부 시세·차트·순위 조회에 사용하고, 회원·모의 계좌·주문·자산은 자체 백엔드에서 관리합니다.
- 모의투자와 경제학습을 연결하는 서비스이며, 학습·AI 관련 계획과 실제 구현 완료 여부는 구분해 기록합니다.
- 프론트에서 KIS 키나 DB 비밀번호를 직접 사용하지 않습니다. 프론트는 설정된 백엔드 API에 요청합니다.

## 문서 관리 기준

- 실행 명령·환경 설정·오류 진단 절차가 바뀌면 연동 가이드를 갱신합니다.
- 프론트 변경은 `frontend 구현기록/`에 변경 이유, 검증 결과, 남은 제한을 간단히 남깁니다.
- API 변경은 프론트·백엔드 담당자가 경로와 요청·응답 형식을 맞추고 배포 반영 여부도 확인합니다.
- 검증한 사실과 미검증 항목을 구분하고, 근거 없는 진척률이나 완료 표현을 사용하지 않습니다.
- 파일 이동·삭제 시 이 목차와 링크를 함께 수정합니다. 공유 문서는 Git 추적 여부까지 확인합니다.
- 비밀번호·토큰·API 키 등 비밀값은 문서나 Git에 넣지 않습니다.
