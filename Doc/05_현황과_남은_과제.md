## 1. 한 장 요약

- **무엇을 만드는가** — 한국투자증권 Open API로 **실제 시세**만 받아오고, 계좌·주문·체결·자산은
  **전부 자체 구현**한 모의투자 + 경제학습 플랫폼. AI가 투자 성향을 분석하고, 손실이 나면
  관련 개념 학습으로 연결한다.
- **전체 진척** — 약 **45~50%**. 백엔드 27개 엔드포인트가 Render에 배포되어 동작 중이고,
  React 프론트는 기반 작업과 UI 시안이 완료됐다. **둘이 아직 연결되지 않았다.**
- **가장 큰 남은 일 3가지**
  1. **백엔드 거래 로직 결함 4건 수정** (C-1~C-4) — 고치기 전에는 시연 금지
  2. **React ↔ 백엔드 API 연동** (F-11~F-20) — 최종 산출물이 React인데 연동 0%
  3. **학습 시스템·AI 실체 채우기** — 발표에서 약속한 차별점이 아직 비어 있음

## 4. 백엔드 — 발견된 결함 (2026-08-25 리뷰 기준)

> 총평: **구조는 정석대로 잘 잡혀 있습니다.** 레이어 분리·주석 품질·소유권 검증은 학부
> 팀 프로젝트 기준 상위권입니다. 문제는 **거래 로직의 정확성** 한 곳에 몰려 있습니다.

### 4-1. 🔴 치명적 결함 4건 — 시연 전 반드시 수정 (합계 약 3일)

| # | 결함 | 결과 | 수정 |
|---|---|---|---|
| **C-1** | 주문 가격을 **클라이언트가 지정** (`OrderRequest.price` 무검증) | 1원에 사서 시세로 팔면 **무한 수익**. Swagger에서 30초면 재현 | 서버가 KIS 현재가를 조회해 체결가 결정. 요청 `price`는 "지정가 희망값"으로만 쓰고 현재가 대비 ±30% 범위 검증 |
| **C-2** | 수량·가격 **음수 검증 없음** | `quantity:-100` 매수 시 **잔고가 증가**하고 보유수량이 음수가 됨 | `Field(..., gt=0)` + DB `CHECK (quantity > 0)`, `CHECK (hold_quantity >= 0)` |
| **C-3** | 매수 시 `balance`도 차감 → 주식 가치가 자산에 미반영 | `balance == withdrawable_cash`가 항상 성립. **랭킹이 "투자 안 한 사람" 순**으로 나옴 | `balance` 컬럼을 없애고 현금은 `withdrawable_cash` 하나로 관리. 총자산은 조회 시 `현금 + Σ(보유수량 × 현재가)`로 계산. 랭킹은 **일별 스냅샷 테이블** 기준 |
| **C-4** | 계좌 조회에 **행 잠금 없음** | 탭 두 개에서 동시 주문 시 **예수금 초과 매수** | `.with_for_update()` — `Account`와 `Portfolio` 양쪽에 적용 |

**완료 판정**

- [ ] `quantity: -100` 주문이 422로 거부된다
- [ ] `price: 1` 매수가 **시세로 계산**되어 잔고 부족으로 거부된다
- [ ] 동시 주문 2건 중 하나만 성공한다
- [ ] 매수해도 **총자산이 변하지 않는다** (수수료 제외)
- [ ] 매수해도 **랭킹이 떨어지지 않는다**

### 4-2. 🟠 높음 (9월 중)

| # | 항목 | 내용 |
|---|---|---|
| **H-1** | 모델↔DB 타입 드리프트 | 마이그레이션은 `Integer`인데 모델은 `Numeric(20,2)`. `autogenerate`가 되돌리는 마이그레이션을 만들고, 평단이 미세하게 틀어짐 |
| **H-2** | `httpx.AsyncClient(verify=False)` (2곳) | TLS 검증 없이 **APP KEY/SECRET이 전송**됨. `certifi` 최신화 → 실전 도메인 → 그래도 안 되면 `APP_ENV`로 분리 |
| **H-3** | KIS 시세 캐시·유량 제한 없음 | 요청마다 직접 호출. 폴링 도입 즉시 차단됨. **TTL 5초 캐시 10줄이면 해결** (토큰 23시간 캐시와 같은 방식) |
| **H-4** | 체결(`trades`) 테이블 없음 | 전량 매도 시 `Portfolio` 행을 삭제 → **실현손익·승률을 계산할 수 없음**. 자산 화면과 "손실→학습 트리거"의 전제 |
| **H-5** | 거래 규칙 검증 전무 | 수수료·증권거래세·장 운영시간·호가 단위·상하한가·거래정지 전부 없음. 새벽 3시에도 체결되고 327,123원 주문이 통과됨 |
| **H-6** | 뉴스 수집 방식 불일치 | 팀 설계문서는 "네이버 검색 API → 요약 → DB 저장"인데 실제는 **HTML 직접 크롤링**. 약관 리스크 + 선택자 변경 시 즉시 빈 배열 |

### 4-3. 🟡 중간 (10월 중)

CORS `["*"]` · `datetime.utcnow()` naive(거래시각 9시간 오차) · 리프레시 토큰/로그아웃 없음 ·
포트폴리오 N+1 · `total_value`가 평가금액이 아닌 매입금액 · 차트 TR이 최근 30일만 반환
(`FHKST03010100` 권장) · KIS 모의 도메인 사용 · 테스트 0건 · 에러 응답 형식 불일치 ·
Render 콜드스타트(첫 요청 15초+)

### 4-4. ✅ 잘한 점 (그대로 유지)

레이어 분리(routers/services/schemas/models/utils) · **주석 품질**(인수인계·심사 설명에 그대로 사용 가능) ·
**KIS 토큰 23시간 캐시** · `bcrypt==4.0.1` 핀 · **계좌 소유권 검증이 모든 경로에 일관 적용** ·
크롤링 실패 시 빈 배열 반환 · Alembic 마이그레이션 실운영 · **`demo.html` 7개 탭 데모**

## 10. 협업 규칙 — 계약 우선(Contract-First)

팀이 정한 `Pydantic 계약 → Mock 껍데기 → 병렬 개발` 방식은 **표준 패턴이고 옳습니다.**
실제로 이 방식 덕분에 백엔드 27개 엔드포인트와 `demo.html`이 나왔습니다.
다만 두 가지를 조정하세요.

**① 프론트는 이제 Mock이 아니라 배포된 실제 API를 씁니다.**
2단계는 이미 지났습니다. `VITE_API_BASE_URL=https://gp-mock-inv.onrender.com/api` 한 줄이면 됩니다.

**② 계약이 절반만 지켜지고 있습니다.**
`description`만 채우고 제약을 안 걸면 **문서 기능만 쓰고 검증 기능은 버리는 셈**입니다.
결함 C-2(음수 수량)는 계약을 제대로 썼다면 애초에 생기지 않았을 버그입니다.

```python
# 지금 (계약이 느슨함)
quantity: int = Field(..., description="주문 수량")
order_type: str = Field(..., description="주문 타입 (매수, 매도)")

# 계약을 제대로 썼다면
quantity: int = Field(..., gt=0, description="주문 수량")   # ← 음수 차단
order_type: Literal["매수", "매도"]                          # ← 오타 차단
```

**팀 규칙**

| 규칙 | 내용 |
|---|---|
| R-1 | **모든 엔드포인트에 `response_model` 필수** (현재 31개 중 19개가 스키마 없이 응답) |
| R-2 | 금액 타입 통일 — 문자열/숫자 혼재 금지 (숫자 권장) |
| R-3 | 계약 변경 시 **`03_API_명세서.md` 를 먼저 고치고** 팀에 공유한 뒤 코드 반영 |
| R-4 | 아직 없는 API는 1·2단계(스키마 + Mock 라우터)만이라도 먼저 |
| R-5 | 브랜치: `main` ← `develop` ← `feat/*`, PR 리뷰 1인 필수. **6명이 `main`에 직접 커밋 금지** |
| R-6 | 막히면 **2시간 규칙** — 혼자 2시간 이상 막히면 팀에 공유 |

**Definition of Done**

- 백엔드: Swagger 정상 응답 / **클라이언트가 보낸 금액을 신뢰하지 않음** / 잔고 변경 로직에
  `with_for_update()` / 금액은 `Decimal` / DB 변경은 Alembic / 핵심 로직 단위 테스트 1개 이상
- 프론트: 로딩·에러·빈 상태 모두 처리 / **하드코딩 목업 제거** / 콘솔 에러 없음 /
  보호 화면은 비로그인 접근 시 리다이렉트
