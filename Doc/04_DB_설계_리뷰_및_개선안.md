## 2. 현행 스키마의 문제 (우선순위순)

### 🔴 D-1. `account.balance`의 의미가 무너져 있음 — **최우선**

```python
# models/account.py 주석
balance            = 총 자산 (현금 + 보유 주식 평가금액)
withdrawable_cash  = 매수 가능 현금

# services/order_service.py 실제 동작 (매수 시)
account.withdrawable_cash -= total_amount
account.balance -= total_amount          # ← 총자산에서 매입액을 빼버림
```
→ `balance == withdrawable_cash`가 항상 성립. **보유 주식 가치가 자산에 전혀 반영되지 않음.**
→ `ranking_service`가 이 값으로 수익률을 계산하므로 **랭킹이 "투자를 안 한 사람" 순**으로 나옴.

**해결 (권장안)**: `balance`를 **저장하지 말고 계산**합니다.

```sql
-- balance 컬럼은 남겨두되 "원금(seed)" 용도로 재정의하거나, 아래처럼 명시적으로 분리
ALTER TABLE account RENAME COLUMN balance TO seed_cash;   -- 선택: 의미를 명확히
ALTER TABLE account ALTER COLUMN seed_cash SET DEFAULT 10000000;
```
```python
# 총자산은 조회 시점에 계산 (portfolio_service)
total_asset = account.withdrawable_cash + sum(p.hold_quantity * current_price(p.symbol_code)
                                              for p in holdings)
profit_rate = (total_asset - account.seed_cash) / account.seed_cash * 100
```

> 개명이 부담스러우면 **컬럼명은 `balance`로 두고 "원금"으로 의미만 재정의**해도 됩니다.
> 중요한 것은 **매수·매도 시 이 값을 건드리지 않는 것**입니다.
> 랭킹은 매 요청마다 전 유저 시세를 조회할 수 없으므로 **일별 스냅샷 테이블**(§4-2)을 기준으로 삼으세요.

### 🔴 D-2. 예수금 잠금(`locked_cash`) 없음
현행은 주문 = 즉시 체결이라 당장은 문제가 없지만, **미체결 지정가 주문을 도입하는 순간 필수**입니다.
또한 동시 주문 시 이중 지출을 막는 근거이기도 합니다. (`11` 문서 C-4)

### 🔴 D-3. 체결(`trades`) 테이블 없음
주문만 있고 체결 기록이 없어 **실현손익·수수료·세금·거래내역**을 만들 수 없습니다.
게다가 `_process_sell`은 **전량 매도 시 `portfolio` 행을 `db.delete()`** 하므로
"얼마에 사서 얼마에 팔았는지"가 사라집니다.
→ 자산 화면의 "총 수익", AI 코치의 "승률", 손실 학습 트리거가 **전부 이것에 의존**합니다.

### 🟠 D-4. 모델과 DB의 타입 드리프트
| 컬럼 | 모델 선언 | 실제 DB |
|---|---|---|
| `orders.price` | `Numeric(20,2)` | **`INTEGER`** |
| `portfolio.avg_price` | `Numeric(20,2)` | **`INTEGER`** |

`alembic revision --autogenerate` 실행 시 **Integer를 Numeric으로 되돌리는 마이그레이션이 생성**됩니다.
평균단가 계산 결과(`73333.33`)도 저장 시 잘립니다.

**해결**: 국내주식은 원 단위 정수이므로 **모델을 `Integer`로 맞추는 쪽**을 권장합니다.
```python
# models/order.py, models/portfolio.py
price     = Column(Integer, nullable=False)
avg_price = Column(Integer, nullable=False)
```
단, 평단 계산은 `Decimal`로 하고 저장 직전에 반올림하세요.
```python
portfolio.avg_price = int((Decimal(total_cost) / total_qty).quantize(Decimal("1"), ROUND_HALF_UP))
```

## 3. 현행 테이블 보강 (ALTER)

> 아래는 **Alembic 리비전으로 작성**하세요. 로컬 DB에 직접 실행 금지.

### 3-1. 1차 리비전 — 안전장치 (즉시 적용, `11` 문서 C-2/C-3 대응)

```sql
-- 음수 주문·잔고 방어
ALTER TABLE orders    ADD CONSTRAINT ck_orders_qty   CHECK (quantity > 0);
ALTER TABLE orders    ADD CONSTRAINT ck_orders_price CHECK (price > 0);
ALTER TABLE portfolio ADD CONSTRAINT ck_pf_qty       CHECK (hold_quantity >= 0);
ALTER TABLE account   ADD CONSTRAINT ck_acc_cash     CHECK (withdrawable_cash >= 0);

-- 포트폴리오 중복 방지
ALTER TABLE portfolio ADD CONSTRAINT uq_portfolio UNIQUE (account_id, symbol_code);

-- 조회 인덱스
CREATE INDEX idx_orders_account   ON orders(account_id, created_at DESC);
CREATE INDEX idx_orders_open      ON orders(symbol_code, status) WHERE status = '대기';
CREATE INDEX idx_portfolio_account ON portfolio(account_id);
CREATE INDEX idx_posts_symbol     ON posts(symbol_code, created_at DESC);
CREATE INDEX idx_comments_post    ON comments(post_id, created_at);
```

### 3-2. 2차 리비전 — 거래 기능 확장

```sql
-- 계좌: 예수금 잠금 + 원금 분리
ALTER TABLE account ADD COLUMN locked_cash NUMERIC(20,2) NOT NULL DEFAULT 0;
ALTER TABLE account ADD COLUMN seed_cash   NUMERIC(20,2) NOT NULL DEFAULT 10000000;
ALTER TABLE account ADD CONSTRAINT ck_locked CHECK (locked_cash >= 0
                                                    AND locked_cash <= withdrawable_cash);
-- 주문가능금액 = withdrawable_cash - locked_cash (컬럼으로 두지 말고 계산)

-- 주문: 지정가/시장가, 부분체결, 정정·취소 추적
ALTER TABLE orders ADD COLUMN order_kind      VARCHAR(10) NOT NULL DEFAULT 'LIMIT';
ALTER TABLE orders ADD COLUMN filled_quantity INTEGER     NOT NULL DEFAULT 0;
ALTER TABLE orders ADD COLUMN filled_amount   NUMERIC(20,2) NOT NULL DEFAULT 0;
ALTER TABLE orders ADD COLUMN reserved_cash   NUMERIC(20,2) NOT NULL DEFAULT 0;
ALTER TABLE orders ADD COLUMN reject_reason   VARCHAR(200);
ALTER TABLE orders ADD COLUMN updated_at      TIMESTAMPTZ;
ALTER TABLE orders ADD CONSTRAINT ck_filled CHECK (filled_quantity <= quantity);

-- 포트폴리오: 매도 예약 수량, 총매입금액, 누적 실현손익
ALTER TABLE portfolio ADD COLUMN locked_quantity  INTEGER       NOT NULL DEFAULT 0;
ALTER TABLE portfolio ADD COLUMN total_buy_amount NUMERIC(20,2) NOT NULL DEFAULT 0;
ALTER TABLE portfolio ADD COLUMN realized_pnl     NUMERIC(20,2) NOT NULL DEFAULT 0;
ALTER TABLE portfolio ADD CONSTRAINT ck_locked_qty CHECK (locked_quantity <= hold_quantity);

-- 종목: 시장 구분, 거래 가능 여부
ALTER TABLE item_master ADD COLUMN market     VARCHAR(20);   -- KOSPI / KOSDAQ
ALTER TABLE item_master ADD COLUMN is_active  BOOLEAN NOT NULL DEFAULT TRUE;

-- 시세 이력: 중복 적재 방지 (데이터 적재 시작 전에 걸어둘 것)
ALTER TABLE price_history ADD CONSTRAINT uq_price UNIQUE (symbol_code, time_frame, timestamp);
CREATE INDEX idx_price_lookup ON price_history(symbol_code, time_frame, timestamp DESC);

-- 사용자: 권한
ALTER TABLE users ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'USER';
```

### 3-3. 타임존 전환 (별도 리비전 권장)

```sql
-- 전 테이블의 DateTime → TIMESTAMPTZ (기존 값은 UTC로 해석)
ALTER TABLE users  ALTER COLUMN created    TYPE TIMESTAMPTZ USING created    AT TIME ZONE 'UTC';
ALTER TABLE users  ALTER COLUMN last_login TYPE TIMESTAMPTZ USING last_login AT TIME ZONE 'UTC';
ALTER TABLE orders ALTER COLUMN created_at TYPE TIMESTAMPTZ USING created_at AT TIME ZONE 'UTC';
-- posts, comments, user_survey_response, ai_propensity_advice, price_history 동일
```
그리고 코드에서 `datetime.utcnow()` → `datetime.now(timezone.utc)`로 교체하세요.
서버 타임존은 `TZ=Asia/Seoul`로 고정합니다.

## 4. 신규 테이블

### 4-1. `trades` — 체결 기록 ★ 최우선 신규

```sql
CREATE TABLE trades (
    trade_id       SERIAL PRIMARY KEY,
    order_id       INTEGER NOT NULL REFERENCES orders(order_id),
    account_id     INTEGER NOT NULL REFERENCES account(account_id),
    symbol_code    VARCHAR(20) NOT NULL REFERENCES item_master(symbol_code),
    order_type     VARCHAR(10) NOT NULL,          -- '매수' | '매도' (현행 표기 유지)
    price          INTEGER NOT NULL,              -- 체결단가
    quantity       INTEGER NOT NULL CHECK (quantity > 0),
    amount         NUMERIC(20,2) NOT NULL,        -- price * quantity
    fee            NUMERIC(20,2) NOT NULL DEFAULT 0,
    tax            NUMERIC(20,2) NOT NULL DEFAULT 0,
    settled_amount NUMERIC(20,2) NOT NULL,        -- 현금 증감(부호 포함)
    realized_pnl   NUMERIC(20,2) NOT NULL DEFAULT 0,   -- ★ 매도 시 실현손익
    realized_pnl_rate NUMERIC(8,4) NOT NULL DEFAULT 0, -- ★ 학습 트리거 판단
    avg_price_before  INTEGER,                    -- 체결 직전 평단 (설명·감사용)
    executed_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_trades_account ON trades(account_id, executed_at DESC);
CREATE INDEX idx_trades_symbol  ON trades(symbol_code, executed_at DESC);
```

> **매도 시 `portfolio` 행 삭제는 그대로 두어도 됩니다.** `trades`에 이력이 남기 때문입니다.
> 다만 `realized_pnl`을 반드시 여기에 기록해야 합니다.

### 4-2. `account_daily_snapshot` — 자산 추이·MDD·랭킹의 근거

```sql
CREATE TABLE account_daily_snapshot (
    snapshot_id    SERIAL PRIMARY KEY,
    account_id     INTEGER NOT NULL REFERENCES account(account_id) ON DELETE CASCADE,
    snapshot_date  DATE NOT NULL,
    cash           NUMERIC(20,2) NOT NULL,
    stock_value    NUMERIC(20,2) NOT NULL,   -- 보유주식 평가금액
    total_asset    NUMERIC(20,2) NOT NULL,   -- cash + stock_value
    total_pnl      NUMERIC(20,2) NOT NULL,
    total_pnl_rate NUMERIC(8,4)  NOT NULL,
    daily_pnl      NUMERIC(20,2) NOT NULL DEFAULT 0,
    max_drawdown   NUMERIC(8,4),             -- ★ 발표 "리스크 관리" 기대효과 대응
    created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_snapshot UNIQUE (account_id, snapshot_date)
);
```
> **이것이 있어야 랭킹이 정상화됩니다.** 매 요청마다 전 유저 시세를 조회할 수 없으므로,
> 장마감 배치(15:40)로 하루 한 번 적재하고 랭킹은 최신 스냅샷을 읽습니다.

### 4-4. 학습 도메인 ★ 발표 핵심기능 D4

> 🎉 `gp-mock-inv/졸업작품 프로젝트 - Google Docs.pdf`에 **경제 용어 약 60개의 설명 원고가
> 이미 작성되어 있습니다.** 새로 쓰지 말고 이것을 `glossary_term` 시드로 변환하세요.

```sql
-- 도움말 아이콘(ⓘ)이 참조할 용어 사전  ← Google Docs 원고 60개를 그대로 시드
CREATE TABLE glossary_term (
    term_id     VARCHAR(50) PRIMARY KEY,     -- 'per', 'order_book', 'limit_order'
    term        VARCHAR(50) NOT NULL,        -- 'PER'
    short_desc  VARCHAR(300) NOT NULL,       -- 툴팁 1~2문장
    long_desc   TEXT,
    example     VARCHAR(300),
    concept_id  VARCHAR(50),                 -- 심화 학습 연결 (FK는 아래 테이블 생성 후)
    category    VARCHAR(30)                  -- 기초/지표/차트/매매/리스크/해외
);

CREATE TABLE learn_concept (
    concept_id  VARCHAR(50) PRIMARY KEY,     -- 'stop_loss', 'diversification'
    title       VARCHAR(100) NOT NULL,
    level       INTEGER NOT NULL DEFAULT 1 CHECK (level BETWEEN 1 AND 3),
    category    VARCHAR(30) NOT NULL,
    summary     VARCHAR(300) NOT NULL,
    content_md  TEXT NOT NULL,
    est_minutes INTEGER DEFAULT 3,
    sort_order  INTEGER DEFAULT 0,
    is_active   BOOLEAN NOT NULL DEFAULT TRUE
);
ALTER TABLE glossary_term ADD CONSTRAINT fk_glossary_concept
    FOREIGN KEY (concept_id) REFERENCES learn_concept(concept_id);

CREATE TABLE learn_quiz (
    quiz_id     SERIAL PRIMARY KEY,
    concept_id  VARCHAR(50) NOT NULL REFERENCES learn_concept(concept_id) ON DELETE CASCADE,
    question    VARCHAR(500) NOT NULL,
    explanation TEXT,
    sort_order  INTEGER DEFAULT 0
);

CREATE TABLE learn_quiz_option (
    option_id  SERIAL PRIMARY KEY,
    quiz_id    INTEGER NOT NULL REFERENCES learn_quiz(quiz_id) ON DELETE CASCADE,
    content    VARCHAR(300) NOT NULL,
    is_correct BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE user_learn_progress (
    progress_id   SERIAL PRIMARY KEY,
    user_id       INTEGER NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    concept_id    VARCHAR(50) NOT NULL REFERENCES learn_concept(concept_id),
    status        VARCHAR(20) NOT NULL DEFAULT 'NOT_STARTED'
                  CHECK (status IN ('NOT_STARTED','IN_PROGRESS','COMPLETED')),
    quiz_score    INTEGER,
    attempt_count INTEGER NOT NULL DEFAULT 0,
    completed_at  TIMESTAMPTZ,
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_progress UNIQUE (user_id, concept_id)
);

-- ★★ 프로젝트 최대 차별화 포인트: 손실 → 학습 연결 ★★
CREATE TABLE learning_trigger (
    trigger_id   SERIAL PRIMARY KEY,
    user_id      INTEGER NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    reason       VARCHAR(30) NOT NULL
                 CHECK (reason IN ('REALIZED_LOSS','OVERTRADING','CONCENTRATION',
```

## 5. 반드시 지킬 데이터 무결성 규칙

| # | 규칙 | 위반 시 증상 | 현행 |
|---|---|---|:--:|
| I-1 | 체결 시 `orders` UPDATE + `trades` INSERT + `portfolio` UPSERT + `account` UPDATE를 **하나의 트랜잭션**으로 | 잔고 불일치 | 🟡 트랜잭션은 하나이나 `trades`가 없음 |
| I-2 | 계좌·포트폴리오 행 갱신 시 **`SELECT ... FOR UPDATE`** | 동시 주문 시 이중 지출 | 🔴 없음 |
| I-3 | 평가금액·평가손익은 **저장하지 않고 계산** | 시세 변동 시 값이 썩음 | 🔴 `balance`가 위반 |
| I-4 | 금액 계산은 `Decimal`, 저장 시 반올림 | 원 단위 오차 누적 | 🟡 일부만 |
| I-5 | 미체결 주문 취소 시 `locked_cash` 반환 | 잔고가 잠긴 채 사라짐 | ─ (미체결 미도입) |
| I-6 | 하루 한 번 자산 스냅샷 고정 | 과거 수익률 재현 불가 | 🔴 없음 |

### 정합성 검증 쿼리 (일일 배치로 실행)

```sql
-- 1) 포트폴리오 음수 수량 (있으면 즉시 사고)
SELECT * FROM portfolio WHERE hold_quantity < 0;

-- 2) 예수금 음수
SELECT * FROM account WHERE withdrawable_cash < 0;

-- 3) 체결 합계 vs 보유 수량 (trades 도입 후)
SELECT p.account_id, p.symbol_code, p.hold_quantity,
       COALESCE(SUM(CASE WHEN t.order_type='매수' THEN t.quantity ELSE -t.quantity END),0) AS calc_qty
FROM portfolio p
LEFT JOIN trades t ON t.account_id=p.account_id AND t.symbol_code=p.symbol_code
GROUP BY p.account_id, p.symbol_code, p.hold_quantity
HAVING p.hold_quantity <> COALESCE(SUM(CASE WHEN t.order_type='매수'
                                            THEN t.quantity ELSE -t.quantity END),0);

-- 4) 잠금 금액 정합성 (locked_cash 도입 후)
SELECT a.account_id, a.locked_cash, COALESCE(SUM(o.reserved_cash),0)
FROM account a
LEFT JOIN orders o ON o.account_id=a.account_id AND o.status='대기'
GROUP BY a.account_id, a.locked_cash
HAVING a.locked_cash <> COALESCE(SUM(o.reserved_cash),0);
```

## 6. 적용 절차

| 단계 | 작업 | 시점 |
|:--:|---|---|
| 1 | 모델 타입 드리프트 해소 (D-4) — 모델을 `Integer`로 | **즉시** |

### 팀 규칙
- 스키마 변경은 **반드시 Alembic 리비전**으로. Supabase 콘솔에서 직접 ALTER 금지.
- `autogenerate` 결과는 **항상 사람이 읽고 수정**한 뒤 커밋 (특히 타입 변경 시 `postgresql_using` 필요).
- `Database/Table`(DBML)은 현행과 이미 어긋나 있으므로, **실물 기준으로 갱신**하고
  파일명을 `Database/schema.dbml`로 바꾸세요. (ERD 이미지는 발표 산출물로도 필요)
