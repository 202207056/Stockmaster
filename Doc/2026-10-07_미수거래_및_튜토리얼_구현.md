# 미수거래와 위험 체험 구현

확인일: 2026-10-07. 기존 [고위험 금융투자 조사](./자료조사/2026-10-06_고위험금융투자_조사.html)의 4장·13장을 바탕으로 구현했다. 이 문서는 사이트의 모의거래 계약이며 실제 증권사의 거래 약관이 아니다.

## 사용자 흐름

트레이딩의 매수 창에서 **미수거래**를 누르면 같은 자리에 현재 주문 폼을 사용하는 체험이 열린다. 계좌·입력값은 별도의 컴포넌트 메모리에서 유지하며 주문·상환 API를 호출하지 않는다. 다른 화면으로 이동하지 않고 현재 항목을 따라 안내가 이동한다. 배경은 어둡게 하지 않는다. 퀴즈는 없다.

1. 위험부터 설명한다: 반대매매, 자기자금 초과 손실, 이용 제한.
2. 예시 현금 100,030원, 주당 50,000원에서 수량을 4주로 바꾼다.
3. 주식값 200,000원 + 매수 수수료 30원, 부족금 100,000원을 확인하고 예시 매수를 누른다.
4. 주가 10% 하락 → 평가액 180,000원 → 부족금 차감 후 80,000원. 시작 현금 대비 손실은 20,030원으로 약 20%다.
5. 휴일 없는 월요일 매수·수요일 결제와 화요일 매도·목요일 결제를 비교한다. ‘팔았으니 제때 갚았다’는 오해를 교정한다.
6. 60% 급락 후 80,000원에 전량 매도하는 사례에서 수수료 12원·세금 144원을 차감하면 79,844원만 갚을 수 있고, 20,156원이 남는다. 연체 비용을 제외한 모의 사례다.
7. 기본 종료는 **체험 종료 · 현금 유지**다. **위험 확인 · 미수 선택**을 별도로 눌렀을 때만 선택한 계좌의 이번 주문에 미수가 켜진다. 계좌 변경·매도 전환·체결 후에는 현금 방식으로 돌아간다.

현재 테스트 요구에 따라 버튼을 누를 때마다 체험이 열린다. 학습 탭의 ‘미수거래 체험 다시 시작’, 트레이딩의 ‘위험 체험 다시 보기’, `/trading?misuTour=1`로 재시작한다. 로그인 없이 체험할 수 있지만 실제 모의계좌 주문은 인증이 필요하다.

## 실제로 저장되는 모의 기능

| 항목 | 구현 계약 |
|---|---|
| 대상 주문 | 사이트에서 조회 가능한 국내 주식의 즉시 시장가 매수. 지정가·호가 주문·예약·조건 주문과 미수 결합은 지원하지 않으며 서버도 거부 |
| 증거금 | 거래대금의 50%를 원 단위 올림 + 매수 수수료 전액. 실제 종목의 미수 가능 여부·증거금률을 뜻하지 않음 |
| 현금 사용 | 보유 현금을 먼저 사용하고 나머지만 부족금으로 기록. 현금으로 전액 낼 수 있으면 현금 주문을 안내 |
| 가격 | 서버가 조회한 당일 2분 이내 체결 시세. 거래일 한국시간 09:00~15:20에만 미수 매수. 시세 누락·오래된 시세·감시 미준비 시 거부 |
| 결제 | 체결일 다음 두 거래일을 센 T+2의 17:00 한국시간. XKRX 휴장일 달력 사용. 주말·공휴일·연말 휴장일 제외 |
| 계좌 제한 | 부족금 또는 결제 대기 매도대금이 있으면 모든 신규 매수를 제한. 예약·조건 주문 실행과 기존 대기 매수 체결도 동일 검사 |
| 매도 | 미수 부족금/결제 대금이 남은 계좌의 매도는 현금으로 즉시 쓰지 못하며 T+2의 17시에 부족금부터 충당. 남는 돈만 현금으로 반영 |
| 상환 | ‘모의 입금으로 갚기’에서 금액 입력 후 확정. 실제 돈 없이 가상 외부 자금을 추가해 부족금 상환. 부족금 초과 입금 불가 |
| 기한 경과 | 부족금이 남으면 해당 계좌의 미수 이용을 다음 거래일 09:00부터 30일 제한. 상환해도 제한 기간 유지. 현금 주문은 남은 결제 처리가 끝난 뒤 가능 |
| 반대매매 | 다음 거래일 09:00 이후 30초 주기의 감시에서 신선한 시세가 있을 때 모의 매도. 미결제 매도대금을 감안하고 필요한 수량부터 처분. 부족하면 다른 보유종목도 대상 |
| 처분 실패 | 시세 없음/오래된 시세에서는 처분하지 않고 재확인. 전량 처분 후에도 부족금이 남으면 장부에 계속 보존 |
| 자산 | 현금 + 보유 평가액 + 결제 대기 매도대금 − 남은 부족금. 음수도 그대로 표시 |

반대매매는 보유 행 순서대로 처분하며 실증권사의 종목별 우선순위·하한가 기준 수량 산정·호가 잔량·부분 체결·슬리피지를 재현하지 않는다. 최근 체결 시세가 있다고 그 가격에 전량 팔 수 있다는 보장은 실제 시장에 없다. 거래정지 중 새 체결이 없으면 모의 처분도 보류된다. 연체 이자·연체료는 이번 버전에서 부과하지 않는다.

현금 일반 주문의 기존 즉시 현금 반영 방식은 유지한다. 따라서 사이트 전체가 실제 증권사와 동일한 결제 원장을 구현한 것은 아니다. 미수 상태에 한해 지연 매도대금과 채무 장부를 적용한다. 가상 외부 입금이 들어가는 만큼 기존 단순 잔고 랭킹을 미수 투자 성과 평가에 사용하면 안 된다.

## 서버 데이터와 안전성

백엔드 위치: `D:\pros\gp-mock-inv\backend`.

- `orders.funding_type`: 현금 / 미수 / 반대매매 구분.
- `misu_debts`: 최초 부족금, 잔여 부족금, 주문 연결, 납부·처분 시각, 이용 제한 종료, 요청 UUID.
- `misu_settlements`: 매도 주문별 결제대금, 결제시각, 처리 여부.
- `misu_payments`: 모의 외부 입금액, 시각, 요청 UUID. 교육용 외부 입금이며 은행 이체 API가 없다.
- 조회 `GET /api/trading/misu/{account_id}`; 상환 `POST .../{account_id}/repay`; 현재 시각의 결제 처리 `POST .../{account_id}/settle`.
- 기존 주문 API에 `funding_type: "미수"`, `client_request_id: UUID`, `misu_risk_ack: true`를 전달한다. 별도 주문확인 창에서 최종 제출한다.
- 소유 계좌를 검사하고 PostgreSQL 계좌 행 잠금을 먼저 획득한다. 계좌·보유수량·주문·채무·결제 기록을 한 트랜잭션으로 저장한다. 요청 UUID와 계좌의 유일 제약으로 중복 미수 주문과 중복 입금을 방지한다.
- GET은 장부를 변경하지 않는다. 감시 프로세스와 명시적 POST가 결제를 처리한다. 서버가 늦게 재시작해도 예정 결제시각 순으로 처리해 제때 들어온 매도대금을 연체로 오인하지 않는다.
- 실증권사 주문 API를 호출하지 않는다. 학습 완료를 투자 적합성 판정이나 공인 교육 이수로 표시하지 않는다. 위험 확인은 서비스의 모의 기능 선택이며 실증권사 계약 체결이 아니다.

## 서버 적용 순서

운영/공유 DB와 외부 배포는 이번 로컬 작업에서 변경하지 않았다. 새 백엔드는 아래 스키마 적용과 함께 배포해야 한다. 기존 서버에 프론트만 올린 상태에서는 미수 상태 API를 확인하지 못하므로 미수 주문이 차단된다.

```powershell
# backend 폴더, 해당 환경의 가상환경에서 실행
python -m pip install -r requirements.txt
alembic upgrade head
# 이후 API 서버 재시작
```

마이그레이션: `e20261007_misu` (부모 `d20261006_automations`). 새 코드의 일반 주문·포트폴리오도 미수 장부를 참조하므로 **마이그레이션 전에 새 백엔드로 교체하면 안 된다**. 미수 장부가 없는 서버는 미수 감시를 시작하지 않는다. 프로덕션 DB를 대상으로 명령을 실행하기 전에 운영 절차에 따라 백업·적용 대상을 확인한다.

프론트는 해당 백엔드의 `VITE_API_BASE_URL`, 검증된 환경의 기존 `VITE_ENABLE_ORDER_SUBMISSION=true` 설정을 사용한다. 미수 감시의 최근 정상 실행이 확인되지 않으면 신규 미수 주문을 거부한다. 미수 결제 내역에 감시 중단 상태를 표시한다.

`holidays==0.106`의 XKRX 달력은 휴장일 계산 자료이며 거래소의 실시간 공식 일정 API가 아니다. 임시 휴장·제도 변경 시 달력 버전과 실제 공지를 대조하고 갱신해야 한다. 최초 미수 매수와 반대매매에는 당일 최근 체결 시세도 함께 요구한다.

## 교육·법률·윤리 검토

고위험 기능을 수익 확대 도구로 홍보하지 않는다. 손실·현금흐름·강제처분을 먼저 설명하고 현금 유지 종료를 기본으로 둔다. 타사 이미지나 설명서 문장을 복제하지 않고 자체 예시와 계산을 사용한다. 튜토리얼에서 개인정보 수집·계좌 변경·외부 전송·투자 추천·공인 수료 인증을 하지 않는다.

실제 국내 주식은 T+2 결제이며 회사가 납부 시각을 정한다. 원칙적 미수동결 30일, 소액 등 예외, 다른 증권사 계좌에도 미칠 수 있는 영향과 모의 규칙을 구분해 설명한다. 50% 증거금, 17시 마감, 소액 예외 없는 단일 계좌 제한, 동일 수수료율은 이 사이트의 가정이다. 법률 검토 의견서나 서비스 적법성 인증을 대신하지 않는다.

교육 효과를 실제 초보 학습자로 측정하지는 않았다. 퀴즈를 추가하지 않고 출시 전 관찰 면담으로 ① 부족금 설명 ② 납부일과 매도 결제일 구분 ③ 주가 하락률과 자기자금 손실률 차이 ④ 전량 처분 후 남은 채무 이해를 확인한다. 완료율·수익률을 이해도 증거로 사용하지 않는다.

- [python-holidays 공식 프로젝트](https://github.com/PPsyrius/python-holidays): XKRX 휴장일 달력 구현.

## 검증

격리된 SQLite와 시세 응답으로 증거금·수수료, 서버 가격, 인증, 중복 주문·입금, 결제 날짜, 휴장·연말, 추가 매수 제한, 당일/익일 매도의 결제 차이, 재시작 뒤 처리, 시세 누락, 반대매매 잔여 채무를 검사한다. 프론트는 미수 버튼 진입, 계좌와 분리된 체험, API 미호출, 명시적 선택과 주문확인 후 제출, 반복 실행, 크기 변경, 음수 순자산을 검사한다.

실제 PostgreSQL의 동시 요청 부하와 배포 서버의 KIS 연동·감시 실행은 아직 운영 환경에서 검증하지 않았다. 외부 계좌에 시험 주문을 만들지 않았다.

최종 로컬 결과: 프론트 전체 106개, 백엔드 주문·미수 40개 통과. 모바일 안내 스크롤 보완 후 매수·미수 관련 10개를 재검증했다. ESLint와 프로덕션 빌드를 통과했으며 기존 공통 번들의 크기 경고는 남아 있다. 신규 마이그레이션의 적용·되돌리기를 격리 SQLite에서 확인했다. 브라우저에서 데스크톱 진입과 390px 화면의 수량 조작·금액 강조·결제일 비교·반대매매·현금 유지 종료를 확인했다. 긴 안내에서도 진행 버튼을 유지하고 창 내부 스크롤이 위치 재계산으로 초기화되지 않도록 보완했다.
