## 구현 결과와 수정 기준

학습 목적은 사이트의 기능과 확인 위치에 익숙해지는 것이다. 계산 문제·정답 입력·선택지·채점·좌우 학습 패널을 제거했다. 실제 `Trading.jsx`와 `Assets.jsx`를 그대로 렌더링하고, 기존 `TutorialStart`·`TutorialTarget`·`OrderDialog`로 설명을 덧붙인다. 주문 폼·비용 표시·계좌 선택·차트·주문내역·자산 표는 일반 이용과 같은 컴포넌트다. 각 과정의 차이는 실제 사용하는 기능과 안내 순서다.

`/trading?practice=buy`처럼 기존 사이트 주소에 연습 모드를 지정한다. 별도 `/learn/tutorial/:id` 주소는 호환용으로만 남겨 해당 사이트 주소로 이동시킨다. 제목은 개념·기능명으로 표시하고 상황은 카드 설명에 짧게 쓴다. 기존 `/learn/trading-tutorial`과 기존 기본 가이드들은 삭제하지 않았으며 예비 연습에서 이용한다. 기존 매수·매도 연습에는 비용·결제 시차 생략 안내를 추가했다.

| 학습 제목 | 직접 사용하는 기능 | 확인하는 정보 |
|---|---|---|
| 매수와 거래 비용 | 검색 → 종목 선택 → 계좌 선택 → 수량 입력 → 비용 기준 펼치기 → 주문 → 내역 → 내 자산 | 매수대금과 수수료, 현금에서 주식으로 바뀐 자산, 비용 포함 원가 |
| 매도와 실현손익 | 보유 주식의 매도 입력 → 비용 확인 → 주문 → 체결내역 → 보유종목 | 순수령액, 거래대금 기준 세금, 매도 실현손익과 잔여 평가손익 |
| 주문 확인과 체결내역 | 주문 확인 창 열기 → 전송 전 취소 → 내역 확인 → 다시 주문 → 내역 새로고침 | 확인 창과 주문 실행의 차이, 취소 시 무부과, 중복 주문 전 내역 조회 |
| 계좌 선택과 자산 조회 | 내 자산의 계좌 전환 → 자산·원가·보유종목 확인 → 종목명으로 트레이딩 이동 | 계좌별 데이터, 이동 후 유지된 주문 계좌 |
| 체결과 결제 | 매도 → 내 자산 이동 → 현금·원가 확인 | 사이트의 즉시 현금 반영과 실제 T+2 결제·출금의 차이 |
| 매매와 계좌 확인 | 매수 → 내 자산 → 종목명으로 돌아가기 → 일부 매도 → 내역 → 내 자산 | 거래와 자산 조회를 왕복하며 비용·보유수량을 확인하는 사용 흐름 |

수량 입력은 실제 주문의 입력이며 계산 답안이 아니다. 예시 권장 수량은 매수 10주지만 정확히 그 숫자를 맞혀야 하는 구조가 아니다. 유효한 수량과 현금·보유수량 조건을 검사한다. 설명을 읽는 단계의 `확인했어요`는 채점 없이 안내를 넘긴다.

## 연습 데이터의 분리

- 연습 모드에서만 페이지 본문에 임시 인증·계좌 컨텍스트를 제공한다. 실제 로그인·선택 계좌·토큰·관심종목을 변경하지 않는다.
- 기본 예시 계좌는 현금 500,000원, 매매 연습 계좌는 초기 현금 1,000,000원이다. 매도·계좌·결제 과정에는 10주를 이미 매수한 상태를 준비한다. 준비된 매입원가 500,070원과 잔여 현금 499,930원을 명시한다.
- 종목명·코드·가격·차트는 연습 데이터다. 연습 체결가는 50,000원으로 고정한다. 실제 시세·뉴스·코칭인 것처럼 표시하거나 외부 계좌 API로 보내지 않는다.
- `useSiteResource`는 명시적인 연습 컨텍스트 안에서만 로컬 데이터를 읽는다. 일반 모드의 API 실패를 예시 데이터로 대체하지 않는다.
- 연습 주문은 메모리의 `executePracticeOrder`만 호출한다. 재시작·새로고침·연습 종료 시 초기화하며 실제 주문 API, 계좌 저장, 학습 결과 저장을 하지 않는다.
- 트레이딩 ↔ 내 자산의 안내 링크는 동일한 연습 계좌와 진행을 유지한다. 일반 메뉴로 연습을 떠나면 종료된다. 실제 계좌와 혼동하지 않도록 연습 중 미니 자산창은 숨긴다.

## 미구현 기능과 판단

미수·선물·신용융자·공매도·레버리지 ETF·옵션은 기존 사이트에 해당 거래·계좌 기능이 없다. 이전에 만든 독립 문제풀이 과정을 삭제하고 실행 가능한 튜토리얼 목록에서 제외했다. 현재 현금 주식 주문 폼을 파생상품 주문처럼 가장하거나, 임의의 가상 화면으로 기능을 대신하지 않는다. **이들 심화 튜토리얼은 완료된 것이 아니다.**

같은 이유로 실제 제공하지 않는 부분 체결·미체결 정정/취소·은행 입출금·결제일 이동을 조작한 것으로 처리하지 않는다. 주문 과정의 취소는 전송 전 확인 창 닫기이며, 체결 취소가 아니라는 설명을 붙였다. 실제 주식의 T+2는 자산 금액을 읽는 맥락에서 설명하되 출금 기능을 구현했다고 표현하지 않는다.

향후 심화 과정에는 우선 사이트의 해당 기능이 필요하다. 미수는 종목별 증거금·결제 부족·납부·반대매매 상태, 선물은 상품명세·계약수·거래승수·증거금·일일정산·청산, 신용융자는 약정·기간별 이자·상환, 공매도는 대차·매도·재매수·반환·차입비용, ETF/옵션은 상품별 세금·보수 또는 프리미엄·결제 방식을 실제 주문·자산 구조에서 처리해야 한다. 구현 당시의 공식 상품·증권사 기준을 재검증하고 그 기능 위에 안내를 붙인다. 이전 기획의 숫자나 제거된 연습의 비율을 실제 거래 설정으로 가져오지 않는다.

## 수수료·세금 설정 요약

정책 버전: `KR-EQUITY-2026-01-v1`, 세율 적용 기준일 2026-01-01, 확인일 2026-09-30.

| 구분 | 매수 | 매도 | 부과 기준 |
|---|---:|---:|---|
| 증권사 수수료 | 0.015% | 0.015% | 각 체결대금 |
| 코스피 증권거래세 | 없음 | 0.05% | 매도대금 |
| 코스피 농어촌특별세 | 없음 | 0.15% | 매도대금 |
| 코스닥 증권거래세 | 없음 | 0.20% | 매도대금 |
| 코스닥 농어촌특별세 | 없음 | 없음 | 해당 매도에 별도 부과하지 않음 |

수수료는 법정 세율이 아니다. 증권사·매체·계좌·이벤트에 따라 달라 단일한 업계 공통 또는 통계적으로 가장 많이 쓰는 요율로 단정할 수 없다. 대표적인 저비용 온라인 기본요율인 키움증권 0.015%를 채택했으며 우대·이벤트는 제외했다. 실제 사용자 계좌의 증권사 요율을 추정한 값이 아니다.

세금은 차익이 아닌 매도대금 기준으로 계산한다. 손실 매도에도 부과된다. 일반 코스피·코스닥 상장주식에만 적용하며 ETF·ETN·배당소득세·대주주 등의 양도소득세·파생상품 과세는 이 계산에 포함하지 않는다.

단일 체결 주문별 수수료는 10원 미만 버림, 세금은 세목별 1원 미만 버림으로 구현했다. 수수료 단수 기준은 선택한 증권사 안내를 따른다. 이는 모든 증권사의 복수 체결·일별 합산 방식을 재현한다는 뜻이 아니다. 프론트는 정수 ppm 및 BigInt, 백엔드는 Decimal을 사용하며 두 정책 JSON의 일치 여부를 검사한다.

### 실제 적용 예시

50,000원 × 10주 매수: 매수대금 500,000원, 수수료 70원, 총 필요금액 500,070원. 초기 현금 1,000,000원에서 잔여 현금은 499,930원이다. 주가가 그대로면 총자산은 999,930원이며 주식 원가에는 수수료가 포함된다.

그중 5주를 같은 가격으로 코스피 매도: 매도대금 250,000원, 수수료 30원, 거래세 125원, 농특세 375원, 순수령액 249,470원. 배분 원가 250,035원 대비 실현손익 -565원, 잔여 주식 평가손익 -35원. 현금 749,400원과 주식 평가금액 250,000원을 합한 총자산은 999,400원이다. 이 예시는 검증용이며 사용자에게 계산 답을 요구하지 않는다.

## 사이트 모의투자의 비용 처리

이번 변경은 안내 문구에 그치지 않고 별도 백엔드 저장소에도 구현했다.

- `GET /trading/orders/cost-policy?symbol_code=...`로 정책 버전과 종목 과세 분류를 확인한다. 비용 정책을 제공하는 서버에서 버전 불일치 또는 미분류 종목은 주문을 막는다.
- 현재 작업트리에는 구버전 서버 주문 호환 경로도 존재한다. 정책 API가 404이고 OpenAPI 명세로 구버전 주문 계약이 확인된 경우 기존 주문을 허용한다. 이 경로는 서버에 비용 처리 기능이 없으므로 이번 수수료·세금을 부과하지 못한다. **일반 모의투자에 비용이 실제 반영되려면 반드시 신규 백엔드·DB 마이그레이션을 배포해야 한다.** 연습 모드는 구버전 경로를 사용하지 않는다.
- 주문 요청에 `cost_policy_version`을 전달한다. 서버가 시세를 다시 조회하여 체결가격과 실제 비용을 결정한다. 클라이언트가 보낸 가격을 비용 계산의 근거로 신뢰하지 않는다.
- 매수는 매수대금과 수수료를 현금에서 차감하고 수수료를 취득원가에 포함한다. 매도는 수수료·세금 차감 후 순수령액을 현금에 반영하고 배분 원가로 실현손익을 계산한다.
- 주문에 수수료·각 세목·현금 증감·정책 버전·매도 실현손익을 저장한다. 조회 시 현재 요율로 과거 거래를 다시 계산하지 않는다.
- 포트폴리오에는 비용 포함 취득원가를 저장한다. 일부 매도 시 소수점 6자리로 배분하고 최종 전량 매도는 잔여 원가를 모두 사용한다. 평균단가는 체결가격 기준으로 유지한다.
- 주문내역과 주문 완료 창에서 실제 비용을, 내 자산과 미니 자산창에서 비용 포함 원가·평가손익을 표시한다.
- 이전 거래의 미기록 비용은 `NULL`로 남겨 ‘과거 미기록’으로 표시한다. 소급 부과하지 않는다. 과거 포트폴리오 원가는 기존 평균단가 × 수량으로 이전한다.
- 사이트는 비용 차감 후 현금을 즉시 반영한다. 실제 시장의 결제 대기·출금 제한·미수 금융을 구현한 것은 아니다.

## 내용 검증과 용어 정리

주문 접수와 체결, 체결과 결제, 재사용 가능한 현금과 출금가능금액, 체결단가와 비용 포함 원가, 평가손익과 실현손익을 구분했다. 시장가의 가격 보장·손절 주문의 실행 보장·분산투자의 손실 방지처럼 오해할 수 있는 표현을 정정했다. 기존 과정 제목은 상황형 질문 대신 개념명으로 바꾸고 상황 설명은 별도로 표시했다.

용어집에서는 PBR의 분모(BPS), EPS의 가중평균 주식 수, PER·ROE·52주 가격의 해석 한계, 캔들 색의 시가/종가 비교 기준, 시가총액과 기업가치, 권리락·배당락과 시장가격, 거래대금 합산, 가격제한폭의 예외, 예수금·결제 표현 등을 점검·수정했다. 가격 전망이나 특정 비율을 투자 정답으로 제시하지 않는다.

## 검증 및 배포 상태

최종 작업트리 기준 프론트 린트·프로덕션 빌드 통과, 자동 테스트 67개 통과, 백엔드 unittest 34개 통과. 신규 조작 테스트는 실제 Trading/Assets 컴포넌트에서 6개 과정의 완료·초기화, 페이지 왕복, 전송 전 취소 및 재진입, 권장 수량과 다른 유효 수량 주문, 비용·원가 반영, 연습 중 API 호출 0회를 확인했다. 계산 테스트는 시장별 비용·단수 처리 경계·잔고 부족·초과 매도 거절·계좌 격리·부분 매도 원가를 검사한다. 백엔드 검증은 메모리 SQLite 트랜잭션과 테스트 API를 사용한다. Alembic 오프라인 SQL 생성도 통과했으며 대상 DB에는 적용하지 않았다.

브라우저 연결이 제공되지 않아 실제 브라우저의 화면 배치·팝업 위치 확인은 미완료다. DOM 조작 검증을 시각 검증으로 표현하지 않는다. 빌드에는 500kB 초과 번들 경고(약 578kB)가 남아 있다. 테스트에서 Vite HMR 포트 중복 경고가 있었지만 테스트 실패는 없었다. 백엔드에는 기존 datetime/테스트 스트림 관련 경고가 남아 있다.

**운영 배포와 실제 DB 마이그레이션은 실행하지 않았다.** 프론트와 백엔드는 별도 저장소이므로 둘 다 반영해야 일반 모의투자에 비용이 적용된다. 기존 주문 전송 기능 플래그도 임의로 활성화하지 않았다.

반영 순서:

1. 대상 DB 백업과 현재 Alembic revision을 확인한다. 이번 revision은 `c20260930_cost_policy`, 이전 revision은 `2622474e79f5`다.
2. 백엔드 코드와 의존성을 반영하고 `backend`에서 대상 환경 설정으로 `alembic upgrade head`를 실행한다. 이번 작업에서는 오프라인 SQL 생성만 검증했다.
3. 일반주식 종목의 `tax_market`과 `instrument_type`을 확인한다. 마이그레이션은 기존 시드의 확인된 코스피 일반주식 30종목만 분류한다. 나머지 종목은 검증된 원천으로 분류해야 하며 이름이나 코드 패턴으로 추측하지 않는다. 미분류·ETF 등은 주문을 거절한다.
4. 백엔드 정책 API·주문 응답·포트폴리오 응답을 확인한 뒤 프론트를 반영한다. 두 정책 JSON이 일치해야 한다.
5. 기존 운영 절차에 따라 `VITE_ENABLE_ORDER_SUBMISSION`을 설정한다. 이번 변경으로 자동 활성화하지 않는다.
6. 테스트 모의계좌에서 수수료 포함 잔고 부족 거절, 매수·일부 매도, 비용 내역 및 실현손익을 확인한다. 실제 증권계좌 주문과 연결하지 않는다.

마이그레이션 downgrade는 신규 필드를 제거하지만 평균단가의 향상된 정밀도는 손실 방지를 위해 유지한다. 요율이 바뀌면 양쪽 정책 파일·버전·시행일·설명·검증 예시를 함께 갱신한다. 미래 세율 변경을 자동 추종하는 시스템은 아니다.
