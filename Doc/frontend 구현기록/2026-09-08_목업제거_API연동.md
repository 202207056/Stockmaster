# 2026-09-08 · 목업 제거 및 API 연동

## 후속 수정 — 기존 디자인 복원

사용자 요청에 따라 API 연결은 유지하고 기존 디자인으로 복원했다. 홈 상단 주요 시세 카드·스크롤, 순위 3열(거래대금 상위/급상승/인기 종목)·각 5개, 뉴스 왼쪽·관심종목/커뮤니티 오른쪽 배치를 되돌렸다. 헤더 검색 폭·인기검색어 자리, 자산 화면 구획, 거래 3단 배치와 관심종목 영역, 커뮤니티 목록 스타일도 복원했다. 지표·인기검색어는 API가 없어 원래 자리에 `준비 중`을 표시하며 가짜 숫자는 사용하지 않는다. 거래대금 열은 기존 amount API 응답을 표시하며 서버 정렬 정확성은 별도 확인 대상이다. 새 기능은 추가하지 않았다.

아래 최초 작업 요약의 “지표·인기검색어 숨김, 거래대금 순위 보류”는 이 후속 수정으로 대체된다.

## 변경 요약

프론트 코드에 실제 API 호출을 연결하고 목업 데이터·배지를 제거했다. 백엔드 코드와 기존 `.env`는 변경하지 않았다. 현재 설정된 API 주소는 `https://gp-mock-inv.onrender.com/api`이다.

| 영역 | 구현한 내용 |
|---|---|
| 홈 | 거래량·상승률 순위, 뉴스 링크, 최근 게시글 조회. 관심종목에 실제 종목명·시세 연결 |

| 주문 | 모의 매수·매도 폼, 전송 직전 시세 재조회, 중복 클릭 방지, 주문내역 조회·갱신. **전송은 기본 비활성화** |

| 커뮤니티 | 목록·페이지 이동·상세·작성·댓글·좋아요 API 연결. 실서버에 테스트 글/댓글을 게시하지 않았음 |
| 설문 | 기존 답변 불러오기, 답변과 규칙 기반 성향 서버 저장. 두 번째 저장 실패는 부분 실패 안내. AI 분석으로 표시하지 않음 |

| 관심종목 | 비회원/사용자별 브라우저 저장 분리. 서버 동기화는 미구현 |

공통 `api/data.js`, `api/normalize.js`, `hooks/useRemote.js`를 추가했다. 조회는 로딩·빈 결과·오류·재시도를 구분하며 화면 이탈/조회 조건 변경 시 취소한다. 자동 시세 폴링은 하지 않는다. 캔들차트는 SVG로 구현해 새 패키지를 추가하지 않았다.

`mockData.js`, `MockBadge`, 목업 지수·인기검색어 컴포넌트를 제거했다. 아직 API가 없는 지수·인기검색어는 숨기고, 거래대금 순위는 백엔드의 volume/amount 분기 정확성 확인까지 보류했다. 정적 용어집과 설문 문항은 유지했다.

## 실제 API 시도 결과

| 요청 | 결과 |
|---|---|
| `GET /` | **200**, 서버 상태 응답 확인 |
| `GET /openapi.json` | **200**, 배포 경로와 주문 요청 스키마 확인 |
| `GET /api/stocks?search=005930` | 비로그인 **403** |
| `GET /api/news/market?limit=1` | 비로그인 **403** |
| `GET /api/community/posts?size=1` | 비로그인 **403** |
| `OPTIONS /api/users/login`, Origin `http://localhost:5173` | 30초 시간 초과. **브라우저 CORS 통과 여부 미확인** |

초기 네트워크 제한 후 허용된 외부 요청으로 위 결과를 확인했다. 비로그인 화면에서는 호출을 반복하지 않고 로그인 안내를 제공한다. 계정이 제공되지 않아 실서버 로그인 후 시세·자산 조회, 설문 저장, 주문 체결 성공은 검증하지 않았다. 임의 계정 생성이나 실서버 데이터 변경은 하지 않았다.

- `npm.cmd run lint` 통과.
- `npm.cmd run build` 통과.
- `npm.cmd test` **14개 통과**: 금액 누락/타입, 시세 누락 시 합계 차단, 동일 가격 매수 전후 총자산 보존, 차트 날짜·OHLC 검증, 외부 링크 제한, API 파라미터·토큰 전달, 오래된 401, 설문 두 API 계약, 계정별 관심종목 분리 등.
- 7개 화면의 비회원 상태와 차트 표는 서버 렌더링 검사 통과. 브라우저 도구는 사용 가능한 브라우저가 없어 **실제 브라우저 조작·모바일 외관·E2E 미검증**.
- 자동 검사는 로컬 응답 어댑터를 사용한다. 실서버 정상 동작의 증거와 구분한다.

## 주문 전송을 제한한 이유

로컬 백엔드는 요청 가격을 그대로 체결가로 사용하며 수량·동시성 검증이 부족하다. 배포 OpenAPI에도 `price`가 필수이고 수량 양수 제약이 없다. 프론트 검증만으로 이를 해결할 수 없으므로 `VITE_ENABLE_ORDER_SUBMISSION`은 기본 `false`다.

검증된 **테스트 환경에서만** `VITE_ENABLE_ORDER_SUBMISSION=true`로 켤 수 있다. 현재 전송 코드는 기존 계약 `{account_id, symbol_code, order_type, price, quantity}`를 사용하므로, 서버가 체결가를 결정하는 새 계약이 나오면 함께 수정해야 한다. 주문 응답 시간 초과·5xx는 실패로 단정하지 않고 내역 확인을 안내하며 해당 화면의 재전송을 막는다. 이 기능은 서버 멱등성을 대체하지 않는다.

## 백엔드 담당에게 남은 요청

1. 테스트 계정/환경과 프론트 origin의 CORS 응답 확인.
2. 서버 체결가·수량 검증·트랜잭션·멱등성 및 새 주문 계약.
3. 자산 요약과 시세 기준시각·유효성 제공. 현재 프론트 평가는 순차 조회 가격과 평균단가를 이용한 참고값이다.
4. 공개 종목/뉴스/커뮤니티 조회 정책 확정. 현재 인증 요구에 맞춰 구현했다.
5. 거래대금 순위 수정, 설문 저장·성향 산출의 단일 API, 학습 추천·진도 API.
