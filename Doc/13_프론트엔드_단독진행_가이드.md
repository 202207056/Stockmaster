# 13. 프론트엔드 단독 진행 가이드

> **백엔드 저장소에 손대지 않고, 프론트엔드만으로 할 수 있는 일 전부.**
> 담당: 이시영 · 작성 2026-08-25

---

## 0. 결론: 저장소 병합을 기다릴 필요가 없습니다

백엔드는 **`https://gp-mock-inv.onrender.com` 에 이미 배포되어 공개 API로 동작 중**입니다.
게다가 CORS가 `allow_origins=["*"]`로 열려 있어 **`localhost:5173`에서 바로 호출됩니다.**

```
백엔드 저장소 접근 ❌  →  상관없음
백엔드 로컬 실행    ❌  →  필요 없음
DB 설치            ❌  →  필요 없음
```

`.env`에 아래 한 줄만 넣으면 오늘부터 실데이터로 개발할 수 있습니다.

```ini
VITE_API_BASE_URL=https://gp-mock-inv.onrender.com/api
```

그리고 `gp-mock-inv/demo.html`(1,090줄)이 **모든 API 호출을 이미 검증해 둔 정답지**입니다.
막히면 백엔드 코드를 읽지 말고 이 파일의 해당 함수를 보세요.

## 3. API 사용 설명서 (프론트 관점)

> 실제 배포본 기준입니다. Swagger: https://gp-mock-inv.onrender.com/docs

### 3-1. 인증

```jsonc
// POST /api/users/register
{ "login_id":"test01", "passwd":"1234", "user_name":"이시영", "email":"a@b.com" }
→ { "user_id":1, "login_id":"test01", "user_name":"이시영",
    "email":"a@b.com", "investment_style":null }
// 회원가입 시 1,000만원 계좌가 자동 생성되지만 응답에는 포함되지 않습니다.

// POST /api/users/login
{ "login_id":"test01", "passwd":"1234" }
→ { "access_token":"eyJ...", "token_type":"bearer" }

// GET /api/users/me   (Bearer 필요)
→ { "user_id":1, "login_id":"test01", "user_name":"이시영",
    "email":"a@b.com", "investment_style":null }
```
> ⚠️ 로그인 응답에 유저 정보가 없으므로 **로그인 직후 `/users/me`를 한 번 더 호출**해야 합니다.
> `demo.html`의 `doLogin()`이 정확히 이렇게 합니다.

### 3-2. 계좌 — 모든 거래 API의 전제

```jsonc
// GET /api/trading/accounts
→ [ { "account_id":1, "account_name":"모의투자 기본계좌",
      "balance":"10000000.00", "withdrawable_cash":"10000000.00" } ]
```
> 🔴 **`balance`와 `withdrawable_cash`가 문자열입니다.** 반드시 `parseFloat()` 하세요.
> `/trading/orders`의 `price`도 문자열입니다. 반면 `/trading/portfolio`는 숫자로 옵니다. (§4-1)

`account_id`는 주문·포트폴리오 조회에 계속 필요하므로 **로그인 직후 받아서 Context에 보관**하세요.

### 3-3. 종목 · 시세

```jsonc
// GET /api/stocks?search=삼성        (🔒 로그인 필요)
→ [ { "symbol_code":"005930", "name":"삼성전자",
      "market_type":"국내주식", "sector_code":"전기전자" } ]
// 현재 등록 종목은 코스피 대표 30개입니다.

// GET /api/stocks/005930/price
→ { "symbol_code":"005930", "current_price":75000, "change_rate":1.5,
    "high":76000, "low":74500, "volume":15000000 }

// KIS 키가 설정되지 않았거나 오류일 때
→ { "symbol_code":"005930", "current_price":0, "change_rate":0.0,
    "message":"KIS API 키가 설정되지 않았습니다..." }
// 🔴 current_price가 0이면 "시세를 불러올 수 없음"으로 처리하세요.

// GET /api/stocks/005930/chart?period=D     (D=일봉, W=주봉, M=월봉)
→ [ { "date":"20240115", "open":74000, "high":76000,
      "low":73500, "close":75000, "volume":15000000 } ]
// 🔴 date가 "YYYYMMDD" 문자열입니다. 차트 라이브러리에 넣기 전 변환 필요.
// 🔴 최근 약 30건만 옵니다. 한 달치 차트만 그려집니다.
```

### 3-4. 주문

```jsonc
// POST /api/trading/orders
{ "account_id":1, "symbol_code":"005930",
  "order_type":"매수",        // "매수" | "매도"  ← 한글입니다
  "price":75000, "quantity":10 }

→ { "order_id":1, "account_id":1, "symbol_code":"005930", "order_type":"매수",
    "price":"75000.00", "quantity":10, "status":"체결",
    "message":"005930 10주 매수가 완료되었습니다.",
    "created_at":"2026-08-25T10:30:00" }

// GET /api/trading/orders?account_id=1     → [OrderResponse] (message는 null)
// PUT /api/trading/orders/1/cancel         → { "message":"..." }
```

**에러 응답 (FastAPI 기본형)**
```jsonc
{ "detail": "매수 가능 현금이 부족합니다." }
```
자주 보게 될 문구: `매수 가능 현금이 부족합니다.` · `보유 수량이 부족합니다.` ·
`종목을 찾을 수 없습니다.` · `계좌를 찾을 수 없습니다.` · `유효하지 않거나 만료된 토큰입니다.`

### 3-5. 포트폴리오

```jsonc
// GET /api/trading/portfolio?account_id=1
→ { "account_id":1,
    "balance":10000000.0,             // ← 숫자 (계좌 API와 타입이 다름)
    "withdrawable_cash":9250000.0,
    "holdings":[
      { "portfolio_id":1, "symbol_code":"005930", "security_name":"삼성전자",
        "avg_price":74000.0, "hold_quantity":10,
        "total_value":740000.0 }       // ← 평가금액이 아니라 "매입금액"입니다
    ] }
```
> 🔴 `total_value = 평균단가 × 수량` 이므로 **평가금액이 아닙니다.**
> 평가금액·손익은 프론트가 현재가를 조회해 직접 계산해야 합니다. (§5-1)

### 3-6. 뉴스 · 랭킹 · 커뮤니티

```jsonc

// GET /api/news/005930?limit=10   → [ { "title", "url", "date", "source":"연합뉴스" } ]
// 🔴 크롤링 실패 시 빈 배열 []이 옵니다. 에러가 아니라 빈 상태로 처리하세요.

// GET /api/community/posts?page=1&size=20&symbol_code=005930
→ { "total":150, "page":1,
    "items":[ { "post_id":1, "title":"...", "author_name":"홍길동",
                "symbol_code":"005930", "created_at":"...",
                "like_count":5, "comment_count":3 } ] }

// GET /api/community/posts/1
→ { "post_id":1, "title", "content", "author_name", "symbol_code", "created_at",
    "like_count":5,
    "comments":[ { "comment_id":1, "author_name":"...", "content":"...", "created_at":"..." } ] }

// POST /api/community/posts/1/comments { content }                     → { message }
```

## 4. 반드시 알아야 할 함정 5가지

### 4-1. 🔴 숫자가 문자열로 옵니다 (일부만)

| API | 필드 | 타입 |
|---|---|---|
| `/trading/accounts` | `balance`, `withdrawable_cash` | **문자열** `"10000000.00"` |
| `/trading/orders` | `price` | **문자열** `"75000.00"` |
| `/trading/portfolio` | `balance`, `avg_price`, `total_value` | 숫자 |
| `/stocks/{c}/price` | `current_price` | 숫자 |

일관되지 않으므로 **모든 금액을 `Number()`로 감싸는 유틸을 통과**시키세요.

```js
// src/utils/format.js
export const num = (v) => Number(v ?? 0);
export const won = (v) => num(v).toLocaleString('ko-KR') + '원';
export const rate = (v) => `${num(v) >= 0 ? '+' : ''}${num(v).toFixed(2)}%`;
export const sign = (v) => (num(v) > 0 ? 'up' : num(v) < 0 ? 'down' : 'flat');
```

### 4-2. 🔴 Render 콜드스타트 — 첫 요청이 15초 이상 걸립니다

무료 티어라 유휴 시 서버가 잠듭니다. **실측 결과 첫 요청이 15초 타임아웃 후 기동**했습니다.
아무 처리도 없으면 사용자에게는 "먹통"으로 보입니다.

```js
// src/api/client.js — 3초 이상 걸리면 안내 문구 노출
let wakeTimer;
api.interceptors.request.use((config) => {
  wakeTimer = setTimeout(() => {
    window.dispatchEvent(new CustomEvent('api:slow'));   // "서버를 깨우는 중이에요..."
  }, 3000);
  return config;
});
api.interceptors.response.use(
  (res) => { clearTimeout(wakeTimer); window.dispatchEvent(new CustomEvent('api:ok')); return res; },
  (err) => { clearTimeout(wakeTimer); return Promise.reject(err); }
);
```
그리고 앱 진입 시 워밍업 요청을 한 번 날려두면 체감이 크게 좋아집니다.
```js
// main.jsx 최상단
fetch(import.meta.env.VITE_API_BASE_URL.replace('/api','') + '/').catch(() => {});
```
> **이 처리는 프론트만으로 가능하고 시연 품질에 직결됩니다.** 우선순위를 높게 두세요.

### 4-3. 🔴 토큰이 60분이면 만료되고, 갱신 수단이 없습니다

리프레시 토큰이 없으므로 **만료되면 재로그인**밖에 없습니다.
401을 잡아 자동 로그아웃 처리를 넣지 않으면 화면이 조용히 깨집니다.

### 4-4. 🔴 종목 조회에도 로그인이 필요합니다

`GET /api/stocks` 계열 전부에 인증이 걸려 있습니다.
따라서 `Landing.jsx`의 **"먼저 둘러보기"** 로 비로그인 사용자를 대시보드에 보내면
빈 화면만 보게 됩니다.

**대응 (프론트에서 선택)**
1. "먼저 둘러보기" → `/signup`으로 유도 (가장 간단)
2. 비로그인 시 대시보드를 **정적 소개 화면**으로 표시
3. 팀원에게 인증 해제를 요청 (§7)

### 4-5. 🟡 종목이 30개뿐입니다

`item_master`에 코스피 대표 30종목만 시드되어 있습니다.
검색 UI를 만들 때 "결과 없음" 상태가 자주 나오므로, **EmptyState 문구**를
"등록된 종목이 아니에요. 다른 종목으로 검색해 보세요." 정도로 준비해 두세요.

## 5. 백엔드 결함을 프론트에서 보완하기

백엔드에 알려진 결함이 있지만, **일부는 프론트에서 먼저 방어할 수 있습니다.**

### 5-1. ✅ 총자산·평가손익을 프론트가 직접 계산

`/trading/portfolio`의 `balance`는 계산이 잘못되어 있고 `total_value`는 매입금액입니다.
**프론트가 현재가를 조회해 직접 계산하면 지금 당장 정확한 숫자를 보여줄 수 있습니다.**
(`demo.html`의 `loadHoldings()`가 이미 이렇게 합니다.)

```js
// src/api/portfolio.js
export async function getPortfolioWithPrices(accountId) {
  const { data } = await api.get('/trading/portfolio', { params: { account_id: accountId } });

  // 보유 종목 현재가 병렬 조회
  const prices = {};
  await Promise.all(data.holdings.map(async (h) => {
    try {
      const { data: p } = await api.get(`/stocks/${h.symbol_code}/price`);
      prices[h.symbol_code] = num(p.current_price) || num(h.avg_price); // 실패 시 평단으로 대체
    } catch { prices[h.symbol_code] = num(h.avg_price); }
  }));

  const holdings = data.holdings.map((h) => {
    const cur = prices[h.symbol_code];
    const buyAmount  = num(h.avg_price) * h.hold_quantity;
    const evalAmount = cur * h.hold_quantity;
    return {
      ...h,
      current_price: cur,
      buy_amount: buyAmount,
      eval_amount: evalAmount,
      eval_pnl: evalAmount - buyAmount,
      eval_pnl_rate: buyAmount ? ((evalAmount - buyAmount) / buyAmount) * 100 : 0,
    };
  });

  const cash       = num(data.withdrawable_cash);
  const stockValue = holdings.reduce((s, h) => s + h.eval_amount, 0);
  const seed       = 10_000_000;                    // 초기자금 (백엔드 기본값)

  return {
    cash,
    stockValue,
    totalAsset: cash + stockValue,
    totalPnl: cash + stockValue - seed,
    totalPnlRate: ((cash + stockValue - seed) / seed) * 100,
    holdings,
  };
}
```
> 이렇게 하면 **백엔드 수정 전에도 Assets 화면이 정확한 숫자를 보여줍니다.**
> 나중에 백엔드에 `/portfolio/summary`가 생기면 이 함수 내부만 교체하면 됩니다.
>
> ⚠️ 다만 **실현손익(총 수익)** 은 체결 테이블이 없어 프론트에서도 계산 불가입니다.
> 화면에서 "총 수익" 항목은 빼고 **평가손익만** 표시하세요.

### 5-2. ✅ 관심종목을 localStorage로 임시 구현

`favorites` API가 없지만, 기능 자체는 프론트만으로 만들 수 있습니다.

```js
// src/utils/favorites.js
const KEY = 'gp_favorites';
export const getFavorites = () => JSON.parse(localStorage.getItem(KEY) || '[]');
export const isFavorite = (code) => getFavorites().includes(code);
export const toggleFavorite = (code) => {
  const list = getFavorites();
  const next = list.includes(code) ? list.filter((c) => c !== code) : [...list, code];
  localStorage.setItem(KEY, JSON.stringify(next));
  return next;
};
```
`Favorites.jsx`는 이 목록으로 종목 정보와 현재가를 조회해 렌더링합니다.
API가 생기면 이 파일만 교체하면 되므로 **버려지는 작업이 아닙니다.**
> 단, 기기 간 동기화가 안 되므로 발표에서는 "임시 구현"임을 언급하거나, 그전에 API를 받으세요.

### 5-3. 🟡 주문 가격 입력 방어

백엔드가 클라이언트가 보낸 가격을 그대로 신뢰하는 결함이 있습니다.
**프론트가 이를 고칠 수는 없지만, 정상 사용자가 이상한 값을 넣지 않도록 막을 수는 있습니다.**

```jsx
// 시장가 주문: 가격 입력을 아예 막고 현재가를 그대로 전송
<input value={won(currentPrice)} readOnly className="bg-gray-100" />

// 지정가: 현재가 ±30% 범위로 제한
<input type="number" value={price} onChange={...}
       min={Math.floor(currentPrice * 0.7)}
       max={Math.ceil(currentPrice * 1.3)} step={tickSize(currentPrice)} />
```
```js
// src/utils/tickSize.js — 호가 단위 스텝 버튼용
export function tickSize(p) {
  if (p < 2000) return 1;      if (p < 5000) return 5;
  if (p < 20000) return 10;    if (p < 50000) return 50;
  if (p < 200000) return 100;  if (p < 500000) return 500;
  return 1000;
}
```
> 호가 단위 값은 시장·시점에 따라 다를 수 있습니다. 공식 자료로 확인 후 갱신하세요.

### 5-4. 🟡 성향 분석 결과를 프론트에서 산출

`GET /api/ai/propensity`가 항상 null이므로 Survey 결과 화면을 만들 수 없습니다.
**규칙 기반 점수는 프론트에서 계산할 수 있습니다.**

```js
// src/constants/survey.js — 문항·선택지·점수를 프론트에 정의
export const SURVEY = [
  { number: 1, question: '투자 경험이 있나요?',
    options: [ {label:'전혀 없습니다', score:0}, {label:'1년 미만', score:5},
               {label:'1~3년', score:10}, {label:'3년 이상', score:15} ] },
  // ... 6문항
];

export function calcStyle(totalScore) {
  if (totalScore <= 20) return { code:'STABLE',         label:'안정형' };
  if (totalScore <= 40) return { code:'STABLE_SEEKING', label:'안정추구형' };
  if (totalScore <= 60) return { code:'NEUTRAL',        label:'위험중립형' };
  if (totalScore <= 80) return { code:'RISK_SEEKING',   label:'적극투자형' };
  return { code:'AGGRESSIVE', label:'공격투자형' };
}
```
제출 흐름:
```js
await api.post('/ai/survey', { answers });                    // 원본 답변 저장
const style = calcStyle(totalScore);
await api.put('/users/survey', { investment_style: style.label });  // 결과 저장
// → /users/me 의 investment_style로 대시보드 개인화 가능
```
> AI 담당자가 나중에 서버에서 같은 계산을 하게 되면 그때 제거하면 됩니다.
> **지금은 이 방법이 Survey 화면을 완성하는 유일한 길입니다.** AI 담당자와 문항·점수를 먼저 합의하세요.

```jsx
// src/components/learn/HelpIcon.jsx
import { useState } from 'react';
import { GLOSSARY } from '../../constants/glossary';

export default function HelpIcon({ termId }) {
  const [open, setOpen] = useState(false);
  const t = GLOSSARY[termId];
  if (!t) return null;
  return (
    <span className="relative inline-block">
      <button type="button" onClick={() => setOpen((v) => !v)}
              aria-label={`${t.term} 설명 보기`}
              className="ml-1 align-super text-xs text-gray-400 hover:text-blue-500">ⓘ</button>
      {open && (
        <>
          <div className="fixed inset-0 z-40" onClick={() => setOpen(false)} />
          <div className="absolute z-50 left-0 top-6 w-72 rounded-lg border border-gray-200
                          bg-white p-4 shadow-lg text-left">
            <h4 className="font-bold text-gray-900 text-sm">{t.term}</h4>
            <p className="mt-1 text-sm text-gray-600 leading-relaxed">{t.desc}</p>
            {t.example && <p className="mt-2 text-xs text-gray-400">예: {t.example}</p>}
          </div>
        </>
      )}
    </span>
  );
}
```
