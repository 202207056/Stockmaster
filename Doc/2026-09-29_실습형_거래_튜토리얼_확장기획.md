## 1. 개선 방향: 거래 이후의 돈을 설명할 수 있게 만들기

현재 튜토리얼은 종목 검색, 관심종목, 차트 변경, 계좌 선택, 주문 확인, 매수·매도 결과 확인까지 자연스럽게 이어진다. 이 조작 흐름을 유지하면서 **“무엇을 누를까?” 다음에 “얼마가 왜 바뀔까?”를 학습**하도록 발전시킨다.

현재 코드에서 확인한 기준은 다음과 같다.

| 현재 구현 | 장점 | 확장할 학습 |
|---|---|---|
| 예시전자 50,000원, 시작 현금 1,000,000원, 2주 매수 후 1주 매도 | 숫자가 단순하고 흐름을 이해하기 쉬움 | 매수·매도 비용, 비용 반영 전후 손익 |
| 주문 시 고정 가격으로 즉시 체결 | 첫 주문을 끝까지 경험할 수 있음 | 접수·부분 체결·취소·결제 구분 |
| 현금 1,000,000 → 900,000 → 950,000원 | 잔액 변화가 명확함 | 결제 전후 예수금, 주문가능금액, 출금가능금액 구분 |

## 2. 추천 학습 구성

전체 내용을 한 번에 강제로 진행시키지 않고 5~12분 단위로 나눈다. 시간은 기획상 목표이며 사용자 테스트로 조정한다.

| 과정 | 상황형 제목 | 핵심 실습 | 목표 시간 | 선행 학습 |
|---|---|---|---|---|
| A | 10만 원어치를 사면 정확히 10만 원만 필요할까? | 비용 포함 매수, 잔액 예측 | 7분 | 기존 조작 안내 |
| B | 같은 가격에 팔았는데 왜 손실일까? | 부분 매도, 실현·평가손익 분리 | 7분 | A |
| C | 팔았는데 왜 전부 출금할 수 없을까? | 결제일 이동, 출금·재주문 비교 | 8분 | A·B |
| D | 주문했는데 주식은 왜 없을까? | 미체결·부분 체결·취소 | 6분 | A |
| E | 수익이 났는데 이번 주 쓸 돈이 부족하다면? | 계좌 분리, 현금 계획, 거래 복기 | 10분 | C·D |
| F | 내 돈보다 많이 샀다면 언제 채워야 할까? | 미수 예상액, 납부, 반대매매 분기 | 12분 | C·E |
| G | 적은 증거금으로 큰 계약을 하면 어떻게 될까? | 선물 손익, 일일정산, 추가증거금 | 12분 | B·E |
| H | 비슷해 보이는 거래는 무엇이 다를까? | 신용융자·공매도·레버리지 ETF 비교 실습 | 각 5~8분 | F·G 권장 |

기본 과정은 A~E, 심화 과정은 F~H로 표시한다. 심화 과정 진입 전에는 “결제 전 매도대금과 출금가능금액 구분”, “비용 반영 손익 계산”의 짧은 확인 문제를 제공한다. 틀렸다면 해당 기본 실습으로 바로 이동한다. 이 구분은 학습 순서이며 실제 금융상품 거래 자격을 부여하지 않는다.

## 3. 모든 과정에 적용할 학습 방식

### 3.1 한 장면의 순서

1. **상황**: “내일 20만 원을 써야 합니다”처럼 행동의 이유를 제시한다.
2. **예측**: 결과를 보여 주기 전에 잔액·비용·부족금을 입력하거나 선택한다.
3. **행동**: 주문, 취소, 날짜 이동, 입금, 출금 등의 조작을 수행한다.
4. **대조**: 예상한 값과 실제 실습 결과를 나란히 보여 준다.
5. **설명**: 바뀐 금액을 거래대금·비용·가격 변화·입출금으로 분해한다.
6. **전이**: 가격이나 수량을 바꾼 문제를 안내 없이 다시 풀게 한다.

첫 시도에는 클릭 위치를 안내하되, 복습에서는 위치 안내를 숨긴다. 수량을 틀리게 입력하면 곧바로 막기보다 예상 비용을 보여 주고 수정할 기회를 준다. 단, 주문가능금액 부족 등 주문 자체가 성립하지 않는 상황은 이유와 부족액을 표시한다.

### 3.2 화면 구성 예시

| 위치 | 보여 줄 내용 |
|---|---|
| 상단 | 상황, 학습 목표 하나, 현재 단계, 가상 거래 표시 |
| 중앙 | 기존 차트·주문·보유 내역 화면 |
| 계좌 영역 | 변화 전 → 변화 후, 차이, 변화 원인 |
| 하단 | “먼저 예상하기”, 계산 펼치기, 결과 비교, 다시 해보기 |
| 완료 화면 | 내가 한 거래, 놓친 비용, 결제 일정, 재학습할 개념 |

안내는 “어디를 누르는지”와 “왜 하는지”를 각각 한 문장으로 작성한다. 모든 용어를 처음부터 펼치지 않고 해당 숫자를 누르면 설명이 나오게 한다. 금액 변화는 색상뿐 아니라 `−100원 · 매수 수수료`처럼 부호와 원인을 함께 표시한다.

### 3.3 계산 예시의 공통 약속

아래 요율과 증거금 수치는 계산을 쉽게 하기 위한 **가상 학습 설정**이다. 실제 증권사의 요율이나 현재 법정 세율을 재현하지 않는다.

| 항목 | 문서의 가상 설정 |
|---|---|
| 일반 주식 매수 수수료 | 체결대금의 0.1% |
| 일반 주식 매도 수수료 | 체결대금의 0.1% |
| 일반 주식 매도 시 세금 | 체결대금의 0.2%인 가상 세금 |
| 계산 단위 | 비용 항목별 원 미만 버림. 본문의 주식 예시는 모두 정수로 계산됨 |
| 기본 현금 계좌 | 거래대금과 비용을 전액 확보, 미수 사용 안 함 |
| 국내주식 결제 시계 | T+2 영업일. T는 각 거래의 체결일이며 휴장일은 건너뜀 |
| 종목 | 예시전자 등 가상 종목만 사용 |
| 거래일 | 별도 공휴일이 없는 가상 달력 사용 |

매수 단계에서 거래세까지 일괄 부과하거나, 모든 금융상품에 같은 세금을 적용하면 안 된다. 실제 요율을 제공하는 버전은 시장·상품·계좌·적용일에 따라 별도로 검증해야 한다. 국내주식 T+2 결제와 비용 항목의 근거는 [토스증권 국내주식 거래설명서](https://home-files.tossinvest.com/files/notice/f8b692a8-2b29-46c4-b279-f6bf865e64d5.pdf)에서 확인했다.

**표시 기준을 나누는 원칙:** A·B는 비용 이해에 집중하도록 `거래 반영 예상 현금`을 사용한다. 이는 미결제 거래까지 반영한 학습용 금액이며 지금 출금할 수 있다는 뜻이 아니다. C에서 실제 결제 전후 시간축을 펼친다. 화면에서 이 금액을 단순히 `예수금`이라고 부르지 않는다.

## 4. 과정 A — 수수료까지 포함해서 매수하기

### 상황과 목표

“매매 연습 계좌에 1,000,000원이 있습니다. 예시전자를 50,000원에 2주 사려 합니다. 주문 전후의 돈을 예상해 보세요.”

목표: 거래대금과 총 필요금액을 구분하고, 현금 감소 전체를 손실로 오해하지 않는다.

### 장면별 실습

| 단계 | 사용자 행동 | 화면과 피드백 | 통과 기준 |
|---|---|---|---|
| 1. 계좌 확인 | 매매 연습 계좌 선택, 잔액 확인 | 계좌명·번호·가상 현금 1,000,000원 | 올바른 계좌 선택 |
| 2. 비용 예측 | 2주 입력 후 필요금액 선택 | 선택지 100,000 / 100,100 / 100,300원 | 비용 포함 금액 도출 |
| 3. 계산 확인 | 수수료 항목 펼치기 | 거래대금 100,000 + 수수료 100 = 100,100원 | 수수료가 붙는 기준액 선택 |
| 4. 주문 | 확인 창의 계좌·가격·수량 검토 후 제출 | 예상 비용과 체결 비용 비교 | 2주 체결 |
| 5. 잔액 대조 | 예상 현금 입력 | 1,000,000 − 100,000 − 100 = 899,900원 | 899,900원 입력 |
| 6. 자산 설명 | 감소 원인을 분류 | 주식 평가액 100,000원, 순자산 999,900원 | 실제 비용 100원과 자산 형태 변경 구분 |

안내 문구: “주식값으로 100,000원, 수수료로 100원이 필요해요. 현금이 줄어든 금액 대부분은 주식으로 바뀌었고, 수수료 100원이 비용으로 나갔어요.”

오답 예시: 900,000원이라고 답하면 “주식값 계산은 맞았어요. 주문서의 수수료 100원도 반영해 보세요”라고 안내한다. 정답만 보여 주지 않고 비용 항목을 다시 열어 준다.

### 실패를 활용한 추가 실습

계좌를 100,000원으로 초기화하고 동일한 2주 주문을 시도한다. 부족액은 100원이다. `1주로 수정`, `가상 현금 100원 입금`, `주문 취소` 중 하나를 선택하게 한다. 주문 금액만 맞춰도 비용 때문에 주문이 불가능할 수 있음을 경험한다.

재도전: 30,000원짜리 3주를 매수한다. 거래대금 90,000원, 수수료 90원, 총 필요금액 90,090원이다. 초기 현금 1,000,000원이라면 예상 현금은 909,910원이다.

## 5. 과정 B — 같은 가격에 팔아도 손실이 생긴다

### 상황과 목표

A의 상태를 이어받는다. 예상 현금 899,900원, 50,000원에 산 주식 2주가 있다. 이 중 1주를 같은 가격에 판다.

목표: 매도대금과 순수령액을 구분하고, 실현손익과 남은 주식의 평가손익을 분리한다.

### 장면별 실습

1. “같은 가격에 팔면 손익은 얼마일까요?”에 먼저 답한다.
2. 매도 수량 1주를 입력하고 수수료·세금 항목을 펼친다.
3. 매도대금 50,000원에서 수수료 50원과 가상 세금 100원을 뺀다.
4. 순수령 예정액 49,850원을 확인하고 매도한다.
5. 예상 현금 949,750원, 남은 주식 1주, 주식 평가액 50,000원을 확인한다.
6. 사라진 250원을 거래 내역에서 찾아 매수 비용 100원과 매도 비용 150원으로 분류한다.

| 시점 | 거래 반영 예상 현금 | 주식 평가액 | 학습용 순자산 | 최초 대비 |
|---|---:|---:|---:|---:|
| 시작 | 1,000,000원 | 0원 | 1,000,000원 | 0원 |
| 2주 매수 | 899,900원 | 100,000원 | 999,900원 | −100원 |
| 같은 가격에 1주 매도 | 949,750원 | 50,000원 | 999,750원 | −250원 |

### 손익을 두 관점으로 보여 주기

주식 가격만 비교한 매도 차익은 0원이다. 이 문서는 매수 수수료 100원을 2주에 50원씩 배분하므로, 매도한 1주의 비용 반영 실현손익은 `49,850 − 50,050 = −200원`이다. 남은 1주의 비용 반영 평가손익은 `50,000 − 50,050 = −50원`이다. 둘의 합은 −250원이다.

이때 남은 주식의 미래 매도 비용은 아직 차감하지 않는다. `지금 전량 팔면 예상 손익`은 별도 항목으로 둔다. 실제 서비스마다 매입단가·평가손익의 비용 포함 방식이 다를 수 있으므로 화면에 계산 기준을 붙인다.

안내 문구: “매도한 1주의 손실은 200원이에요. 남은 1주에도 매수 수수료 50원이 배분되어 있어요. 계좌 전체의 비용은 지금까지 250원입니다.”

### 가격 상승 분기

같은 매수 직후 상태로 되돌리고 이번에는 1주를 55,000원에 매도한다.

| 항목 | 결과 |
|---|---:|
| 매도대금 | 55,000원 |
| 수수료 / 가상 세금 | 55원 / 110원 |
| 순수령 예정액 | 54,835원 |
| 매도한 1주 비용 포함 원가 | 50,050원 |
| 비용 반영 실현손익 | +4,785원 |
| 남은 1주 평가액 / 비용 반영 평가손익 | 55,000원 / +4,950원 |
| 예상 현금 / 순자산 | 954,735원 / 1,009,735원 |

최종 질문: “현금이 54,835원 늘었으니 이익도 54,835원일까요?” 원금 회수와 이익을 분리해서 답해야 완료한다.

## 6. 과정 C — 결제와 출금 시점을 직접 이동해 보기

### 상황과 목표

새 실습 계좌를 제공한다. 결제 완료 현금 100,000원, 과거에 매수하여 결제가 끝난 주식 10주가 있다. 월요일에 10주를 50,000원씩 매도하고 화요일에 300,000원을 출금하려 한다.

목표: 체결·결제·출금을 구분하고, 같은 매도대금도 재매수 가능 여부와 출금 가능 여부가 다를 수 있음을 이해한다.

매도대금은 500,000원, 수수료 500원, 가상 세금 1,000원, 순수령 예정액은 498,500원이다. 이 실습은 별도 의무나 제한이 없는 계좌에서 결제 완료 주식의 순매도대금을 재주문에 사용할 수 있다고 가정한다. 증권사의 재사용가능금액·출금가능금액은 서로 다른 항목이라는 점은 [KB증권 예수금상세 안내](https://help2.kbsec.com/0362.html)를 참고했다.

| 시점 | 결제 완료 현금 | 미결제 순매도대금 | 주문가능금액* | 출금가능금액* |
|---|---:|---:|---:|---:|
| 월요일 매도 전 | 100,000원 | 0원 | 100,000원 | 100,000원 |
| 월요일 체결 후 | 100,000원 | 498,500원 | 598,500원 | 100,000원 |
| 화요일 T+1 | 100,000원 | 498,500원 | 598,500원 | 100,000원 |
| 수요일 T+2 결제 후 | 598,500원 | 0원 | 598,500원 | 598,500원 |
| 수요일 300,000원 출금 후 | 298,500원 | 0원 | 298,500원 | 298,500원 |

*다른 주문·채무·출금 제한이 없는 이 실습의 가정이다. 주문가능금액은 비용도 충당해야 하는 예산이며, 그 전부를 주식 거래대금으로 주문할 수 있다는 의미는 아니다.

### 장면별 실습

1. 매도 직후 300,000원 출금을 시도한다. 현재 출금 가능 100,000원, 부족 200,000원을 표시한다.
2. “돈은 어디에 있나요?”를 누르면 미결제 순매도대금 카드와 수요일 결제 예정 표시를 연결한다.
3. 화요일로 시간을 이동해 출금 가능 금액이 그대로인지 확인한다.
4. 수요일로 이동하여 매도대금이 결제된 뒤 300,000원을 출금한다.
5. 거래 복기에서 출금은 투자 손실이 아니라 계좌 밖으로 돈을 옮기는 일임을 확인한다.

안내 문구: “매도는 체결됐지만 대금 결제는 아직이에요. 매도대금으로 다시 주문할 수 있는 경우에도 지금 출금할 수 있는 돈과는 달라요.”

대안 분기: 월요일에 재매수하면 새 매수의 결제 예정액도 시간표에 추가한다. 출금 예정 자금이 줄어드는 이유를 확인한다. 기준 정답은 위 표의 ‘재매수하지 않은 경로’와 별도로 관리한다.

재도전: 공휴일이 없는 금요일 매도의 결제일을 선택한다. 정답은 다음 화요일이다. 월요일 휴장 카드를 추가하면 수요일로 바뀐다. 모든 시장이 T+2라고 일반화하지 않는다.

## 7. 과정 D — 미체결·부분 체결·취소로 묶인 돈 이해하기

### 상황과 목표

현금 1,000,000원으로 50,000원 지정가 4주 매수 주문을 낸다. 주문 접수 때 거래대금과 예상 비용을 모두 확보하는 가상 정책을 적용한다.

| 상태 | 누적 체결 수량 | 미체결 수량 | 체결분 결제 예정액 | 미체결 주문 확보액 | 추가 주문 가능 예산 |
|---|---:|---:|---:|---:|---:|
| 접수 전 | 0주 | 0주 | 0원 | 0원 | 1,000,000원 |
| 4주 접수 | 0주 | 4주 | 0원 | 200,200원 | 799,800원 |
| 2주 체결 | 2주 | 2주 | 100,100원 | 100,100원 | 799,800원 |
| 잔여 2주 취소 완료 | 2주 | 0주 | 100,100원 | 0원 | 899,900원 |

사용자는 주문내역에서 보유 수량과 미체결 수량을 따로 확인하고, 남은 2주만 취소한다. “취소했으니 주식 2주도 사라질까요?”에 답한다. 취소 요청 중에는 추가 체결이 발생할 수 있으므로 `취소 요청`과 `취소 완료`를 나누고 최종 체결 수량을 다시 확인하게 한다.

피드백: “취소한 것은 아직 체결되지 않은 2주예요. 이미 산 2주와 결제 예정액 100,100원은 남아 있어요.”

시장가 비교 실습에서는 같은 4주가 50,000원 2주, 50,100원 2주에 체결되도록 한다. 거래대금은 200,200원, 평균 체결가는 50,050원이다. 화면에 보였던 가격이 전체 수량의 체결가를 보장하지 않는다는 점을 학습한다. 지정가는 가격 조건을 제시하지만 체결을 보장하지 않는다는 비교 문제로 마무리한다.

## 8. 과정 E — 계좌를 목적에 맞게 관리하기

### 상황과 목표

“가상 자금 1,000,000원 중 300,000원은 며칠 뒤 써야 합니다. 나머지로 매매를 연습하려 합니다.” 사용자가 돈의 용도, 거래 계좌, 비용, 출금 일정을 함께 확인하게 한다.

특정 현금 비중을 모든 사람에게 권하는 내용으로 만들지 않는다. 다음 금액과 비중은 해당 상황에서 사용자가 정한 연습 규칙이다.

### E-1. 계좌 분리와 주문 전 점검

1. 가상 보관 계좌에 300,000원, 매매 연습 계좌에 700,000원을 배분한다.
2. “곧 사용할 300,000원은 매매하지 않는다”는 규칙을 선택한다.
3. 보관 계좌가 선택된 주문서를 제시한다. 사용자가 계좌를 바꿔야 진행한다.
4. 연습 계좌에서 50,000원짜리 4주를 산다. 비용 포함 200,200원, 남은 예상 현금 499,800원이다.
5. 연습 계좌 순자산 699,800원, 보관 계좌 300,000원, 합산 순자산 999,800원을 비교한다.
6. 각 계좌 거래내역과 합산 자산을 대조해 계좌 간 이동 자체가 수익을 만들지 않는다는 점을 확인한다.

질문: “연습 계좌 잔액이 줄었는데 보관 계좌에서 자동으로 채워질까요?” 이 예시는 자동 이체가 없으므로 정답은 ‘아니요’다. 화면에 실제 기능처럼 보이는 자동 보전 동작을 넣지 않는다.

### E-2. 입금과 투자 수익 구분

독립된 문제에서 시작 순자산 1,000,000원, 외부 입금 200,000원, 기간 말 순자산 1,210,000원을 제시한다. 단순 기간 손익은 `1,210,000 − 1,000,000 − 200,000 = +10,000원`이다. 사용자가 210,000원을 수익으로 답하면 입금 항목을 다시 분류한다.

외부 출금이 있으면 `기말 순자산 − 기초 순자산 − 외부 입금 + 외부 출금`으로 손익을 확인한다. 이는 입출금 시점을 고려한 수익률 공식은 아니다. 계좌 간 내부 이체는 합산 기준 외부 입출금에서 제외한다.

### E-3. 집중도와 대응 계획

주식 A 600,000원, 주식 B 200,000원, 현금 200,000원인 별도 계좌를 보여 준다. A가 20% 하락하는 버튼을 누르면 A는 480,000원, 순자산은 880,000원이 된다. 사용자가 손실액 120,000원과 계좌 전체 변화율 −12%를 계산한다.

이후 `그대로 관찰`, `일부 매도 검토`, `추가 매수 검토` 중 하나와 이유를 기록한다. 매매 방향 자체를 정답 처리하지 않고, 추가 비용·가용 현금·원래 목적·위험 변화를 확인했는지를 평가한다.

### E-4. 마감 점검

계좌에 미체결 주문 한 건, 다음 영업일 결제 예정 한 건, 기록하지 않은 비용 한 건을 숨겨 둔다. 사용자가 주문내역·결제 예정·거래내역에서 각각 찾아 짧은 복기 노트를 완성한다.

완료 노트 예시: “4주를 매수해 비용 200원이 발생했다. 남은 예상 현금은 499,800원이다. 보관 계좌 300,000원은 사용하지 않았다. 결제 일정과 남은 주문을 확인했다.”

## 9. 과정 F — 미수거래: 주문 가능과 결제 가능은 다르다

### 먼저 구분할 개념

이 과정의 미수거래는 매수대금 일부를 증거금으로 확보해 주문한 뒤 결제일까지 나머지 대금을 준비해야 하는 상황을 다룬다. 결제 전의 `예상 부족액`과 결제일까지 납부하지 못해 발생한 `미수금`을 다른 이름으로 표시한다. 약정된 대출을 이용하는 신용융자와도 구분한다.

실제 미수금은 결제대금 부족으로 발생하며 미해소 시 반대매매 등이 발생할 수 있다. 구체적인 시한·선정 수량·제한은 증권사 약관에 따라 달라진다. 근거: [KB증권 예수금상세](https://help2.kbsec.com/0362.html), [토스증권 국내주식 거래설명서](https://home-files.tossinvest.com/files/notice/f8b692a8-2b29-46c4-b279-f6bf865e64d5.pdf).

### 가상 설정

| 항목 | 값 |
|---|---:|
| 시작 현금 | 400,000원 |
| 주문 | 주당 10,000원 × 100주 = 1,000,000원 |
| 가상 주문 증거금률 | 30% |
| 매수 수수료 | 1,000원 |
| 주문 시 확보액 | 증거금 300,000원 + 비용 1,000원 = 301,000원 |
| 결제 총 필요금액 | 1,001,000원 |
| 결제일까지 추가로 필요한 현금 | 601,000원 |

이 과정에서는 추가 주문을 허용하지 않는다. 확보 후 남은 현금 99,000원이 보여도 결제 전체를 감당할 수 있다는 의미가 아님을 강조한다.

### 장면별 실습

1. **예측**: “주문이 접수되면 지금 가진 돈으로 결제도 끝낼 수 있을까요?”
2. **비교**: 현금 100% 정책에서는 주문이 거절되고, 가상 30% 증거금 정책에서는 접수될 수 있음을 비교한다.
3. **주문**: 100주를 매수하고 `총 결제금액 1,001,000원 / 준비된 현금 400,000원 / 예상 부족액 601,000원`을 확인한다.
4. **달력**: T+2 결제 시점과 가상 입금 마감 표시를 연다. “주문 다음 날이면 끝”이라는 오해를 확인한다.
5. **선택**: 부족액 전부 입금, 일부 입금, 아무 조치 없이 진행을 선택한다.
6. **대조**: 각 경로를 되돌려 실행하고 입금 내역·미수금·반대매매 결과를 비교한다.

### 분기 A — 기한 내 전액 입금

601,000원을 가상 입금하면 결제 후 현금 0원, 주식 평가액 1,000,000원, 미수금 0원이 된다. 누적 외부 투입액은 1,001,000원이므로 가격이 같아도 비용 1,000원만큼 손실이다. 입금 601,000원을 수익으로 표시하지 않는다.

### 분기 B — 일부만 입금

500,000원을 입금하면 결제 시 101,000원이 부족하다. “입금 완료” 표시만 보고 끝내지 않고 `남은 부족액 101,000원`을 확인한 뒤 추가 입금 여부를 선택한다.

### 분기 C — 미해소 후 반대매매

전혀 입금하지 않아 미수금 601,000원이 발생한 상태에서 다음 영업일로 이동한다. **이 가상 경로는 100주 전량을 8,000원에 매도하도록 정한 예시**다. 실제 반대매매 수량이나 체결가격 산식으로 안내하지 않는다.

| 항목 | 계산 |
|---|---:|
| 반대매매 대금 | 8,000원 × 100주 = 800,000원 |
| 매도 수수료 / 가상 세금 | 800원 / 1,600원 |
| 순매도대금 | 797,600원 |
| 미수 원금 해소 후 예상 잔액 | 797,600 − 601,000 = 196,600원 |
| 최초 자기자금 대비 손익 | 196,600 − 400,000 = −203,400원 |
| 최초 자기자금 대비 손실률 | −50.85% |

위 잔액은 반대매매 대금까지 결제된 뒤의 값이며, 계산 집중을 위해 연체료 등은 제외했다. “주가 20% 하락”과 “자기자금 약 50.85% 손실”을 함께 보여 준다.

추가 충격 버튼을 누르면 매도가격이 5,000원이 된다. 순매도대금 498,500원으로는 미수 원금 601,000원을 모두 해소하지 못해 **102,500원이 남는다**. 주식이 모두 없어져도 채무가 남을 수 있음을 직접 확인한다.

안내 문구: “주문이 가능했던 이유는 결제대금이 충분해서가 아니에요. 일부 증거금으로 주문했기 때문이에요. 강제로 팔린 뒤에도 갚아야 할 돈이 남을 수 있어요.”

### 놓치기 쉬운 별도 분기

결제 마감 당일 “다른 주식을 오늘 팔아서 채우기”를 선택하면 그 매도의 결제일을 새로 표시한다. 매도 체결만으로 당일 현금 납부가 완료됐다고 처리하지 않는다. 실제 상계·재매매·대출 가능 여부는 계좌 정책별 확인이 필요하다는 문맥 설명을 붙인다.

완료 조건: 예상 부족액 601,000원을 계산하고, 결제일까지의 조치를 선택하고, 미해소 경로에서 남은 채무를 확인한다. 재도전에서는 현금 500,000원, 동일 주문으로 부족액 501,000원을 계산한다.

## 10. 과정 G — 선물: 증거금, 계약 규모, 일일정산

### 먼저 보여 줄 차이

주식 1주를 사는 화면 옆에 선물 1계약의 `계약가격 × 승수 × 계약 수`를 보여 준다. 증거금은 계약대금 전체나 최대 손실액이 아니라 계약 이행을 위해 맡기는 담보 성격의 돈이다. 근거: [한국거래소 증거금 종류 및 구성](https://clearing.krx.co.kr/contents/RGL/06/06020201/RGL06020201.jsp).

### 가상 상품 명세

실제 코스피200 선물 등과 혼동되지 않도록 상품명을 **학습지수 선물**로 한다. 실제 상품의 승수·증거금률·기본예탁금·거래 자격을 재현하지 않는다.

| 항목 | 가상 값 |
|---|---:|
| 시작 현금 | 200,000원 |
| 진입가격 | 100포인트 |
| 승수 | 포인트당 10,000원 |
| 수량 / 방향 | 1계약 / 매수 |
| 계약 명목금액 | 1,000,000원 |
| 개시증거금 / 유지증거금 | 200,000원 / 150,000원 |
| 비용 | 첫 실습에서는 0원, 후속 비용 실습에서 별도 반영 |
| 증거금 기준 | 해당 시나리오 동안 고정된 가상 금액 |
| 추가증거금 규칙 | 계좌 평가액이 유지증거금 미만이면 개시증거금까지 보충 |

실제 증거금은 상품·시장 상황 등에 따라 달라지므로 이 비율을 실제 시장 규칙처럼 설명하지 않는다. 상품별 개시·유지증거금 구분은 [NH선물 국내선물 증거금 안내](https://mail.futures.co.kr/content/Getcontent.do?content=3000044)를 참고한다.

### G-1. 증거금을 낸 뒤 무엇을 보유하는가

1. 1계약 매수 전 명목금액을 입력한다. 정답은 1,000,000원이다.
2. 주문 후 현금 200,000원 중 증거금으로 묶인 200,000원을 확인한다.
3. “현금 200,000원을 냈으니 그 금액만큼의 주식을 가진 것일까요?”에 답한다.
4. 포지션 카드에 `학습지수 선물 매수 1계약`, `1포인트 변화 시 10,000원 손익`을 표시한다.

증거금을 수수료처럼 없어진 돈으로 표현하지 않는다. 신규 진입 시 200,000원의 거래 손실이 생긴 것으로 계산해서도 안 된다.

### G-2. 가격 방향과 손익

가격을 103 또는 97로 이동한다. 매수 1계약은 각각 +30,000원, −30,000원이다. 시작 증거금 200,000원 대비 ±15%이지만 지수 변화는 ±3%임을 비교한다.

다시 초기화해 매도 1계약으로 바꾸면 103에서 −30,000원, 97에서 +30,000원이다. 선물 매도 포지션과 보유 주식 매도는 다른 행위임을 설명한다.

### G-3. 일일정산과 중복 계산 방지

| 시점 | 정산가격 | 당일 정산손익 | 정산 후 계좌금액 | 최초 대비 누적손익 |
|---|---:|---:|---:|---:|
| 100에 매수 | 100 | 0원 | 200,000원 | 0원 |
| 1일 차 종료 | 103 | +30,000원 | 230,000원 | +30,000원 |
| 2일 차 종료 | 101 | −20,000원 | 210,000원 | +10,000원 |

사용자는 2일 차 손익 기준가격을 100과 103 중 선택한다. 정답은 전일 정산가격 103이다. 아직 포지션을 청산하지 않았어도 일일정산으로 손익이 반영될 수 있으며, 이미 정산한 이익을 누적 평가손익에 다시 더하면 안 된다. 일일정산·최종결제 개념은 [KB증권 선물 거래 안내](https://www.kbsec.com/go.able?linkcd=s040313010002)를 참고한다.

### G-4. 추가증거금과 대응

최초 상태로 되돌려 가격이 94가 되면 손실 60,000원, 계좌 평가액 140,000원이 된다. 유지증거금 150,000원보다 작으므로 가상 규칙상 추가증거금은 `200,000 − 140,000 = 60,000원`이다.

사용자가 10,000원이라고 답하면 “유지 기준과의 차이는 10,000원이지만, 이 연습은 개시증거금 수준까지 채우는 규칙이에요”라고 설명한다.

| 선택 | 직접 수행할 일 | 결과 확인 |
|---|---|---|
| 보충 | 가상 현금 60,000원 입금 | 계좌 200,000원, 누적 투입 260,000원, 누적 손실 60,000원 |
| 자발적 청산 | 94에 반대 방향 주문으로 1계약 청산 | 포지션 0, 비용 제외 잔액 140,000원 |
| 미대응 | 가상 납부 시한 경과 | 92에 강제청산되는 경로 실행, 비용 제외 잔액 120,000원 |

이미 발생한 추가증거금 요구가 청산만으로 어떤 시점에 해소되는지는 실제 계좌 규칙에 달려 있다. 실습에서도 주문 제출만으로 해소 처리하지 않고, 체결과 계좌 재계산 이후 부족금 0원을 확인하게 한다.

충격 분기: 100에서 진입한 뒤 급격히 75에서 청산되면 손실 250,000원으로 초기자금 200,000원을 초과한다. 추가 납부할 금액은 50,000원이다. 유지증거금 경고가 항상 원하는 가격에 청산시켜 주는 장치는 아니라는 점을 설명한다.

### G-5. 비용과 만기까지 확인하기

후속 문제에서는 진입·청산 수수료를 각각 가상 1,000원으로 설정한다. 현금 202,000원에서 100에 진입하고 103에 청산하면, 비용 반영 잔액은 230,000원, 손익은 +28,000원이다. 이 예시의 파생상품 관련 세금은 생략했다고 표시한다.

마지막에는 현금결제형으로 정한 학습 상품의 만기일을 이동한다. `만기 전 반대매매로 청산`과 `만기 최종결제`를 비교하고, 다음 만기 계약을 새로 여는 것은 별도 거래임을 보여 준다. 모든 선물이 동일한 결제 방식을 갖는다고 설명하지 않는다.

완료 조건: 계약 규모·1포인트 손익·추가증거금을 계산하고, 정산손익을 중복 합산하지 않으며, 초기 증거금을 초과한 손실 가능성을 설명한다.

## 11. 과정 H — 추가로 확장할 특수 거래 실습

F·G 완성 후 선택 과정으로 제공할 예시다. 제도·거래 가능 여부·자격 요건은 실제 제공 시 별도 검증한다. 아래는 가상 계약을 통한 개념 학습이다.

### H-1. 신용융자: 빌린 돈에는 기간 비용이 생긴다

자기자금 400,000원과 융자금 600,000원으로 주식 1,000,000원어치를 보유한 상태에서 시작한다. 계산 집중을 위해 매매 비용은 제외한다. 가상 연 이자율 10%, 365일 기준 단리로 10일을 이동하면 이자는 원 미만 버림 1,643원이다.

사용자는 가격 변화가 없어도 상환 원리금 601,643원이 필요함을 확인한다. 같은 날 전량 매도 후 대금 결제와 원리금 상환까지 마치면 자기자금은 398,357원이 된다. `매도 주문 제출`, `대금 결제`, `융자 상환 확인`을 차례로 수행한다.

오답 피드백: “주가가 그대로여도 돈을 빌린 기간에 대한 비용이 생겼어요.” 미수거래의 결제 부족과 약정된 신용융자의 만기·이자·담보 관리는 서로 구분한다.

### H-2. 공매도: 빌린 주식은 다시 사서 돌려줘야 한다

가상 대차 계약으로 10주를 빌려 10,000원에 매도한다. 비용 제외 시 8,000원에 다시 사서 반환하면 20,000원 이익, 12,000원에 사서 반환하면 20,000원 손실이다.

사용자가 `차입 → 매도 → 재매수 → 반환` 순서 카드를 배치한 뒤 양쪽 가격 경로를 실행한다. 단순히 매도 버튼만 누르면 완료되지 않는다. 받은 매도대금 100,000원을 자유롭게 출금 가능한 이익으로 표시하지 않고 담보·반환 의무를 함께 보여 준다.

차입 비용·담보 요구·반환 조건·가격 상승에 따른 손실을 확인하는 후속 장면을 둔다. 보유 주식 매도, 선물 매도, 차입 주식 매도를 구분하는 문제로 끝낸다.

### H-3. 레버리지 ETF: 며칠 수익률이 단순 배수는 아니다

비용·추적오차를 제외한 가상 일간 2배 상품을 사용한다. 지수와 상품 모두 100에서 출발한다.

| 시점 | 지수 | 가상 일간 2배 상품 |
|---|---:|---:|
| 시작 | 100 | 100 |
| 1일 차 +10% | 110 | 120 |
| 2일 차 −10% | 99 | 96 |

사용자가 두 번째 날 결과를 예상한 후 날짜를 이동한다. 지수의 누적 수익률은 −1%, 상품은 −4%이며 ‘기간 수익률의 무조건 2배’가 아님을 확인한다. 일간 목표 수익률의 누적 계산에서 생기는 차이라는 점을 설명한다.

### H-4. 옵션 입문: 권리와 의무 비교

추가 확장 후보로 둔다. 가상 콜옵션의 행사가 100, 프리미엄 5, 승수 1을 고정한다. 만기 기초자산 가격을 90·100·110으로 이동하면 매수자의 비용 제외 순손익은 각각 −5·−5·+5다. 사용자가 행사 이익과 지급한 프리미엄을 따로 계산하게 한다.

매도자 관점은 프리미엄 수취와 이행 의무를 함께 표시한다. 프리미엄 수입을 확정 수익으로 오인하지 않게 하며, 담보와 큰 손실 가능성을 별도 심화에서 다룬다. 첫 출시 범위에서는 F·G보다 우선하지 않는다.

## 12. 학습 평가와 피드백 기준

### 클릭 완료와 이해 완료를 분리한다

| 수준 | 확인 방식 | 예시 |
|---|---|---|
| 따라 해봄 | 안내가 있는 조작 완료 | 2주 매수 주문 |
| 이해함 | 금액·원인 예측 정답 | 비용 포함 필요금액 100,100원 |
| 적용함 | 새로운 수치·상황으로 재도전 | 3주 매수 또는 휴장일 포함 결제일 |

완료 화면은 “거래 전문가” 같은 표현 대신 `수수료 계산 가능`, `결제일 확인 가능`, `추가증거금 계산 복습 필요`처럼 확인된 능력을 표시한다.

숫자 문제는 쉼표·원 단위 표기를 허용하고 정해 둔 버림 규칙에 따라 채점한다. 서술형은 키워드 하나만으로 탈락시키지 않는다. 객관식 원인 선택과 사용자의 메모를 함께 받고, 자유 기록은 회고 자료로 사용한다.

### 통합 졸업 실습 예시

초기 현금 1,000,000원으로 20,000원 주식 10주를 산다. 매수 수수료는 200원이다. 매수 결제가 끝난 뒤 5주를 22,000원에 팔고 해당 매도의 결제일까지 진행한다. 외부 입출금과 다른 주문은 없다.

정답: 매수 후 예상 현금 799,800원, 매도대금 110,000원, 매도 수수료 110원, 가상 세금 220원, 순수령액 109,670원, 최종 현금 909,470원이다. 남은 5주 평가액 110,000원을 더한 순자산은 1,019,470원이다. 매도한 5주의 원가에 매수 수수료 100원을 배분하면 실현손익은 +9,570원, 남은 주식의 비용 반영 평가손익은 +9,900원이다.

사용자는 금액 계산뿐 아니라 선택 계좌, 미체결 여부, 결제일, 출금가능금액을 확인한다. 심화 과정은 별도의 미수·선물 문제로 평가하며 기본 과정 완료를 위해 심화 거래를 하도록 강제하지 않는다.

### 학습 효과를 확인할 지표

- 설명을 보기 전 금액 예측 정답률과 재도전 정답률의 차이
- 수수료 누락, 예수금·출금 혼동, 증거금·최대 손실 혼동의 발생 빈도
- 안내 없이 계좌·주문·결제 내역을 찾아 확인한 비율
- 과정별 중단 지점과 소요 시간
- 일정 기간 뒤 다른 숫자로 복습했을 때 정답률

단순 클릭 수, 거래 횟수, 수익률, 심화 거래 진입률은 학습 성공의 주 지표로 쓰지 않는다. 평가 답안과 사용자의 실제 금융정보를 연결할 필요도 없다.

## 13. 기존 화면에 연결하는 방법과 우선순위

### 1차 — 매수·매도 과정의 학습 밀도 개선

기존 `quantity` 단계에 비용 예측을, `confirm` 단계에 거래대금·수수료·세금·총액 분해를, `holding` 단계에 변화 전후 비교와 원인 설명을 추가한다. 기존 검색·차트 안내는 첫 경험에서 제공하고 재학습에서는 생략할 수 있게 한다. A·B와 숫자가 바뀐 재도전까지를 하나의 완성 범위로 본다.

### 2차 — 계좌와 주문의 시간축

기존 계좌 읽기·주문 상태 가이드를 C·D·E와 연결한다. 핵심은 결제 전 금액을 출금가능금액과 구별하고, 미체결 취소 이후에도 체결분의 결제 의무가 남는다는 사실을 일관되게 보여 주는 것이다.

### 3차 — 미수와 선물의 독립 실습

F·G는 기본 주식 주문 화면의 옵션 하나로 끝내지 않고, 결제 마감 또는 일일정산 시계를 가진 별도 과정으로 제공한다. 가상 계좌와 가상 상품 안에서 입금·청산·미대응을 되돌려 비교할 수 있게 한다.

### 4차 — 특수 거래 비교와 복습

H의 선택 과정을 추가하고 사용자가 자주 틀리는 개념을 짧은 복습으로 연결한다. 고정 계산 결과와 완료 판정은 동일한 규칙을 따르게 하고, AI 코칭은 사용자가 틀린 원인을 쉬운 말로 설명하는 데 활용한다.

## 14. 콘텐츠 검수 기준

- 모든 장면에 목표·사용자 행동·계좌 결과·피드백·완료 조건이 있다.
- 거래 접수, 체결, 취소 완료, 결제 완료를 서로 구별한다.
- 매수 수수료와 매도 수수료·가상 세금을 각각 해당 시점에 반영한다.
- 총자산 설명에서 현금과 미결제 대금을 중복 합산하지 않는다.
- 미수·융자 계좌의 순자산에는 채무를 반영하고 외부 입금을 이익으로 처리하지 않는다.
- 부분 매도에서 매수 비용 배분 기준을 유지한다.
- 출금 이후 계좌자산 감소를 투자 손실로 표시하지 않는다.
- 선물 증거금을 비용이나 손실 한도로 설명하지 않는다.
- 일일정산 손익과 누적손익을 중복 반영하지 않는다.
- 반대매매 이후 잔존 채무와 대금 결제 시점을 확인할 수 있다.
- 가상 요율·계약 조건이 실제 금융상품의 현재 조건처럼 보이지 않는다.
- 가격 상승만 제공하지 않고 손실·미체결·자금 부족 상황도 제공한다.
- 안내를 끄고 다른 숫자로 풀 수 있으며 틀린 단계만 재시도할 수 있다.
- 휴장일·키보드 조작·색상 외 금액 변화 표기를 함께 검토한다.
