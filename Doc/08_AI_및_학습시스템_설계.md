### 1-2. 🔴 핵심 문제: AI의 실체가 없음

```python
# routers/ai.py — 외부 AI 서버로 프록시만 함
async def _call_ai(path: str, payload: dict | None = None) -> dict:
    async with httpx.AsyncClient(timeout=30) as client:
        resp = await client.post(f"{settings.AI_SERVER_URL}{path}", json=payload)
    ...
    except httpx.ConnectError:
        raise HTTPException(503, "AI 서버에 연결할 수 없습니다.")
```
`AI_SERVER_URL=http://localhost:8001`인데 **그 서버가 존재하지 않습니다.**
설문을 제출해도 성향 분석 결과가 생성되지 않아 `/api/ai/propensity`는 언제나 null을 반환합니다.

## 3. AI 아키텍처 공통 원칙

```text
  [1] 정량 계산은 서버(Python)가 한다     → 승률, 회전율, 손익, 비중 등
  [2] LLM은 "계산된 숫자를 해석·설명"만    → 환각(hallucination) 방지
  [3] 출력은 JSON 스키마로 강제           → 파싱 실패 대비 재시도 1회
  [4] 모든 결과는 DB에 저장               → 재호출 방지 = 비용 절감
  [5] 실패 시 규칙기반 폴백이 항상 존재    → AI 없이도 서비스가 죽지 않음
```

> 🔴 **[5]가 특히 중요합니다.** 현행은 AI 서버가 없으면 그냥 503이 나갑니다.
> 모든 AI 기능은 **"규칙기반 결과 → AI가 성공하면 덮어쓰기"** 구조로 만드세요.

### 목표 모듈 구조
```text
app/services/ai/
├── llm_client.py       # JSON 강제 출력, 재시도, 타임아웃, 비용 카운터
├── propensity.py       # 설문 → 규칙 점수(폴백) + LLM 해석
├── coach.py            # 매매 지표 계산 + LLM 코칭
├── news_pipeline.py    # 수집 → 요약 → 감성 → DB 저장
└── prompts/            # 프롬프트 템플릿 (버전 관리)
```

### 모델 선택 가이드

| 후보 | 장점 | 단점 |
|---|---|---|
| Claude / GPT API | 한국어 품질 우수, 구현 간단 | 유료 (예산 필요) |
| 로컬 오픈소스 | 무료, "직접 돌렸다"는 어필 | GPU 필요, 한국어 금융 품질 낮음 |

**권장**: 상용 API + 강력한 캐싱. `.env`에 `LLM_PROVIDER` / `LLM_API_KEY` / `LLM_MODEL` 추가.

### 💰 비용 통제 전략
1. **뉴스 요약은 `article_url` 유니크로 1회만** (`04` 문서 §4-5 설계에 반영됨)
2. 성향 분석은 설문 회차당 1회. 재조회는 DB에서.
3. 코치 리포트는 **주 1회** 또는 사용자 명시 요청 시에만.
4. 프롬프트에 본문 전체 대신 **1,500자 이내**만 전달.
5. `AI_MONTHLY_BUDGET` 초과 시 자동 폴백 모드 + 관리자 알림.
6. 개발 중에는 응답을 파일로 캐싱해 같은 입력에 API를 다시 부르지 않기.

## 4. 기능 1 — 투자 성향 분석

### 4-1. 현행 데이터 구조의 한계

```python
# 현행: 문항 "번호"와 답변 "텍스트"만 저장
class UserSurveyResponse:
    question_number: int      # 1, 2, 3...
    selected_answer: str      # "30대", "시세차익 목적"
```
문항·선택지가 DB에 없어 **점수화가 불가능**하고, 프론트는 더미 텍스트를 보여주고 있습니다.
또 재설문 시 기존 답변을 `DELETE`하므로 **이력이 사라집니다.**

**보강**: `survey_question` / `survey_option` 테이블 추가 + `attempt_no` 컬럼 (`04` 문서 §4-5).

### 4-2. 설문 확정안 (프론트 `Survey.jsx`의 6문항 기준)

| # | 문항 | 선택지 (점수) |
|---|---|---|
| 1 | 투자 경험이 있나요? | 전혀 없음(0) / 1년 미만(5) / 1~3년(10) / 3년 이상(15) |
| 2 | 투자할 자금의 성격은? | 잃으면 안 되는 생활비(0) / 목적 있는 저축(5) / 여윳돈(12) / 없어도 되는 돈(20) |
| 3 | 손실을 얼마나 감당할 수 있나요? | 원금 보존 필수(0) / -5%까지(7) / -20%까지(15) / -30% 이상도(25) |
| 4 | 원금을 얼마나 보존하고자 하나요? | 100%(0) / 90% 이상(6) / 70% 이상(12) / 상관없음(18) |
| 5 | 투자 예정 기간은? | 6개월 미만(2) / 6개월~1년(6) / 1~3년(10) / 3년 이상(12) |
| 6 | 투자의 목표는? | 예금 이상 수익(2) / 물가상승률+α(6) / 적극적 자산증식(10) / 단기 고수익(10) |

**합계 0~100점** → 성향 매핑

| 점수 | `style_code` | 표시명 |
|---|---|---|
| 0-20 | `STABLE` | 안정형 |
| 21-40 | `STABLE_SEEKING` | 안정추구형 |
| 41-60 | `NEUTRAL` | 위험중립형 |
| 61-80 | `RISK_SEEKING` | 적극투자형 |
| 81-100 | `AGGRESSIVE` | 공격투자형 |

> 팀 설계 문서(Google Docs 3p)의 결과 4분류(적극/균형/안정/초보 투자형)와도 호환됩니다.
> 5분류가 부담스러우면 4개로 줄여도 무방하니 **팀에서 하나로 확정**하세요.
>
> 이 규칙 점수가 **폴백이자 검증 기준**입니다. LLM 결과가 이 구간에서 2단계 이상 벗어나면
> 규칙 결과를 채택하세요 (환각 방지).

### 4-3. 제출 흐름 (현행 → 목표)

```text
현행:  POST /api/ai/survey → user_survey_response INSERT → 끝 (분석 없음)

목표:  POST /api/ai/survey
         ① user_survey_response INSERT (attempt_no 포함)
         ② 규칙 점수 계산 → style_code 산출        ← LLM 없이도 여기까지 완성
         ③ ai_propensity_advice INSERT (규칙 결과)
         ④ LLM 호출 시도 → 성공 시 요약·조언 덮어쓰기, 실패 시 규칙 문구 유지
         ⑤ users.investment_style 캐시 갱신
       ← { style_code, risk_score, summary, guide, recommended_concepts, is_fallback }
```

### 4-4. LLM 프롬프트

```text
[System]
당신은 초보 투자자를 돕는 금융 교육 코치입니다.
특정 종목의 매수/매도를 추천하거나 수익을 보장하는 표현은 절대 사용하지 마세요.
결과는 반드시 아래 JSON 스키마로만 출력하세요.

[User]
사용자 설문 응답:
1. 투자 경험: 1년 미만
2. 자금 성격: 여윳돈
3. 손실 감내: -5%까지
4. 원금 보존: 90% 이상
5. 투자 기간: 6개월~1년
6. 투자 목표: 물가상승률+α

규칙 기반 산출 점수: 31점 / 100 (안정추구형)

출력 스키마:
{
  "style_code": "STABLE|STABLE_SEEKING|NEUTRAL|RISK_SEEKING|AGGRESSIVE",
  "style_label": "한국어 표시명",
  "summary": "2~3문장 성향 요약. 초보자도 이해할 쉬운 말로.",
  "strengths": ["강점 2개"],
  "cautions": ["주의할 점 2개"],
  "guide": "이 성향의 사용자를 위한 5문장 이내 투자 학습 가이드",
  "recommended_concepts": ["learn_concept의 concept_id 2~3개"]
}
```

> ⚠️ LLM 호출이 5~15초 걸릴 수 있으므로 **프론트에 로딩 UI 필수**.
> 15초 초과 시 규칙 결과로 폴백하고 `"is_fallback": true`를 내려주세요.

## 5. 기능 2 — AI 뉴스 요약 + 감성 분석

### 5-1. 현행 vs 설계 문서의 불일치 🔴

팀 자체 설계 문서(Google Docs 1p)는 이렇게 명시합니다.
> 네이버 뉴스 **검색 API** → 기사 URL 수집 → 크롤링 → AI 요약 → **DB 저장** → 요약 + 원문 링크 제공
> 기사 전문을 크롤링해 재배포하는 것은 저작권 문제로 불가능

그런데 현행 `news_service.py`는 **네이버 금융 페이지 HTML을 직접 파싱**하며,
DB 저장도 AI 요약도 없고 요청마다 실시간 크롤링합니다.

| 문제 | 내용 |
|---|---|
| 약관 | 공식 API가 아닌 직접 크롤링 — **팀이 스스로 정한 원칙과도 어긋남** |
| 안정성 | `table.type5` 선택자는 HTML 변경 시 즉시 빈 배열. 종목 뉴스 페이지는 iframe 구조라 동작 검증 필요 |
| 성능 | 요청마다 크롤링 → 응답 지연 |
| AI 미연결 | `ai_news_summary` 테이블이 아예 없어 저장할 곳이 없음 |

### 5-2. 목표 파이프라인 (설계 문서대로 복원)

```text
[수집]  스케줄러 30분 주기 — 네이버 뉴스 검색 오픈API로 목록·URL 확보
          ↓
[중복]  article_url이 이미 DB에 있으면 skip        ← 비용 절감 핵심
          ↓
[본문]  기사 본문 추출 (BeautifulSoup), 1,500자로 절단

          ↓

          ↓
```

## 7. 기능 4 — AI 투자 코치

### 7-1. 서버가 먼저 계산할 지표 (LLM에 넘길 재료)

`trades` 테이블이 생긴 뒤에 가능합니다.

```python
def build_metrics(user_id, period) -> dict:
    trades = get_trades(user_id, period)
    return {
      "trade_count":      len(trades),
      "win_rate":         이익매도수 / 전체매도수,
      "avg_holding_days": 평균 보유기간,
      "turnover_rate":    기간 매매대금 / 평균 자산,   # ★ 뇌동매매 지표
      "concentration":    최대 종목 비중,              # ★ 분산 실패 지표
      "loss_cut_rate":    -10% 이하에서 손절한 비율,   # ★ 손절 규율
      "avg_win": ..., "avg_loss": ...,                 # ★ 손익비
      "top_loss": {"symbol":"035420","pnl_rate":-12.4},
      "buy_after_surge_ratio": 급등일(+5%↑) 매수 비율, # ★ 추격매수 지표
      "style_code": "STABLE_SEEKING"                   # 설문 성향
    }
```

> Google Docs 2p의 코치 예시("평균 보유 기간이 2일로 매우 짧습니다", "손실 발생 후 즉시 재매수하는
> 경향이 있습니다", "반도체 업종에 비중이 집중되어 있습니다")가 위 지표와 정확히 대응합니다.

### 7-2. 성향과 실제 행동의 '불일치' 진단 ★ 가장 강력한 기능

```text
설문 성향: 안정추구형 (손실 -5%까지만 감내)
실제 행동: 평균 보유기간 1.8일, 회전율 420%, 최대 종목 비중 68%

→ AI 코치: "설문에서는 안정추구형이라고 하셨지만, 실제 매매는 공격투자형에 가까워요.
            특히 한 종목에 68%를 집중하셨는데, 이 종목이 -20% 하락하면
            전체 자산이 -13.6% 줄어듭니다. '분산투자' 개념을 함께 볼까요?"
            [분산투자 3분 학습 →]
```

이 기능 하나가 발표자료의 기대효과 3개를 동시에 충족합니다.
- 비이성적 투자행태 개선 (뇌동매매 지표화)
- 리스크 관리의 극대화 (집중도·MDD 제시)
- 합리적 의사결정 보조 (근거 있는 피드백)

> **심사 데모 시나리오로 이 화면을 준비하세요.** 다른 모의투자 사이트에 없는 기능입니다.
