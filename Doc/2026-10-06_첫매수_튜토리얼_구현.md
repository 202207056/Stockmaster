# 첫 매수 튜토리얼과 주문유형 구현

## 변경된 진입 방식

- 일반 트레이딩의 매수 입력창을 처음 클릭하거나 키보드로 조작하면 현재 URL과 트레이딩 화면을 유지한 채 매수창 자리에 튜토리얼을 연다. 원래 주문 동작은 중단되며 자동 재전송하지 않는다. 매도 탭 선택 자체는 가로채지 않는다.
- 계좌 선택 → 현재가·호가 개념 창 → 시장가/지정가 비교 주문 → 나머지 주문유형 → 시장가 2주 입력 → 수수료 계산·이해 확인 → 최종 가상 체결 순으로 진행한다. 폼 조작은 즉시 다음 항목으로 이동한다. 개념 창은 설명을 읽고 이해 확인을 마친 후 버튼으로 진행한다.
- 가상 주문을 체결하고 결과 확인을 눌러야 최초 안내를 마친 것으로 저장한다. 비교·수수료 개념 창에 두 이해 확인 문항과 오답 설명을 추가했다. 두 정답과 최종 체결 확인이 완료의 선행 조건이다. 이 기록을 장기 개념 숙달이나 실제 투자 역량의 입증으로 보지 않는다. 종료만 하면 완료되지 않는다. 중도 종료 후 현재 화면에서는 바로 다시 띄우지 않으며, 다음 방문에서는 미완료 사용자에게 다시 안내한다.
- 완료 표시는 이 브라우저의 사용자별 키로 저장한다. 사용자 식별자는 일방향으로 변환한 구분값만 사용하고, 계좌번호·잔고·주문 내역을 넣지 않는다. 보안용 해시는 아니며 브라우저 간 동기화하지 않는다. 비로그인 사용자는 기기 공통 표시를 쓴다. 저장 불가 시 현재 실행 세션에서만 완료 표시를 유지한다.
- 학습 탭의 ‘첫 매수 · 주문유형과 수수료’에서 완료 여부와 관계없이 재시작한다. 재시작 링크는 `/trading?practice=buy`이며 별도 학습 페이지 대신 트레이딩의 같은 매수창 위치에서 연다.

## 화면과 데이터 경계

- 새 튜토리얼과 일반 주문은 같은 `TradingOrderForm`과 `OrderDialog`를 사용한다.
- 2026-10-07 변경: 기존 트레이딩과 일반 주문 폼은 마운트를 유지하고, 일반 폼을 숨긴 자리에 가상 폼을 표시한다. 주변 화면은 어둡게 표시하고 inert로 조작을 막는다. 안내 내부에 키보드 초점을 유지하며 종료 버튼 또는 Esc로 닫는다. 주문 확인 대화상자가 열렸을 때는 해당 대화상자가 Esc를 처리한다.
- 종료하면 기존 종목·차트·주문 입력값을 유지하고 원래 초점·스크롤을 복원한다. 완료/종료 동작으로 기존 주문을 자동 실행하지 않는다.
- 가상 폼의 계좌 선택·체결은 로컬 상태만 변경한다. 배경 화면의 정상 로그인 복구·시세·계좌 조회는 유지될 수 있으므로 페이지 전체 API 호출 0건을 보장하는 구조는 아니다. 가상 거래에서는 계좌 변경·주문 API를 호출하지 않는다.
- 제목·진행률·가상 종목 카드·하단 설명 등 추가 영역을 제거했다. 원래 매수창의 배치를 유지하며 현재 조작 대상에 강조 테두리와 말풍선만 겹친다. 말풍선은 대상 좌표와 스크롤·화면 크기에 맞춰 따라다닌다. 화면에 맞춰 좌우 또는 위아래에 배치하고 현재 항목 외 조작을 막는다.
- 예시전자와 두 가상 계좌는 메모리에서만 관리한다. 종료·새로고침 시 거래 상태를 초기화한다. 학습 완료 표시 외에 가상 거래를 저장하지 않는다.
- 50,000원 × 2주 + 모의 수수료 15원 = 100,015원. 가상 현금 1,000,000원 → 899,985원, 주식 평가액 100,000원, 총자산 999,985원이다.
- 요율은 사이트의 기존 모의 정책이다. 실제 증권사 수수료·법정 세율과 동일하다는 의미가 아니다. 기존 매도 등 다른 구형 튜토리얼은 이번 변경의 대상이 아니다.

## 일반 주문 기능

화면에서 지정가·시장가·중간가·최유리지정가·최우선지정가를 선택할 수 있다. 서버는 중간가·최유리·최우선을 고객이 보낸 가격으로 처리하지 않고 읽기 전용 KIS 최우선 호가 조회로 계산한다. 유효한 호가가 없으면 현재가로 대체하지 않고 오류를 반환한다.

| 유형 | 이번 사이트의 모의 처리 |
|---|---|
| 지정가 | 입력 가격으로 대기 등록. 내역의 ‘체결 확인’으로 서버 호가와 비교 |
| 시장가 | 기존 정책 유지: 서버 현재가로 전량 체결 |
| 중간가 | 양쪽 최우선 호가의 평균을 원 미만 절사. ‘체결 확인’ 때 다시 계산 |
| 최유리지정가 | 접수 시 상대편 최우선 호가에 가격 고정 |
| 최우선지정가 | 접수 시 같은 방향의 최우선 호가에 가격 고정 |

**모의 체결 범위:** 최우선 호가의 잔량으로 전량 거래 가능한 경우에만 해당 호가로 체결하고, 그렇지 않으면 대기한다. 실제 거래소의 부분 체결, 호가 소진·대기 순서, 실시간 자동 매칭을 재현하지 않는다. 중간가도 실시간 자동 재가격이 아니라 명시적인 체결 확인 시점에 갱신한다. 이를 일반 화면과 학습 화면에 명시한다.

대기 주문의 현금·보유수량을 예약하지 않으며, 체결 시 계좌와 보유수량을 다시 잠그고 확인한다. 부족하면 거부 상태가 된다. 취소된 주문이나 이미 체결된 주문은 다시 체결하지 않는다. GET 내역 조회로는 주문·자산을 변경하지 않는다.

추가 API:

- `GET /api/trading/orders/book/{symbol_code}`: 인증 사용자의 읽기 전용 호가 조회.
- `POST /api/trading/orders/{order_id}/check`: 본인 계좌의 대기 주문에 대한 모의 체결 확인.

## 예약·조건 UI 통합

- 트레이딩 하단의 독립적인 예약·조건 주문 영역은 제거했다.
- 매수·매도 창의 ‘실행 방식’에서 즉시 / 예약 / 조건을 고른다.
- 예약·조건은 같은 계좌·종목·매수/매도·수량 입력값을 사용한다. 중복 매수/매도·수량 필드를 표시하지 않는다.
- 기존 서버 자동주문은 **시장가 실행만 지원**하므로 예약·조건 선택 시 시장가로 표시하고 주문유형 선택을 잠근다. 이는 지정가·최유리 등 예약 실행까지 확장한 기능이 아니다.
- 실행시각 또는 감시가격·이상/이하, 만료를 입력하고 등록 확인 후 전송한다. 예약·감시 내역과 취소는 같은 창 안의 접기 영역에 있다.
- 확인 중·처리 중·결과 불명확 상태에는 공통 입력을 잠근다. 결과 불명확 시 동일 등록 키로 조회·재시도하는 기존 중복 방지 흐름을 유지한다.
- 기존 예약·조건 서버 설정·마이그레이션·감시 프로세스가 준비되어 있어야 실행된다. 본 작업은 배포·마이그레이션 실행을 포함하지 않는다.

## 검증과 적용 전 확인

검증 결과: 프런트엔드 전체 94개 테스트, 백엔드 주문유형·예약조건 29개 테스트 통과. ESLint와 프로덕션 빌드 통과. 빌드에는 기존 단일 번들 크기 권고가 남아 있다.

- SQLite와 가짜 시세로 다섯 주문유형, 매수·매도 가격 방향, 수수료, 중간가 갱신, 잔량 부족, 잔고 부족, 취소 후 확인, 중복 체결 방지, 소유권을 테스트한다.
- UI 테스트에서 첫 매수 조작 차단, 가상 튜토리얼 컴포넌트의 API 호출 0건, 현재 화면 유지·기존 폼 복원, 재시작 경로와 Esc 종료, 계좌 선택, 다섯 유형 선택, 비용 확인, 가상 체결, 행동에 따른 자동 진행, 완료 표시를 확인한다.
- 예약·조건을 공통 매수창에서 등록할 때 즉시 주문이 함께 전송되지 않는지 확인한다.
- 브라우저에서 계좌·유형 선택과 수수료·체결 확인창을 점검한다.
- 실제 KIS 자격증명을 사용한 라이브 호가 호출, 운영 DB 변경, 서비스 배포는 수행하지 않는다. 운영 적용 시 해당 환경의 읽기 전용 호가 응답과 API 버전을 확인해야 한다.
- 사용자 대상 학습 효과 측정은 별도 파일럿이 필요하다. 자동 테스트 통과가 실제 교육 효과를 증명하지 않는다.

## 비교 체험 및 반응형 안내 보강

- 같은 초기 시세(최근 거래 50,000원, 최저 매도 50,100원·100주)에서 시장가 1주 체결과 50,000원 지정가 미체결을 각각 기존 주문창으로 체험한다.
- 지정가 결과 창에서 매도 호가를 49,900원으로 바꾸면 한도 이하 체결을 보여준다. 이 변화는 두 주문의 동일 시세 비교와 구분한다. 다른 대기 주문이 없고 충분한 물량이 있다는 가정, 미체결 가능성을 명시한다.
- 비교 거래는 교육용 로컬 시나리오이며 계좌 잔고를 차감하지 않는다. 일반 사이트의 현재가 전량 체결 정책과 구별한다. 최종 체결에만 100,015원을 가상 차감한다.
- 수수료 개념 창은 거래금액 100,000원 + 수수료 15원 = 출금 100,015원을 분리하고, 현금 100,000원 가정에서 부족액을 판단하게 한다. 오답은 설명 후 재시도하며 정답 전 진행을 막는다.
- 일반 주문창에서 삭제한 시장가 상시 설명은 복원하지 않는다. 개념 창에서만 비교 원리와 모의 환경의 차이를 안내한다.
- 위치는 고정 좌표나 CSS 배치 클래스 대신 실제 폼의 data-tutorial-target 식별자를 기준으로 계산한다. 폼·대상·말풍선 ResizeObserver, 폼 내용 변경, 스크롤, 창 크기 및 visualViewport 변경을 관찰하고 재배치한다. 기존 마커가 유지되는 한 너비·높이·줄바꿈 변경을 따라간다. 기능 자체를 다른 컴포넌트로 옮길 경우 해당 마커도 실제 조작 대상으로 옮겨야 한다.
- 검증: 비교 체결/미체결/호가 변경, 오답 진행 차단, 수수료 이해 확인, API 비전송, 계좌 격리 및 UI 크기 변경에 따른 강조·말풍선 재배치를 자동 테스트한다.
- 교육 사실 확인: [한국거래소 호가 유형](https://regulation.krx.co.kr/contents/RGL/03/03020204/RGL03020204.jsp), [한국거래소 시장가 체결 안내](https://regulation.krx.co.kr/contents/RGL/03/03010204/RGL03010204.jsp). 0.015%는 법정·보편 요율이 아니라 이 사이트의 모의 정책이다.


### 나머지 주문유형 체험 추가

중간가·최유리지정가·최우선지정가도 기존 매수창에서 유형 선택 후 모의 매수를 눌러 개별 체험 창으로 연결한다. 각 체험의 조작과 이해 확인 정답을 마쳐야 다음 유형으로 진행한다.

- 중간가: 49,900/50,100원의 중간 50,000원에서 양쪽 호가를 200원 올려 50,200원으로 재계산한다. 상대 주문이 없어 여전히 대기함을 표시하고, 사이트의 체결 확인 시 갱신과 실제 제도를 구별한다.
- 최유리지정가: 초기 매도 호가 50,100원으로 체결되는 상황과, 접수 직후 그 매도 물량이 사라지고 50,300원만 남아 미체결되는 독립 상황을 비교한다. 이미 체결된 주문을 되돌린 것이 아님을 명시한다.
- 최우선지정가: 매수 호가 49,900원에 대기한다. 다른 매수자가 50,000원을 제시해도 기존 가격은 유지된다. 앞선 매수 주문이 소진된 뒤 49,900원 매도 1주를 만나 체결되는 과정을 체험한다.
- 모든 비교는 메모리 내 독립 가정이며 API 호출과 잔고 차감이 없다. 실제 부분 체결·시간 제한·대기 순서 전체를 재현하지 않는다. 세 개 이해 확인 문항의 오답 차단과 끝까지의 연결을 기존 통합 테스트에 추가했다.
