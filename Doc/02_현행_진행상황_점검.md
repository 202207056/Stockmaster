### 2-2. 발견된 결함 (프론트엔드)

**F-1 · 라우팅 버그 4건** — `frontend/src/App.jsx`

- 24행과 30행에 `/trading` 라우트가 **중복 등록**되어 있음 (뒤의 것은 사문화)
- `Signup`, `Favorites`, `Community` 3개 컴포넌트가 **import조차 되어 있지 않아** 라우트 부재
- `Landing.jsx`의 `<Link to="/register">` → **매칭되는 라우트가 없어 빈 화면**
  (파일명은 `Signup.jsx`, 링크는 `/register`로 불일치 — 경로 네이밍을 `/signup`으로 통일 권장)
- `*` (404 Not Found) 라우트 없음

**F-2 · Tailwind를 CDN으로 로드** — `frontend/index.html`

`<script src="https://cdn.tailwindcss.com"></script>`

- `cdn.tailwindcss.com`은 **공식적으로 프로덕션 사용 금지** (개발 편의용 도구)
- 빌드 시 트리셰이킹 불가 → 번들 최적화 불가, 오프라인/사내망 환경에서 스타일 전부 붕괴
- 콘솔에 경고 배너 출력 → 시연/심사 시 감점 요인
- → **9월 첫 주에 `tailwindcss` 정식 설치로 전환 필수** (조치법은 `10` 문서 A-1)

**F-3 · 스타일 자산 공백**
- `index.css`, `App.css` 모두 빈 파일. 전역 리셋, 한글 웹폰트, 색상 토큰, 다크모드 정책 없음

### 🟢 잘한 점
- 레이어 분리(routers/services/schemas/models/utils)가 정석대로 되어 있음
- 주석 품질이 매우 높아 인수인계·심사 설명에 그대로 활용 가능
- **KIS 토큰 23시간 캐시** — 초보자가 가장 많이 걸리는 함정을 이미 회피
- `bcrypt==4.0.1` 핀으로 passlib 호환 문제 대응
- 모든 계좌·주문 조회에 소유권 검증(`user_id` 필터)이 빠짐없이 적용됨
- Alembic 마이그레이션 3개를 실제 운영(테이블 rename, 타입 변경 포함)

### 🔴 치명적 결함 4건 (상세는 `11` 문서 C-1~C-4)
| # | 결함 | 결과 |
|---|---|---|
| C-1 | 주문 가격을 클라이언트가 지정 (`OrderRequest.price` 무검증) | 1원에 사서 시세로 팔면 **무한 수익** |

| C-3 | 매수 시 `balance`도 차감 → 주식 가치가 자산에 미반영 | **랭킹이 "투자 안 한 사람" 순** |
| C-4 | `with_for_update()` 없음 | 동시 주문 시 **예수금 초과 매수** |

- 체결(`trades`) 테이블 없음 + 전량 매도 시 포트폴리오 행 삭제 → **실현손익 계산 불가**
- 수수료·세금·장운영시간·호가단위·상하한가 검증 전무
- 뉴스 수집이 팀 설계문서(네이버 검색 API)와 다르게 HTML 직접 크롤링

저장소 이원화(루트 `backend/`가 빈 껍데기), requirements 두 벌(0.111 vs 0.137),
CORS `*`, `datetime.utcnow()` naive, 리프레시 토큰 없음, 테스트 0건,
학습·관심종목 도메인 없음, Render 무료 티어 콜드스타트(첫 요청 15초+)

## 4. 데이터베이스 상세 점검

### 현황: 12개 테이블 운영 중 (Alembic 리비전 3개)

`users` `account` `item_master` `orders` `portfolio` `price_history`
`posts` `comments` `post_likes` `follows` `user_survey_response` `ai_propensity_advice`

`Database/Table`(DBML 초안)의 설계가 대부분 실제 구현으로 옮겨졌습니다.
종목 시드(`item_master_seed.sql`, 코스피 30종목)도 준비되어 있습니다.

### 🟢 잘한 점
- ERD 초안 → SQLAlchemy 모델 → Alembic 마이그레이션으로 이어지는 흐름이 실제로 작동
- `security` → `item_master` 테이블 rename을 FK 재연결까지 포함해 정상 처리한 마이그레이션
- 커뮤니티 3종 + 팔로우 테이블이 이미 구현됨 (자기참조 관계 처리도 정확)

### 🔴 결손 (요구사항 대비)

| # | 결손 | 영향 |
|---|---|---|
| DB-1 | **체결(`trades`) 테이블 없음** | 실현손익·수수료·세금·거래내역 조회 불가 |
| DB-2 | **학습 시스템 테이블 전무** | 발표자료 핵심기능 D4 미구현. 용어 원고 60개가 있어도 담을 곳이 없음 |
| DB-3 | **관심종목(`favorites`) 테이블 없음** | `Favorites.jsx`와 대시보드 ♡가 붙을 곳이 없음 |
| DB-4 | **일별 자산 스냅샷 없음** | 수익률 추이 그래프·MDD·정상적인 랭킹 산출 불가 |
| DB-5 | 예수금 잠금(`locked_cash`) 없음 | 미체결 주문 개념이 성립하지 않음 |
| DB-6 | 세션/리프레시 토큰 테이블 없음 | 로그아웃·토큰 무효화 불가 |
| DB-7 | 알림 테이블 없음 | 체결·학습 추천 알림 불가 |

### 🟡 품질 문제

| # | 위치 | 문제 |
|---|---|---|
| DB-8 | `users.passwd` | bcrypt 해시가 들어가지만 **컬럼명이 평문을 암시**. `password_hash` 권장 |
| DB-9 | `account.balance` | 의미가 무너져 있음 (§3 C-3). 제거하거나 재정의 필요 |
| DB-10 | `orders` | `order_kind`(시장가/지정가), `filled_quantity`, `updated_at` 없음 |
| DB-11 | `portfolio` | `(account_id, symbol_code)` 유니크 제약 없음 → 중복 행 가능 |
| DB-12 | `price_history` | 유니크 제약·인덱스 없음. **현재 아무 데이터도 적재되지 않음** |
| DB-13 | `item_master` | `market`(KOSPI/KOSDAQ), `is_active` 없음 |
| DB-14 | 전역 | `DateTime`(naive) 사용 → `TIMESTAMPTZ` 권장 |
| DB-15 | 전역 | FK 외 인덱스가 거의 없음 |
| DB-16 | `ai_news_summary` | **DB 설계 문서엔 있으나 실제 모델·테이블이 없음** (뉴스가 저장되지 않음) |
| DB-17 | ERD 파일 | `Database/Table`이 실제 구현과 이미 어긋남. **실물 기준으로 갱신 필요** |

> 개선 스키마는 `04_DB_설계_리뷰_및_개선안.md`. 단, **전면 교체가 아니라 위 결손분만 증분 추가**하는
> 방식을 권합니다. 이미 동작하는 12개 테이블을 갈아엎을 시간은 없습니다.

### 현황: 그릇만 있고 내용물이 없음

| 기능 | 상태 |
|---|---|

| AI 종목 추천 / 코치 / 패턴 / 뉴스요약 | 🔴 외부 AI 서버(`localhost:8001`)로 프록시만 구현. **서버 자체가 없어 전부 503** |
| LLM 제공사·모델 선정 | 🔴 미정 |
| 설문 문항·선택지 실제 내용 | 🔴 미정 (프론트는 더미 텍스트, 백엔드는 문항을 DB로 관리하지 않음) |
| 학습 콘텐츠 | 🟡 **원고 60개가 Google Docs PDF에 이미 작성되어 있음** (활용 필요) |

### 🎉 중요한 발견
`gp-mock-inv/졸업작품 프로젝트 - Google Docs.pdf`에 **경제 용어 약 60개의 설명 원고가 이미
완성되어 있습니다.** (주식·증권시장·가격개념·PER/EPS/PBR/ROE·차트용어·매매방식·주문유형·
투자전략·우선주·공모주·해외주식·환율·세금)
새로 쓸 필요 없이 **DB 시드 SQL로 변환하는 작업**부터 하면 학습 시스템의 절반이 끝납니다.

### 구조에 대한 판단
AI를 별도 서버(`:8001`)로 분리한 설계는 **AI팀과 백엔드팀의 작업 분리에는 유리**하지만,
서버가 하나 더 늘어 배포·시연 리스크가 커집니다.
**권고: 별도 서버 대신 백엔드 안의 `services/ai/` 모듈로 통합**하고, AI팀은 그 모듈만 담당하세요.
분리가 꼭 필요하다면 AI 서버가 죽어도 화면이 죽지 않도록 **폴백 응답**을 반드시 넣으세요.
