## 4. 체결가를 서버가 결정 ★ 가장 중요 (1일)

### 문제
```python
# app/services/order_service.py — 현재
total_amount = req.price * req.quantity      # 프론트가 보낸 가격을 그대로 신뢰
```

Swagger에서 30초면 재현되는 취약점입니다.
```
① {"symbol_code":"005930","order_type":"매수","price":1,"quantity":10000}
   → 1만원으로 삼성전자 1만주 확보
② {"symbol_code":"005930","order_type":"매도","price":500000,"quantity":10000}
   → 50억원 입금
```

### 수정 방향
`req.price`는 **"지정가 희망값"으로만** 쓰고, 실제 체결가는 항상 서버 시세에서 파생시킵니다.

### 4-1. KIS 동기 조회 함수 추가

`routers/orders.py`의 `place_order`는 **동기 함수(`def`)** 인데
`kis_service.get_current_price`는 `async`입니다. 동기 버전이 필요합니다.

```python
# app/services/kis_service.py 에 추가

import httpx
from decimal import Decimal
from datetime import datetime, timedelta, timezone

_VERIFY = settings.APP_ENV != "local"          # 9번 항목과 함께 적용

def _now() -> datetime:
    return datetime.now(timezone.utc)

def get_kis_token_sync() -> str:
    """토큰 캐시를 async 버전과 공유하는 동기 조회."""
    tok = _token_cache.get("token")
    exp = _token_cache.get("expires_at")
    if tok and exp and _now() < exp:
        return tok
    with httpx.Client(verify=_VERIFY, timeout=5.0) as c:
        r = c.post(f"{KIS_BASE_URL}/oauth2/tokenP", json={
            "grant_type": "client_credentials",
            "appkey": settings.KIS_APP_KEY,
            "appsecret": settings.KIS_APP_SECRET,
        })
        r.raise_for_status()
        data = r.json()
    _token_cache["token"] = data["access_token"]
    _token_cache["expires_at"] = _now() + timedelta(hours=23)
    return data["access_token"]


def get_current_price_sync(symbol_code: str) -> dict:
    """주문 처리용 동기 시세 조회 (7번의 캐시를 경유)."""
    hit = _quote_cache.get(symbol_code)
    if hit and _now() - hit[1] < QUOTE_TTL:
        return hit[0]

    token = get_kis_token_sync()
    with httpx.Client(verify=_VERIFY, timeout=5.0) as c:
        r = c.get(
            f"{KIS_BASE_URL}/uapi/domestic-stock/v1/quotations/inquire-price",
            headers={"authorization": f"Bearer {token}",
                     "appkey": settings.KIS_APP_KEY,
                     "appsecret": settings.KIS_APP_SECRET,
                     "tr_id": "FHKST01010100", "custtype": "P"},
            params={"FID_COND_MRKT_DIV_CODE": "J", "FID_INPUT_ISCD": symbol_code},
        )
        r.raise_for_status()
        o = r.json().get("output", {})

    data = {
        "symbol_code": symbol_code,
        "current_price": int(o.get("stck_prpr", 0)),
        "prev_close":    int(o.get("stck_sdpr", 0)),     # 기준가 (신규 수집)
        "upper_limit":   int(o.get("stck_mxpr", 0)),     # 상한가 (신규 수집)
        "lower_limit":   int(o.get("stck_llam", 0)),     # 하한가 (신규 수집)
        "change_rate":   float(o.get("prdy_ctrt", 0)),
    }
    _quote_cache[symbol_code] = (data, _now())
    return data
```

> ⚠️ **주의**: 기존 `get_kis_token()`은 `datetime.utcnow()`(naive)를 씁니다.
> 위 코드는 `datetime.now(timezone.utc)`(aware)를 쓰므로, **둘을 섞으면 비교 시 TypeError가 납니다.**
> 기존 async 함수도 `_now()`를 쓰도록 함께 고치세요.

### 4-2. 주문 서비스 수정

```python
# app/services/order_service.py
def create_order(db: Session, req: OrderRequest, user_id: int) -> Order:
    # ① 계좌 (5번의 행 잠금 포함)
    account = (db.query(Account)
                 .filter(Account.account_id == req.account_id,
                         Account.user_id == user_id)
                 .with_for_update()
                 .first())
    if not account:
        raise HTTPException(404, "계좌를 찾을 수 없습니다.")

    # ② 종목
    stock = db.query(ItemMaster).filter(ItemMaster.symbol_code == req.symbol_code).first()
    if not stock:
        raise HTTPException(404, "종목을 찾을 수 없습니다.")

    # ③ ★ 체결가를 서버가 결정
    quote = kis_service.get_current_price_sync(req.symbol_code)
    market_price = Decimal(quote["current_price"])
    if market_price <= 0:
        raise HTTPException(503, "현재 시세를 가져올 수 없어 주문할 수 없습니다.")

    if req.order_kind == "시장가":
        fill_price = market_price
    else:
        if req.price is None:
            raise HTTPException(400, "지정가 주문은 가격을 입력해야 합니다.")
        _validate_price_limit(req.price, quote)
        # 1단계에서는 지정가도 즉시 체결하되, 사용자에게 유리한 쪽으로
        fill_price = (min(req.price, market_price) if req.order_type == "매수"
                      else max(req.price, market_price))

    total_amount = fill_price * req.quantity

    if req.order_type == "매수":
        _process_buy(db, account, req, fill_price, total_amount)
    else:
        _process_sell(db, account, req, fill_price, total_amount)

    order = Order(account_id=req.account_id, symbol_code=req.symbol_code,
                  order_type=req.order_type,
                  price=int(fill_price),          # ★ 실제 체결가를 기록
                  quantity=req.quantity, status="체결")
    db.add(order); db.commit(); db.refresh(order)
    return order


def _validate_price_limit(price: Decimal, quote: dict):
    upper = Decimal(quote.get("upper_limit") or 0)
    lower = Decimal(quote.get("lower_limit") or 0)
    if upper and not (lower <= price <= upper):
        raise HTTPException(422, f"주문 가격이 허용 범위를 벗어났어요. "
                                 f"({lower:,.0f}원 ~ {upper:,.0f}원)")
```

`_process_buy` / `_process_sell`의 시그니처도 `fill_price`를 받도록 바꾸고,
내부에서 `req.price` 대신 `fill_price`를 쓰도록 전부 교체하세요.

**검증**
1. `price: 1, quantity: 10000` 매수 → 시세로 계산되어 **잔고 부족 거부**
2. 정상 매수 후 `GET /api/trading/orders`의 `price`가 **실제 시세**와 일치

## 6. `balance` 정리 + 랭킹 수정 (1일)

### 문제
`models/account.py` 주석은 `balance = 현금 + 주식평가금액`이라 하지만,
`order_service`는 매수 시 **두 값을 똑같이 차감**합니다.

```python
account.withdrawable_cash -= total_amount
account.balance -= total_amount              # ← 이 줄이 원인
```
→ `balance == withdrawable_cash`가 항상 성립.
→ `ranking_service`가 이 값으로 수익률을 계산하므로 **주식을 살수록 수익률이 마이너스**.
→ 현재 랭킹은 **"누가 투자를 안 했나" 순위**입니다.

### 6-1. `balance`를 원금으로 고정

```python
# app/services/order_service.py
def _process_buy(...):
    account.withdrawable_cash -= total_amount
    # account.balance -= total_amount          ← ★ 삭제

def _process_sell(...):
    account.withdrawable_cash += total_amount
    # account.balance += total_amount          ← ★ 삭제
```
> 컬럼명은 그대로 두고 **의미만 "원금(seed)"으로 재정의**합니다. 개명은 나중에 해도 됩니다.
> 회원가입 시 `balance = 10_000_000`으로 세팅되므로 그대로 원금이 됩니다.

### 6-2. 총자산 계산 함수 신설

```python
# app/services/portfolio_service.py (신설)
def get_summary(db: Session, account: Account) -> dict:
    holdings = db.query(Portfolio).filter(Portfolio.account_id == account.account_id).all()
    stock_value = Decimal(0)
    for h in holdings:
        price = kis_service.get_current_price_sync(h.symbol_code)["current_price"]
        stock_value += Decimal(price) * h.hold_quantity

    cash        = Decimal(account.withdrawable_cash)
    seed        = Decimal(account.balance)           # 원금
    total_asset = cash + stock_value
    return {
        "cash": float(cash),
        "stock_value": float(stock_value),
        "total_asset": float(total_asset),
        "seed_cash": float(seed),
        "total_pnl": float(total_asset - seed),
        "total_pnl_rate": float((total_asset - seed) / seed * 100) if seed else 0.0,
    }
```
`GET /api/trading/portfolio` 응답에 이 값을 합쳐서 내려주세요.
(현재 `total_value = 평균단가 × 수량`은 **매입금액**이므로 필드명을 `buy_amount`로 바꾸고,
현재가 기준 `eval_amount` / `eval_pnl` / `eval_pnl_rate`를 추가)

### 6-3. 랭킹 수정

```python
# app/services/ranking_service.py
def get_profit_ranking(db: Session, limit: int = 20) -> list[dict]:
    # 보유 종목의 현재가를 한 번에 준비 (종목 수가 적고 캐시를 타므로 부담 없음)
    symbols = {r[0] for r in db.query(distinct(Portfolio.symbol_code)).all()}
    prices  = {s: kis_service.get_current_price_sync(s)["current_price"] for s in symbols}

    rows = []
    for user, account in db.query(User, Account).join(Account).all():
        holdings = db.query(Portfolio).filter(Portfolio.account_id == account.account_id).all()
        stock_value = sum(prices.get(h.symbol_code, 0) * h.hold_quantity for h in holdings)
        total = float(account.withdrawable_cash) + stock_value
        seed  = float(account.balance) or START_BALANCE
        rows.append({"user_id": user.user_id, "user_name": user.user_name,
                     "total_balance": total,
                     "profit_rate": round((total - seed) / seed * 100, 2)})

    rows.sort(key=lambda r: r["profit_rate"], reverse=True)
    for i, r in enumerate(rows[:limit], start=1):
        r["rank"] = i
    return rows[:limit]
```
> 종목마스터가 30종목이고 시세 캐시(7번)가 있으므로 KIS 호출은 최대 30건, 5초 캐시로 대부분 재사용됩니다.
> 사용자가 늘면 **일별 스냅샷 테이블**(`04` 문서 §4-2)로 옮기세요.

**검증**
1. 1,000만원으로 500만원어치 매수 → `total_asset`이 여전히 약 1,000만원 (수수료 제외)
2. 매수 후 랭킹에서 순위가 **떨어지지 않음**

## 7. KIS 시세 캐시 (반나절) — 4·6번의 전제

현재 `/api/stocks/{code}/price`는 요청마다 KIS를 직접 호출합니다.
프론트가 3초 폴링을 시작하면 즉시 유량 제한에 걸립니다.

```python
# app/services/kis_service.py 에 추가
_quote_cache: dict[str, tuple[dict, datetime]] = {}
QUOTE_TTL = timedelta(seconds=5)
```
async 버전 `get_current_price()`도 같은 캐시를 읽고 쓰도록 앞부분에 아래를 넣으세요.
```python
hit = _quote_cache.get(symbol_code)
if hit and _now() - hit[1] < QUOTE_TTL:
    return hit[0]
```
그리고 KIS 호출 성공 직후 `_quote_cache[symbol_code] = (data, _now())`.

**검증**: 같은 종목을 5회 연속 호출 → KIS 오류 로그/호출이 **1회만** 발생

## 9. `verify=False` 환경 분리 (1시간)

```python

```
1. 먼저 `pip install -U certifi` 로 해결되는지 확인
2. 안 되면 실전 도메인(`openapi.koreainvestment.com:9443`)으로 전환
3. 그래도 안 되면 **개발 환경에서만** 비활성화


## 12. `MARKET_MODE` 폴백 (1일)

**발표가 주말이나 장 마감 후면 시세가 전혀 움직이지 않습니다.**
KIS 장애·키 만료까지 겹치면 시연 자체가 불가능합니다.

```python
# app/services/market_provider.py (신설)
def get_price(symbol: str) -> dict:
    mode = settings.MARKET_MODE            # LIVE | REPLAY | MOCK
    if mode == "MOCK":
        return _mock_price(symbol)         # 마지막 종가 기준 난수 워크
    if mode == "REPLAY":
        return _replay_price(symbol)       # price_history 재생
    return kis_service.get_current_price_sync(symbol)
```
라우터·서비스가 이 함수만 호출하도록 바꾸면 **환경변수 하나로 전환**됩니다.

> 부수 효과: `MOCK` 모드가 있으면 **KIS 없이 체결 엔진 테스트**를 돌릴 수 있습니다.
