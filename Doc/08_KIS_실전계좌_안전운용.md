# 08. KIS 실전투자 계좌 API — 안전 운용 지침 (조회 전용 · 잔액 0원)

> **팀 결정사항**: 본 프로젝트는 한국투자증권 **실전투자 계좌**로 발급한 API 키를 사용한다.
> 단, **시세·순위 조회 용도로만** 사용하며, 해당 계좌는 **잔액을 0원으로 유지**한다.
> 작성 2026-08-25 · 관련 문서: `07_KIS_API_연동.md`(§2 도메인 선택), `02_시스템_아키텍처.md`

---

## 1. 왜 실전 계좌를 쓰는가

| 이유 | 설명 |
|---|---|
| 순위분석 TR이 모의에서 막힘 | 거래량순위(`FHPST01710000`) 등 **순위분석 API는 실전 전용**. 대시보드 인기 랭킹을 만들려면 선택지가 없다 |
| 유량 제한이 여유로움 | 실전 초당 20건 / 모의 초당 2건 (참고값, 공식 문서 확인 필요). 모의로는 폴링 개발 자체가 어렵다 |
| 지원 TR이 많음 | 지수·호가·기간별 차트 등 앞으로 붙일 TR이 모의 도메인에 없을 수 있다 |
| 주문은 자체 구현 | 본 프로젝트는 체결 엔진을 직접 만든다(`09_모의체결엔진_설계.md`). KIS 주문 API를 쓸 이유가 처음부터 없다 |

```ini
# .env
KIS_BASE_URL=https://openapi.koreainvestment.com:9443   # 실전 도메인
```

## 2. 위험의 정확한 위치

**착각하기 쉬운 점: "조회만 하니까 키도 조회용"이 아니다.**

KIS는 조회 전용 키를 따로 발급하는 기능이 없다. 우리가 쓰는 실전 앱키는
**주문 API를 호출할 수 있는 자격증명**이며, 안전한 이유는 API가 막아줘서가 아니라
**① 우리가 주문 코드를 짜지 않아서 ② 키가 유출되지 않아서 ③ 계좌에 돈이 없어서**다.
이 3가지가 우리가 관리해야 할 전부다.

| 구분 | 계좌 영향 | 판정 |
|---|---|---|
| `quotations/*` (현재가·호가·차트·순위) | 없음 (읽기 전용) | ✅ 안전. 몇 만 번 호출해도 무관 |
| 잔고·체결내역 조회 | 없음 (읽기 전용) | ✅ 안전. 단 우리는 쓰지 않음 |
| `trading/order-cash` 등 주문 TR | **실제 체결. 확인 절차 없음** | 🔴 **사용 금지** |
| 앱키+계좌번호 유출 | 제3자가 내 계좌로 주문 가능 | 🔴 최대 리스크 |

> ⚠️ 반복문 안에 주문 호출이 잘못 들어가면 수십 건이 순식간에 나간다. 확인 팝업 같은 건 없다.
> 그래서 §4의 코드 가드와 §5의 잔액 0원 정책을 **둘 다** 건다.

## 3. 잔액 0원 운용 규칙

계좌에 돈이 없으면, 최악의 경우(키 유출 + 주문 시도)에도 **주문이 증거금 부족으로 거부**된다.
이것이 우리의 마지막 방어선이므로 다음을 지킨다.

- [ ] **예수금 0원 유지** — 개발용으로 쓸 계좌에서 잔액 전액 출금
- [ ] **보유 종목 0** — 주식이 남아 있으면 매도 주문이 가능하다. 잔고를 비운다
- [ ] **연계 은행계좌 자동이체·즉시입금 한도 해제** — 잔액이 0이어도 즉시입금이 열려 있으면 의미가 반감된다
- [ ] **미수/신용 거래 미신청** — 예수금 0원이어도 미수 한도가 있으면 주문이 나갈 수 있다. **가장 중요**
- [ ] **가급적 이 프로젝트 전용 계좌를 신규 개설** — 본인의 실제 투자 계좌와 분리한다
- [ ] 잔액이 0인지 **월 1회 확인** (배당금·이자 등으로 잔액이 생길 수 있음)

> 💡 미수 한도 확인: KIS 홈페이지/MTS → 계좌관리 → 미수·신용 약정 여부.
> 약정이 되어 있으면 예수금 0원이어도 매수가 가능하다. 반드시 해지할 것.

## 4. 코드 레벨 안전장치

### 4-1. 주문 TR 차단 (필수 구현)

`kis_service.py`의 공통 요청 함수에 화이트리스트를 건다. 실수로 주문 TR을 넣어도 **런타임에서 막힌다**.

```python
# app/services/kis_service.py
ALLOWED_TR_PREFIX = ("FHK", "FHP", "HHD", "CTP")   # 조회 계열만 허용

def _assert_read_only(tr_id: str) -> None:
    """주문/계좌 TR 사용을 코드 레벨에서 차단한다.

    본 프로젝트는 시세 조회 전용이며, 실전 계좌 키를 사용하므로
    주문 TR이 실행되면 실제 체결로 이어진다. (본 문서 §3 참조)
    """
    if not tr_id.startswith(ALLOWED_TR_PREFIX):
        raise RuntimeError(f"주문/계좌 TR은 사용 금지: {tr_id}")
```

- 주문 TR은 `TTTC`(실전) / `VTTC`(모의) 접두사를 쓴다 → 화이트리스트에 걸려 전부 차단된다.
- 이 함수는 **토큰 발급을 제외한 모든 KIS 호출 직전**에 호출한다.

### 4-2. 엔드포인트 경로 차단 (이중 방어)

```python
FORBIDDEN_PATH = ("/trading/", "/order", "/inquire-balance")

if any(p in path for p in FORBIDDEN_PATH):
    raise RuntimeError(f"거래 관련 엔드포인트 호출 금지: {path}")
```

### 4-3. 계좌번호를 코드에서 제거

주문에 필요한 것은 `앱키 + 시크릿 + 계좌번호` 세트다. 시세 조회에는 **계좌번호가 필요 없다.**
계좌번호를 저장하지 않는 것만으로 유출 시 주문 난이도가 크게 올라간다.

```diff
# gp-mock-inv/backend/.env.example
  KIS_APP_KEY=your-kis-app-key
  KIS_APP_SECRET=your-kis-app-secret
- KIS_ACCOUNT_NO=your-account-no
```
```diff
# app/config.py
  KIS_APP_KEY: str = ""
  KIS_APP_SECRET: str = ""
- KIS_ACCOUNT_NO: str = ""
```
> 🔴 현행 `.env.example`과 `config.py`에 `KIS_ACCOUNT_NO`가 남아 있다. **삭제 대상.**

### 4-4. 호출은 반드시 백엔드에서

프론트(React)에서 KIS를 직접 호출하면 **앱키가 브라우저 번들과 네트워크 탭에 그대로 노출**된다.
프론트는 우리 백엔드(`/api/stocks/...`)만 호출하고, KIS 통신은 FastAPI가 전담한다.
`frontend/.env`에 KIS 키를 넣지 않는다(Vite의 `VITE_` 변수는 전부 공개된다).

## 5. 키 관리 규칙

1. `.env`는 커밋하지 않는다. 루트 `.gitignore`에 `.env` 계열이 등록되어 있다 ✅ (2026-08-26 확인)
   ```gitignore
   .env
   .env.local
   **/.env
   ```
2. 키를 단톡방·이슈·PR 본문에 붙여넣지 않는다. 전달은 1:1 또는 학교 계정 메일로.
3. **실수로 커밋했다면 → 히스토리 삭제보다 포털에서 키 재발급이 먼저다.** 이미 push 되었다면 유출로 간주한다.
4. Render 환경변수와 로컬 `.env`의 키를 동일하게 유지한다.
5. TLS 검증(`verify=False`)을 끄면 **이 경로로 앱키와 시크릿이 평문에 가깝게 흐른다**. `07_KIS_API_연동.md` §6 순서대로 해결할 것.

### 유출 의심 시 대응 순서
```text
1. apiportal.koreainvestment.com → 앱키 즉시 폐기 및 재발급
2. 계좌 잔액·보유종목·미수한도 0 확인
3. HTS/MTS 거래내역에서 이상 주문 확인
4. Render 환경변수 갱신 → 재배포
5. git 히스토리 정리(git filter-repo) — 3번까지 끝낸 뒤에 해도 된다
```

## 6. 증권사 설정 레벨 안전장치 (권장)

코드 밖에서 거는 방어선. 개발 기간 내내 유지한다.

| 설정 | 위치 | 효과 |
|---|---|---|
| 온라인 거래한도 최소로 하향 | KIS 홈페이지 → 계좌관리 | 사고 시 손실 상한이 생긴다 |
| 미수·신용 약정 해지 | 계좌관리 | 예수금 0원 방어선이 실제로 작동한다 |
| 해외주식·파생 미신청 | 계좌관리 | 공격 표면 축소 |
| 출금계좌 지정 | 계좌관리 | 임의 출금 방지 |

## 7. 발표/시연 시 설명 문구

심사에서 "실전 계좌를 썼는데 위험하지 않은가"라는 질문이 나올 수 있다. 다음과 같이 답한다.

> "KIS Open API는 **시세·순위 조회 용도로만** 사용합니다. 계좌·주문·체결·잔고는 전부 자체 구현했고,
> KIS의 주문 TR은 코드 레벨 화이트리스트로 차단되어 있습니다. 순위분석 API가 실전 계좌에서만
> 제공되기 때문에 실전 도메인을 사용하며, 해당 계좌는 **예수금 0원·미수 미약정 상태**로 유지합니다."

## 9. 요약

```text
안전의 근거 = KIS가 막아준다  ❌
             우리가 주문 코드를 안 짠다 + 키가 안 샌다 + 계좌에 돈이 없다  ✅
```

세 겹 중 하나라도 무너지면 나머지 두 겹이 막는다. **셋 다 유지하는 것이 이 문서의 목적이다.**
