## 2. 판단이 필요했던 지점과 근거

가이드에 답이 없거나 선택지가 여럿이던 지점입니다. **모두 되돌리기 쉬운 방향**으로 정했습니다.

### 2-1. 🔓 로그인 없이 모든 화면을 볼 수 있게 했다

**요구사항**이자 이번 작업에서 가장 구조에 영향을 준 결정입니다.

**왜**
1. 아직 백엔드를 붙이지 않아 **로그인 자체가 불가능**합니다. 이 상태에서 라우트를 막으면
   개발·시연 중에 첫 화면 밖으로 나갈 수 없습니다.
2. 백엔드를 붙인 뒤에도 `GET /api/stocks` 계열의 인증을 해제해
   "로그인 없이 둘러보기"를 계속 지원할 계획입니다. (Doc/13 §7 요청 3번)

**어떻게 — 라우트를 지우지 않고 플래그 하나로 껐습니다**

```js
// src/config/features.js
export const REQUIRE_AUTH = false;
```

```jsx
// src/components/routing/ProtectedRoute.jsx
if (!REQUIRE_AUTH) return content;   // 아무도 막지 않고 그대로 통과
```

`App.jsx` 의 라우트는 **여전히 `<ProtectedRoute>` 로 감싸 둔 상태**입니다.
나중에 보호가 필요해지면 `features.js` 의 값 하나만 `true` 로 바꾸면 되고,
다른 파일은 손대지 않아도 됩니다.

**개인 데이터 자리는 어떻게 처리했나**

로그인하지 않으면 `user` 와 `account` 가 `null` 입니다. 이때 빈칸이나 무한 스켈레톤을
남겨 두면 "고장난 화면"으로 보이므로, 새로 만든 `LoginNotice` 컴포넌트로 이유를 설명합니다.

| 화면 | 비로그인 상태 |
|---|---|
| 대시보드 | 화면 전체가 보임. 금액 카드에 "로그인하면 표시돼요", 상단에 "지금은 둘러보기 모드예요" |
| 내 자산 | 구조·용어 설명 모두 보임. 금액 자리에만 안내 |
| 트레이딩 | 전부 보임 (원래 로그인과 무관한 화면) |
| 관심종목 | **완전히 동작** (localStorage 기반) |
| 설문 | **완전히 동작** — 결과까지 나옴 (localStorage 저장) |
| 용어사전 | **완전히 동작** |
| 커뮤니티 | 전부 보임 (아직 연동 전) |
| 내 정보 | 개인정보뿐이라 채울 내용이 없어 로그인 안내만 표시 |

> ⚠️ 이것은 **화면 접근 제어일 뿐 보안 장치가 아닙니다.** 실제 데이터 보호는
> 서버가 토큰을 검사하는 것으로만 이뤄집니다. 프론트에서 라우트를 막든 안 막든
> 서버가 인증을 요구하면 데이터는 오지 않습니다.

### 2-2. 하드코딩된 가짜 데이터를 전부 제거했다

기존 화면에는 API가 없는 자리를 채우려고 넣은 숫자들이 있었습니다.

| 위치 | 가짜 값 | 처리 |
|---|---|---|
| `Dashboard` 헤더·카드 | 코스피 `8,096.93 / +612.52(8.1%)` | 제거 (지수 API 없음) |
| `Dashboard` 랭킹 3열 | 목업 5줄이 3열에 그대로 반복 | 제거 (해당 랭킹 API 없음) |
| `Dashboard` 뉴스·커뮤니티 | 기사 2건·게시글 3건 | 제거 |
| `Assets` | 총자산 `22,616,925원`, 내 투자 `12,616,925원` | 제거 |
| `Assets` | **달러 `$5,000` 카드** | 제거 — 이 서비스에 외화 계좌 개념 자체가 없음 |
| `Survey` | 1번 문항 1번 선택지가 항상 체크된 것처럼 보이는 처리 | 제거 |

**근거.** 시안을 채우기 위한 값이지만 시연 중에 실제 데이터로 오해될 위험이 큽니다.
특히 코스피 지수와 자산 총액은 "동작하는 것처럼 보이는" 대표적인 항목입니다.
빈자리는 `EmptyState` / "연동 예정" 표시로 대체해 **무엇이 아직 없는지가 화면에서 드러나도록** 했습니다.

> 되돌리기: 각 자리에 `TODO(F-1x)` 주석이 있어 연동 시 그 자리에 코드를 넣으면 됩니다.

### 2-3. 대시보드를 Doc/13 §6 권장 구성으로 바꿨다

시안(지수 카드 4개 + 거래대금·급상승·급하락 랭킹)은 **지원 API가 하나도 없습니다.**
가이드 §6이 제안한 구성으로 교체했습니다.

```text
상단 카드 4개 : 예수금 · 주문가능금액 (로그인 시 동작) │ 평가손익 · 내 랭킹 (연동 대기)
3열          : 보유종목(F-14) │ 관심종목(로그인 없이 동작) │ 수익률 랭킹(F-18)
뉴스(F-16) · 커뮤니티(F-17)
```

- **예수금·주문가능금액이 바로 동작하는 이유**: `AuthContext`가 로그인 직후 `/trading/accounts`를
  받아 두므로 추가 호출 없이 표시됩니다.
- **"내 랭킹" 카드를 비워 둔 이유**: 백엔드 랭킹 계산식 버그로 *투자를 안 한 사람*이 상위에 옵니다(§6).
  숫자를 띄우면 오히려 신뢰를 잃으므로 계산식 수정 전까지 비워 둡니다.

### 2-4. 헤더에서 지수 표시를 빼고, 검색창은 남기되 비활성화했다

- **지수**: 위 2-2와 같은 이유로 제거.
- **검색창**: `GET /api/stocks` 연동(F-12) 전까지 눌러도 갈 곳이 없습니다.
  아예 없애면 F-12 때 헤더 레이아웃이 다시 흔들리므로, **자리는 유지하고 `disabled` + "(준비 중)"** 로 표시했습니다.

### 2-5. Landing 의 진입 버튼을 3개로 나눴다

기존 "먼저 둘러보기"는 설문(`/survey`)으로 가고, "가입"은 존재하지 않는 `/register`를 가리켰습니다.
로그인 없이 전체 열람이 가능해졌으므로 목적지를 정리했습니다.

| 버튼 | 목적지 | 의도 |
|---|---|---|
| **둘러보기** (주 버튼) | `/dashboard` | 이제 막히지 않으므로 바로 본 화면으로 |
| 가입하고 시작하기 | `/signup` | 가입 유도 |
| 투자 용어사전 66개 보기 | `/learn` | 지금 **가장 완성도 높은 화면**을 첫 화면에서 노출 |

"로그인하지 않아도 모든 화면을 둘러볼 수 있어요" 문구도 함께 넣어 기대를 맞췄습니다.

### 2-6. `/learn` 용어사전 페이지를 새로 만들었다 (가이드에 없던 항목)

헤더 네비의 **"학습" 메뉴가 갈 곳이 없었습니다.** (`learn` API가 없어 화면 자체가 없음)
용어집이 이미 로컬 데이터이므로 **백엔드도 로그인도 없이 100% 동작하는 유일한 화면**입니다.
검색 + 카테고리 필터 + 연관용어 탐색을 붙였습니다. 개념 설명·퀴즈는 `learn` API 이후로 미룹니다.

### 2-7. `src/api/axios.js`를 삭제하지 않고 재수출 shim으로 남겼다

기존 `Login.jsx`가 `import api from '../api/axios'`로 이 파일을 쓰고 있었고,
다른 팀원 코드에도 같은 import가 있을 수 있습니다. 파일을 지우면 그쪽이 깨집니다.

```js
// src/api/axios.js — @deprecated
export { default, API_BASE_URL, ... } from './client';
```

하드코딩된 `baseURL: 'http://localhost:8000'`만 제거했습니다. **다음 정리 시점에 삭제 대상**입니다.

### 2-8. `lightweight-charts` · `recharts`를 설치하지 않았다

가이드 §2-3이 지금 설치하라고 하지만, **쓰는 코드가 F-14/F-15에 있습니다.**
지금 넣으면 미사용 의존성이 번들 관리·보안 감사 대상으로만 남습니다. 해당 작업 시작 시 설치하세요.

### 2-9. 용어집 원고를 PDF에서 옮기지 않고 새로 작성했다

가이드는 `gp-mock-inv/졸업작품 프로젝트 - Google Docs.pdf`의 용어 60개를 옮기라고 안내합니다.
이번 작업은 **`gp-mock-inv`를 없는 것으로 간주**하는 전제라 참조하지 않고 66개를 새로 작성했습니다.

> **⚠️ 후속 조치 필요**: 원고가 존재하므로, 팀 원고와 대조해
> ① 문구 톤 통일 ② 원고에만 있는 용어 추가 ③ 중복 정리가 필요합니다.
> 데이터 구조(`{ term, category, desc, example, related }`)는 그대로 두고 값만 교체하면 됩니다.

### 2-10. 설문 배점을 자체 설계했다

가이드 §5-4는 구조만 예시로 주고 실제 문항·배점은 비워 두었습니다.
기존 `Survey.jsx`의 6문항을 그대로 쓰되 **선택지 4개 × 0/5/10/15점 = 총 0~90점**으로 정하고,
가이드가 제시한 경계값(20/40/60/80)을 그대로 적용했습니다.

> **⚠️ AI 담당자와 합의 필요.** 서버에서 같은 계산을 하게 되면 `calcStyle()`을 지우고 API 결과를 쓰면 됩니다.
> 현재 결과는 **localStorage에만 저장**되며, 화면에도 "임시 결과"임을 명시했습니다.

### 2-11. 콜드스타트 감지 로직을 가이드 예제와 다르게 구현했다

가이드 §4-2 예제는 모듈 전역 타이머 변수 하나를 씁니다.

```js
let wakeTimer;   // 요청이 동시에 여러 개 나가면 나중 요청이 앞 타이머를 덮어씀
```

요청이 병렬로 나가면 **먼저 끝난 요청이 아직 진행 중인 요청의 안내를 지웁니다.**
`api/client.js`는 **진행 중인 요청 수를 세어**, 하나라도 남아 있으면 안내를 유지합니다.

### 2-12. `Trading` 좌측 패널을 관심종목으로 채웠다

호가 API가 없어 좌측이 회색 박스였습니다. 가이드 §1도 "좌측을 다른 것으로" 대체하라고 안내합니다.
**로그인 없이도 동작하는** 관심종목(localStorage) 목록을 넣었습니다. 호가 API가 생기면 이 자리를 교체하면 됩니다.

### 2-13. 접근성·품질 관련 소소한 결정

| 결정 | 근거 |
|---|---|
| `:root { color-scheme: light }` | 기존 코드가 브라우저 다크모드 때문에 요소마다 `bg-white text-black`을 강제 지정하고 있었음. 한 줄로 대체 |
| 등락 표시에 `▲▼` 기호 병기 (`rateWithMark`) | 색상만으로 구분하면 색약 사용자가 읽을 수 없음 (Doc/13 §10) |
| `AuthContext`를 `auth-context.js` / `AuthContext.jsx` / `useAuth.js` 3개로 분리 | 한 파일에서 컴포넌트와 훅·상수를 함께 export 하면 Vite Fast Refresh가 전체 리로드로 떨어짐 (lint 규칙 `react-refresh/only-export-components`) |
| `refresh()`가 첫 줄부터 `await`로 시작 | 이펙트 본문에서 setState를 동기 호출하면 연쇄 렌더 발생 (lint 규칙 `react-hooks/set-state-in-effect`) |
| 페이지 최대 폭을 `max-w-page`(1400px) 토큰으로 통일 | 기존에는 화면마다 1200 / 1400 / 제한없음이 섞여 있었음 |
| `EMPTY_MESSAGES` · `NAV_ITEMS`를 `constants/`로 분리 | 위와 같은 Fast Refresh 이유 |

## 6. F-10 배포 — 남은 절차

설정 파일은 넣었지만 **실제 배포는 수행하지 않았습니다.** (계정 연결·인증이 필요)

**Vercel**
1. Vercel에서 저장소 연결 → **Root Directory 를 `frontend` 로 지정**
2. Environment Variables 에 `VITE_API_BASE_URL = https://gp-mock-inv.onrender.com/api` 추가
3. Deploy — `vercel.json`의 rewrite가 SPA 새로고침 404를 막아 줍니다

**Netlify**
1. 저장소 연결 (`netlify.toml`의 `base = "frontend"`가 이미 지정됨)
2. Site settings → Environment variables 에 `VITE_API_BASE_URL` 추가
3. Deploy

> 🔴 **환경변수를 빠뜨리면** `client.js`의 폴백인 `http://localhost:8000/api`로 요청이 나가
> 배포본에서 모든 API가 실패합니다. 배포 후 네트워크 탭에서 요청 주소를 반드시 확인하세요.

## 7. 다음 작업자를 위한 메모

### 7-1. 로그인 보호를 다시 켜려면

```js
// src/config/features.js — 이 한 줄만 바꾸면 됩니다
export const REQUIRE_AUTH = true;
```

`App.jsx` 의 라우트는 이미 `<ProtectedRoute>` 로 감싸져 있어 다른 파일은 수정 불필요합니다.
켜면 비로그인 사용자는 `/login` 으로 이동하고, 로그인 후 원래 가려던 화면으로 돌아옵니다
(`state.from` 으로 전달됨).

### 7-2. 새 화면을 만들 때

```jsx
import useAuth from '../hooks/useAuth';
import api from '../api/client';
import { num, won, rateWithMark, signTextClass } from '../utils/format';
import { SkeletonList } from '../components/common/Skeleton';
import EmptyState from '../components/common/EmptyState';
import { EMPTY_MESSAGES } from '../constants/emptyMessages';
import ErrorState from '../components/common/ErrorState';
import LoginNotice from '../components/common/LoginNotice';
import HelpIcon from '../components/learn/HelpIcon';
```

- **금액은 반드시 `num()`을 거칩니다.** API마다 문자열/숫자가 섞여 옵니다 (§4-1).
- **상태 4종을 모두 처리합니다**: 로딩(Skeleton) / 오류(ErrorState) / 빈 데이터(EmptyState) /
  **비로그인(LoginNotice)**. 마지막 것을 빠뜨리면 둘러보기 모드에서 무한 스켈레톤이 남습니다.
- **어려운 용어 옆에는 `<HelpIcon termId="..." />`** — 현재 66개 등록.
- 오류 메시지는 `error.userMessage`에 이미 담겨 있습니다 (`client.js`가 FastAPI `detail`을 꺼내 둠).

### 7-3. 주문 폼(F-13)을 만들 때 반드시 지킬 것

백엔드가 클라이언트가 보낸 가격을 그대로 신뢰합니다. **입력 단계 방어가 현재 유일한 안전장치**입니다.

```js
import { validateOrderPrice, tickSize, priceBounds } from '../utils/tickSize';

const err = validateOrderPrice(price, currentPrice);   // 문제 없으면 null
if (err) return setPriceError(err);
```

- 시장가는 가격 입력을 막고 현재가를 그대로 전송
- `order_type`은 **한글** `"매수"` / `"매도"`
- `current_price === 0`이면 KIS 키 문제이므로 **"시세를 불러올 수 없음"** 으로 처리 (§3-3)

### 7-4. 백엔드 담당자에게 전달할 요청

Doc/13 §7 목록 그대로입니다. 이번 작업으로 **우선순위가 바뀐 항목**만 표시합니다.

| 순위 | 요청 | 이번 작업에서 확인된 영향 |
|:--:|---|---|
| 1 | 주문 시 서버가 시세로 체결가 결정 | 프론트 검증만으로는 우회 가능 — 근본 해결 불가 |
| 2 | **랭킹 계산식 수정** | 대시보드 "내 랭킹" 카드와 랭킹 3열을 **비워 둔 직접 원인** |
| **3 ↑** | **`GET /api/stocks` 인증 해제** | **프론트는 이미 로그인 없이 열리도록 만들었습니다. 서버가 인증을 요구하는 한 둘러보기 화면에 시세가 들어가지 않습니다** |
| 4 | `GET /api/trading/portfolio/summary` | 총자산·평가손익을 프론트가 N+1 호출로 계산해야 함 |
| 7 | 지수 · 거래대금/등락률 랭킹 API | 대시보드 상단이 시안과 달라진 원인 |
| 9 | 금액 필드 타입 통일 | `num()` 유틸로 방어 중이나 매번 감싸야 함 |
