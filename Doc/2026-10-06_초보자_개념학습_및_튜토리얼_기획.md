# Stockmaster 초보자 개념 학습과 튜토리얼 기획

작성·코드 확인일: 2026년 10월 6일 · 기획 버전 1.0 · 대상: 주식 투자 경험이 없거나 적은 성인 · 상태: 구현 전 기획

## 1 기획 결론과 적용 범위

학습은 **짧은 개념 설명 → 실제 사이트 화면에서 안내받으며 연습 → 안내 없이 다른 사례 해결 → 결과를 말로 설명 → 나중에 다시 확인**하는 순서로 구성한다. 모든 거래 체험은 회원 계정과 분리된 가상 환경에서 진행한다. 학습을 끝내기 위해 계좌를 만들거나 계정에 연결된 모의주문을 할 필요가 없어야 한다.

여기서 ‘실전 체험’은 실제 돈을 투자한다는 뜻이 아니다. **사이트에 실제 존재하는 주문·조회 인터페이스를, 실제 계정 정보 없이 사용하는 실습**을 뜻한다. 이용자에게는 오해가 적은 ‘가상 실습’과 ‘혼자 해보기’라는 이름을 사용한다. 기존 Stockmaster의 계정형 모의투자도 학습용 세션과 별개로 취급한다.

이번 기획의 우선순위는 다음과 같다.

1. 현금·주식·주문·손익을 이해하는 초보자 공통과정을 먼저 제공한다.
2. 현재 튜토리얼과 일반 화면 사이의 비용·주문 상태 차이, 계정 정보 분리 범위를 먼저 보완한다.
3. 인버스·레버리지·미수·신용·선물·옵션은 위험을 알아보는 선택 과정으로 둔다. 배우는 목적은 고위험 거래를 시작시키는 것이 아니다.
4. 사이트에 없는 기능은 개념 설명만 공개할 수 있다. 해당 기능과 독립된 가상 실행 모델을 먼저 구현·검증한 뒤 튜토리얼을 연결한다.
5. 콘텐츠의 교육적 타당성은 근거와 설계표로 검토하고, 실제 효과는 초보자 사용자 연구로 확인한다. 지금 단계에서 ‘학습 효과 검증 완료’라고 주장하지 않는다.

이 문서는 교육과정, 화면 연계, 데이터 분리, 선행 개발, 효과 검증 및 공개 기준을 다룬다. 서비스 코드 수정·배포는 이번 문서화에 포함하지 않았다. 기존 코드에 진행 중인 다른 변경은 그대로 보존한다.

기초 조사: [고위험 금융투자 조사 보고서](./자료조사/2026-10-06_고위험금융투자_조사.html). 금융 개념·법규의 상세 근거는 해당 보고서의 33개 출처를 함께 사용한다.

## 2 확인한 현재 사이트와 차이

아래는 로컬 작업트리의 코드·문서 검토 결과다. 운영 사이트에서의 배포·정상 동작을 확인한 목록은 아니다. 과거 구현기록보다 현재 소스의 동작을 우선했다.

| 영역 | 현재 확인한 내용 | 기획에 미치는 영향 |
|---|---|---|
| 학습 허브 `/learn` | 기본 투자 가이드, 투자 기초 과정, 투자 비중, 정보 해석, 용어집 | 새 메뉴를 대량 추가하지 않고 권장 경로와 기존 학습을 연결 |
| 실제 화면 튜토리얼 | `/trading?practice=buy` 등에서 `Trading`·`Assets` 재사용. `buy`, `sell`, `orders`, `account`, `settlement`, `review` 6개 | 화면을 재사용하는 기존 구조를 기본으로 채택 |
| 현재 연습 거래 | 예시전자 한 종목, 가격 50,000원 고정, 두 예시 계좌, 현금 매수·매도, 비용 제외 | 가격 변화·비용·다양한 주문 상태 학습은 추가 구현 전 실행 불가 |
| 일반 주문 화면 | 시장가·지정가, 비용 표시, 주문내역, 대기 주문 취소 코드 존재 | 연습에는 가격 종류 선택과 취소가 숨겨져 있어 그대로 재사용 불가 |
| 지정가 동작 | 대기로 접수되지만 자동 체결하지 않고 자금·보유량을 예약하지 않는다고 명시 | ‘가격이 닿으면 체결’하는 사이트 기능으로 가르치면 안 됨 |
| 예약·조건 주문 | 일반 화면의 `AutomationOrders` 및 별도 서버 기능 코드 존재. 연습 중에는 숨김 | 기능은 있으나 격리된 체험용 실행 모델이 없어 튜토리얼은 아직 불가 |
| 비용 | 일반 화면에 모의 수수료 0.015%, 매도 거래세 0.18%, 원 단위 반올림. 연습은 비용 0 | 이 수치는 **현재 사이트 설정**이다. 현행 국내 세율 또는 업계 공통 요율로 가르치지 않음 |
| 기존 기초 과정 | A~E, 15개 차시와 별도 개념 실습·문제 존재 | 주제와 해설을 재사용하되 독립 문제 화면을 ‘실제 사이트 기능 튜토리얼’이라고 부르지 않음 |
| 과정 완료 | 확인 문제에 답했는지로 완료 가능. 정답·독립 수행을 모두 요구하지 않음 | ‘읽음·조작 완료·이해 확인’을 나눠야 함 |
| 연습 계좌 분리 | `SitePractice` 본문 컨텍스트와 메모리 주문 엔진. `useSiteResource`가 연습 데이터 사용 | 유용한 기반이나 앱 전체의 계정 비연결을 증명하지는 않음 |
| 전역 계정 | 앱 바깥쪽 `AuthProvider`가 저장 토큰으로 사용자·계좌를 복구. 헤더는 연습 컨텍스트 바깥 | 저장된 토큰이 있는 직접 진입 시 계정 조회 가능성이 남음. 엄격한 분리 기준 충족 전 구조 보완 |
| 학습 기록 | `learningScope`가 사용자·계좌 ID로 구분한 브라우저 저장 지원 | 신규 과정에는 해당 범위를 그대로 재사용하지 않음 |
| 미수·신용·공매도·ETP·선물·옵션 | 거래 튜토리얼 미제공 목록에 존재. 전용 주문·자산 모델 확인되지 않음 | 위험 개념은 먼저 공개 가능, 전용 체험은 기능 선행 구현 후 공개 |

### 2.1 우선 정리해야 할 내용 불일치

- `tradingTutorials.js`의 ‘사이트는 수수료·세금 제외’, ‘즉시 체결 방식’ 같은 문장은 연습 모델에만 맞고 현재 일반 화면 전체를 설명하지 못한다. ‘이번 기초 연습에서는…’으로 범위를 좁히거나 모델을 통일한다.
- 기존 주문 튜토리얼의 ‘미체결 취소 기능 없음’과 일반 화면의 대기 주문 취소가 충돌한다. **전송 전 취소와 접수된 대기 주문 취소**를 별도로 설명한다.
- 현재 연습은 고정 가격이므로 가격 변화에 따른 손익 이해를 조작 완료만으로 확인할 수 없다.
- `CourseLessons`의 마지막 `/trading` 링크는 계정형 일반 모의투자로 이어질 수 있다. 신규 공통과정의 다음 버튼은 가상 실습 경로로 연결한다.
- 이전 비용 구현·롤백 문서에는 현재 코드와 다른 요율·반올림 방식이 있다. 교재는 화면과 동일한 버전의 정책을 읽고, 과거 문서 숫자를 복사하지 않는다.

## 3 초보자를 위한 학습 목표와 표현 원칙

수료한 학습자는 ‘어떤 종목을 사야 하는지’보다 다음을 설명할 수 있어야 한다.

- 주문할 종목·계좌·수량·예상 비용을 확인하고, 주문을 보내기 전과 후를 구별한다.
- 현금·보유수량·총자산·평가손익·실현손익을 구분한다.
- 예상가격과 체결가격, 접수와 체결, 체결과 결제가 같지 않음을 설명한다.
- 자신이 넣은 돈을 잃는 경우와 추가로 갚아야 할 돈이 생기는 경우를 구분한다.
- 높은 수익 가능성 설명에서 비용·기간·손실·추가 납입·청산 조건을 찾아본다.
- 이해하지 못한 상품은 체험을 중단하거나 거래하지 않겠다고 판단할 수 있다.

### 3.1 설명 문체

한 화면에서 새 용어는 2개 이내를 목표로 한다. 일상어를 먼저 쓰고 전문용어를 뒤에 붙인다. 수식은 처음부터 보여주지 않고 원 단위 예시 → 변화 표 → 필요한 경우 식 순으로 설명한다. 본문 권장 분량은 개념 카드당 2~4문장이고, 한 차시 8~12분은 설계 목표이며 파일럿에서 조정한다.

| 용어 | 처음 보여줄 설명 |
|---|---|
| 매수·매도 | 주식을 사기·보유한 주식을 팔기 |
| 평가손익 | 아직 갖고 있는 주식을 현재 가격으로 계산했을 때의 이익·손실 |
| 체결 | 사려는 주문과 팔려는 주문이 맞아 거래가 이루어진 상태 |
| 결제 | 거래 후 돈과 주식의 인도가 마무리되는 절차 |
| 레버리지 | 적은 자기 돈으로 더 큰 가격 변화에 노출되는 구조 |
| 인버스 | 보통 하루 동안 기준 지수와 반대 방향의 수익률을 목표로 하는 상품 |
| 증거금 | 계약 의무를 이행하도록 맡기는 담보. 잃을 수 있는 최대 금액은 아님 |
| 반대매매 | 부족한 돈을 회수하기 위해 증권사가 약정에 따라 자산을 처분하는 것 |
| 옵션 프리미엄 | 정해진 조건으로 사거나 팔 수 있는 권리를 사는 값 |

‘기초적인 것도 모른다’, ‘겁이 많다’ 같은 표현을 쓰지 않는다. 틀리면 정답만 알리기보다 어떤 숫자·상태를 다시 볼지 안내한다. 계산기·표 읽기를 허용하며 암산 속도를 평가하지 않는다. 색상 외에 ‘증가·감소’, 부호와 금액을 함께 표시한다.

## 4 학습 경험과 화면 연결

### 4.1 네 가지 활동을 구분한다

| 활동 | 이용자에게 보일 이름 | 동작과 목적 |
|---|---|---|
| 개념 | 먼저 이해하기 | 1~2분 설명, 그림·표·한 가지 사례. 실제 화면 이동 전 필요한 의미 이해 |
| 안내 실습 | 함께 해보기 | 실제 컴포넌트에 위치 안내. 해당 화면의 입력·조회·취소 기능을 직접 사용 |
| 독립 실습 | 혼자 해보기 | 동일 인터페이스, 다른 가상 숫자·상태, 안내 제거. 힌트는 요청 시 제공 |
| 이해 확인 | 왜 그랬을까요 | 별도 학습 화면에서 1~2개 문항 또는 짧은 설명. 오답 해설 후 재시도 |

개념 변화 슬라이더·수익률 계산기는 유효한 개념 실험 도구다. 다만 실제 일반 화면에 없는 동작을 수행했다면 ‘사이트 조작 튜토리얼’로 포장하지 않는다. 반대로 튜토리얼 화면의 주문 수량 입력은 거래 조작이며 ‘정답 수량 입력 문제’로 바꾸지 않는다.

기존 조작 튜토리얼의 좁은 말풍선에는 별도 시험·점수판을 넣지 않는다. 개념·평가는 `/learn`에서, 실습은 기존 `/trading`·`/assets`에서 이어간다. 이렇게 하면 이전에 정리한 실제 화면 중심 튜토리얼을 유지하면서 사용자의 이번 요청인 개념 학습을 결합할 수 있다.

### 4.2 권장 경로

`/learn`의 첫 화면에 ‘처음 시작하기’를 배치한다. 카드에는 배울 것, 예상 시간, 선수 개념, 활동 종류와 공개 상태를 표시한다. 수익률·인기 종목·다른 사용자 성적을 표시하지 않는다.

순서는 `개념 카드 → 가상 실습 시작 안내 → /trading 또는 /assets → 실습 결과 → 개념 확인 → 다음 수업`이다. 기존 `practice=buy` 등은 호환 진입점으로 유지하고 내부적으로 학습·시나리오 버전을 연결한다. 새 학습 주소·매개변수는 구현 시 확정하며 현재 존재하는 경로인 것처럼 문서에 제시하지 않는다.

화면 안에는 항상 다음 상태를 유지한다.

> 가상 실습 중 · 예시 가격과 연습용 자산을 사용합니다. 회원 계정의 잔고·주문에는 연결되지 않습니다.

이 문구는 10장의 분리 검증을 통과한 뒤 사용한다. 현재 코드가 모든 조건을 이미 충족한다는 선언은 아니다. 상단의 ‘연습 종료’, ‘처음부터’는 어느 단계에서도 접근할 수 있다.

### 4.3 안내를 줄이는 방식

첫 실습은 위치를 알려주고 이유를 설명한다. 두 번째는 ‘주문을 보내기 전에 잘못된 수량을 고쳐 보세요’처럼 목표만 준다. 세 번째는 숫자·가격·주문 상태를 바꾸고 혼자 해결하게 한다. 도움말을 썼다는 이유로 실패 처리하지 않되, 무도움 첫 수행과 도움 후 수행은 구분한다.

잘못된 입력에는 기존 폼의 오류 안내를 사용한다. 튜토리얼 전용 정답 버튼으로 실제 인터페이스의 오류 처리 과정을 우회하지 않는다. 학습 도중 메뉴 이동·뒤로 가기·새로고침이 일어났을 때 무심코 계정형 주문으로 전환되지 않도록 한다.

PER·ROE·재무제표 심화, 옵션 민감도·내재변동성·롤오버 상세, 해외 세금은 선택 읽기로 둔다. 주식 초보자 공통과정에서 많은 용어를 한꺼번에 외우게 하지 않는다. 기존 B2·B3·C2·D3는 공통 개념에 연결한 추가 학습으로 보존한다.

### 6.2 B05 주문 접수와 체결

먼저 ‘접수는 요청을 받은 것, 체결은 거래가 이루어진 것’이라고 설명한다. 실제 가격 종류 필드를 연습에서도 사용하게 하고, 지정가를 입력해 ‘대기’ 내역을 본 뒤 취소한다. 이 사이트의 기존 지정가는 자동 체결하지 않는다는 제한을 화면에 유지한다.

혼자 해보기에서는 이미 준비된 대기 주문을 찾아 취소하게 한다. **확인 창 닫기 성공을 대기 주문 취소 성공으로 인정하지 않는다.** 주문 상태가 ‘취소’가 되었고 해당 주문으로 보유수량·현금이 변하지 않았는지를 함께 확인한다. 마지막 문항은 ‘대기인데 보유 주식이 늘지 않은 이유’로 한다.

실제 시장의 지정가 체결 원리를 보여주는 호가 실험은 개념 도구로 별도 제공할 수 있다. 일반 사이트 주문 엔진이 지원하지 않는 자동체결을 기존 지정가 기능인 것처럼 연습에서만 구현하면 안 된다. 이를 제품 기능으로 추가하려면 잔량·예약금·부분체결·취소 경쟁까지 별도 계약을 확정한다.

### 6.3 R02 하루 배율과 여러 날의 결과

상품 정보에서 ‘하루 수익률을 기준으로 한다’는 문구를 먼저 읽는다. 준비된 예시 가격 경로만 사용하며 실제 종목 추천을 하지 않는다. 처음 값 100에서 지수 +25% 후 −20%를 보여준다. 지수는 100, +2배는 90, −1배는 90, −2배는 70이 된다. 도구는 표와 선 그래프를 함께 제공한다.

학습자는 배율을 바꾸고 기간별 결과를 비교한다. 숫자를 맞히는 버튼 순서로 진행하지 않는다. ‘왜 지수와 같이 돌아오지 않았나요?’라는 질문에 매일 바뀐 금액에 배율이 적용되기 때문이라고 설명한다. 이어 +10%·+10% 경로에서 +2배는 144가 됨을 보여 ‘시간만 지나면 반드시 손실’이라는 반대 오개념도 막는다.

P10·P11 이전에는 이 내용은 개념 카드·표로 제공한다. 새로운 비교 기능이 사이트에 추가되어 단독으로도 이용 가능해진 뒤 그 화면을 튜토리얼 대상으로 삼는다. 극단값으로 모형 가치가 0 이하가 되면 계산을 중단하고 실제 상품 종료 조건은 상품별 확인 사항이라고 알린다.

### 6.4 R03 미수와 갚아야 할 돈

‘내 돈 40만원으로 100만원어치를 사면, 나머지 60만원은 결제일까지 채워야 해요’라는 가상 상황을 제시한다. 실제 미수 기능의 입력과 결제 부족 내역을 사용하되, 실제 은행 입금·송금 기능과 연결하지 않는다. 시나리오 시간만 다음 결제일로 이동한다.

70만원에 처분된 경우 의무금액 60만원을 제외하면 10만원이 남는다. 50만원에 처분된 경우 10만원이 부족하다. ‘손해 본 돈 50만원’과 ‘추가로 갚을 돈 10만원’을 따로 표시한다. 금액을 빚으로 숨기지 않고 음수 순자산을 정확히 설명한다. 실제 반대매매 시점·가격을 보장하는 예제가 아니라는 표시를 붙인다.

혼자 해보기는 ‘현재 부족한 금액과 기한을 찾아보세요’로 한다. ‘더 사서 손실을 회복하세요’ 같은 미션은 금한다. 추가납부와 주문 취소·거래 보류가 가능한 경우의 차이를 설명한다. 이미 체결된 거래를 단순 취소로 없앨 수 있다고 가르치지 않는다.

### 6.5 R05 선물의 계약 규모

가상 상품 명세는 지수 300, 승수 10만원, 1계약, 증거금 300만원이다. 실제 KRX 상품을 의미하지 않는다. 먼저 명목금액 3천만원과 맡긴 증거금 300만원을 나란히 보여준다. 가격 285에서 손실 150만원, 급변하여 260에 종료된 예시에서 손실 400만원을 표시한다.

주문 화면의 승수·계약수·증거금, 자산 화면의 정산·추가 납입을 확인하게 한다. ‘증거금보다 많이 잃을 수 없다’에 동의하면 선수 개념으로 돌아간다. 평가 목적은 투자 배율을 늘리는 능력이 아니라 계약 규모와 상환 의무를 설명하는 능력이다.

### 6.6 R06과 R07 옵션 권리와 의무

R06은 행사가 100, 지급 프리미엄 8, 만기 기초가격 105의 가상 콜에서 권리 가치 5와 순손익 −3을 구별한다. 가격 단위와 계약승수는 분리 표시한다. 초급 단계에서는 만기 손익만 다루고, 만기 전 가격이 같은 공식으로 계산된다고 설명하지 않는다.

R07은 보유 옵션을 팔아 닫는 화면과 새 매도 포지션을 여는 화면을 구분한다. ‘콜을 새로 팔면 가격이 크게 오를 때 큰 의무가 생길 수 있어요’로 설명한다. 무담보 콜 매도의 이론상 손실 상한 없음, 단순 주식 풋 매도의 큰 손실 가능성을 구별한다. 행사 후 주식 또는 선물 포지션이 생기는 상품은 후속 위험도 보여준다.

두 차시 모두 만기·행사·결제 방식이 표시되는 실제 전용 기능 P15가 전제다. 일반 주식의 매수·매도 화면 문구만 바꿔 옵션 거래처럼 보이게 하지 않는다.

## 8 학습 개발 이전의 사이트 선행 기능과 학습 구현 요건

### 8.1 학습 시스템을 만들기 전에 사이트에 있어야 하는 기능

여기서 선행 기능은 **튜토리얼을 켜지 않아도 사이트에서 단독으로 사용할 수 있는 금융 기능**이다. 학습 진입점·화면 격리·예시 데이터·평가는 학습 시스템을 만드는 과정의 작업이며, 이 목록의 선행 금융 기능에 포함하지 않는다. 아래 현황은 2026-10-06 코드 확인 범위다. ‘미구현’ 기능을 현재 있는 화면처럼 설명하거나 일반 주식 주문창으로 대체하지 않는다.

**개발 순서:** 기존 주식·자산·주문 기능의 정합성 보완 → ETF/ETN 정보와 인버스·레버리지 비교 → 미수·신용 기능 → 선물 → 옵션을 제안한다. 각 주제의 사이트 기능이 준비된 뒤 해당 튜토리얼을 붙인다. 모든 고위험 기능이 완성되어야 기초 주식 학습을 시작할 수 있다는 뜻은 아니다.

전용 기능의 제품 범위는 먼저 정한다. **거래 과정을 체험시키려면 해당 상품의 주문·포지션·정산 기능이 필요**하다. 손익 구조만 체험시키려면 사이트에서 독립적으로 사용할 수 있는 계산·비교 도구로도 가능하지만, 이를 해당 상품의 거래 튜토리얼이라고 부르지 않는다. 실제 금융기관 주문 연결이나 실제 대출 제공은 이 선행 개발 요구에 포함하지 않는다.

선행 콘텐츠는 상품 명세와 규칙, 수수료·이자·세금의 적용 범위와 기준일, 손익 계산 설명, 주문·결제 상태 설명, 위험 고지, 출처·데이터 이용 권한이다. 이들은 튜토리얼 문구보다 먼저 일반 상품·기능 화면에서 확인할 수 있어야 한다. 상품별 조건을 정하지 않은 채 하나의 증거금률·청산 기준을 공통 규칙으로 하드코딩하지 않는다.

## 9 교육적으로 유효한지 확인하는 방법

### 9.1 근거와 적용 한계

IES 학습 지침은 예시 풀이와 직접 문제 해결의 교차, 그림과 언어의 결합, 지연 복습, 퀴즈 재노출을 권고한다. 본 기획은 이를 ‘개념 → 안내 실습 → 독립 실습 → 다른 문제’로 적용한다. 권고별 근거 수준은 같지 않으며 모든 구성요소의 효과가 강하게 입증되었다고 표시하지 않는다. [IES 원문](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

EEF는 계획·점검·평가를 가르치고 교사의 시범과 도움을 점차 줄이는 방식을 설명한다. 이를 주문 전 확인, 결과 비교, 짧은 복기에 적용한다. 주로 학교 교육에 관한 근거이므로 성인 주식 초보자의 온라인 학습에 동일 효과가 난다는 보장은 없다. [EEF 지침](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition?search_term=metacog)

금융교육에 관한 76개 무작위 실험의 메타분석은 지식과 금융행동에 평균적으로 긍정적인 효과가 있음을 보고한다. 이것은 이 사이트의 튜토리얼, 고위험 상품 거래능력 또는 투자수익 개선을 검증한 결과가 아니다. 따라서 교육효과 판단에는 별도 파일럿이 필요하다. [Kaiser 외 NBER 원문](https://www.nber.org/papers/w27057)

### 9.3 사용자 연구 계획

**1단계 형성 평가:** 주식 초보자 5~8명씩 두 차례를 제안한다. 투자 경험 없음/적음, 숫자 읽기 자신감 높음/낮음, 모바일/PC를 섞는다. 이는 사용성 문제를 찾는 작은 표본이며 효과를 통계적으로 입증하는 실험이 아니다. B00·B03·B05·R02를 중심으로 소리 내어 생각하기를 진행한다. ‘이 버튼을 누르세요’라는 진행자 도움은 기록하고 독립 성공으로 세지 않는다.

**2단계 학습 파일럿:** 20~30명 규모로 사전 진단 → 학습 → 즉시 사후평가 → 7일 후 다른 문항으로 재평가를 제안한다. 표본은 실행 가능성을 보는 탐색적 규모다. 개인정보 없이 연결하려면 참여자가 보관하는 무작위 연구 코드를 쓰고, 연락처가 필요하면 평가 데이터와 별도 보관한다. 중도 이탈도 분모에 남기고 결측은 별도 보고한다.

**3단계 효과 비교:** ‘개념만’과 ‘개념+튜토리얼’의 인과 효과를 주장하려면 동일 콘텐츠·학습시간 조건을 맞추고 무작위 배정, 사전 점수 보정, 사전 정의한 주요 지표와 표본수 계산이 필요하다. 한 집단의 전후 향상만으로 튜토리얼의 효과라고 단정하지 않는다. 대조군도 공통 위험 고지와 교육을 제공한다.

참여 보상은 수익·정답·거래 횟수와 연결하지 않는다. 평가 기간에 실제 계좌 거래를 요구하지 않는다. 7일 간격은 운영 제안이며 연구가 보장한 최적 간격이 아니다. 계정 비연결 원칙 때문에 연락·자동 알림은 기본 기능에 포함하지 않는다.

### 9.4 지표와 출시 판단 초안

아래 수치는 합의할 제품 품질 목표이며 학계의 공인 기준 또는 현재 달성값이 아니다. 점수 하나로 통과시키지 않고 심각한 오개념·안전 문제를 함께 본다.

| 지표 | 측정 방법 | 초기 목표 |
|---|---|---|
| 독립 조작 성공 | 처음 보는 시나리오에서 진행자 도움 없이 과제 완수 | 공통 핵심 과제 참여자의 80% 이상. 차시·기기별도 보고 |
| 개념 이해 | 새로운 수치·표현의 10문항, 첫 답만 채점 | 즉시 평가 중앙값 8/10 이상 |
| 위험 오개념 | 증거금 한도·원금 초과·일간 배율·접수/체결 4항목 | 첫 답 오개념 비율과 개선을 보고. 한 항목이라도 반복 혼동이면 해당 차시 수정 |
| 지연 유지 | 7일 후 동등 난도 다른 10문항 | 중앙값 7/10 이상을 초기 목표. 재참여율·누락 함께 공개 |
| 설명 능력 | 화면 근거를 들어 2문장 설명 | 루브릭 3/4 이상. 단어 암기만으로 통과 불가 |
| 과신 | 자기 확신 1~5와 실제 정답 비교 | 자신감만 올라가고 오개념이 유지되면 실패 신호 |
| 계정 비연결 | 전체 앱 요청·저장·계정 전후 상태 검증 | 개인정보/계좌 요청·변경 0건, 데이터 오염 0건 |

수익률·계좌 개설률·고위험 상품 사용률·주문 횟수는 학습효과 지표로 삼지 않는다. 체류시간은 이해도와 같지 않으며, 긴 체류는 막힘의 신호일 수 있다.

### 9.5 평가 예시와 루브릭

| 과제 | 기대 답변·행동 | 실패 신호 |
|---|---|---|
| 주문 확인 창을 닫은 뒤 보유수량 확인 | 전송하지 않았으므로 변하지 않음 | 취소가 이미 체결된 거래를 되돌렸다고 설명 |
| 대기 주문 조회 | 주문은 접수됐지만 거래는 아직 성립하지 않음 | 주문내역에 있으니 주식을 가진 것으로 판단 |
| 100만원 중 30만원만 투자 후 주가 −10% | 비용 제외 총자산 97만원 | 계좌 전체가 90만원이라고 계산 |
| 지수 +25%·−20%와 +2배 상품 비교 | 지수 100, 상품 90. 일간 기준이 누적 두 배를 보장하지 않음 | ‘지수 원점이므로 상품도 원점’ |
| 증거금보다 큰 손실 시나리오 | 추가로 필요한 돈과 최초 납입금을 구분 | 잔고가 0이면 모든 의무가 끝난다고 판단 |
| 설명서의 보장수익 문구 점검 | 근거와 위험을 확인하고 거래 보류를 선택할 수 있음 | 높은 수익만 보고 체험 후 즉시 투자 결심 |

설명형 답변은 ‘개념 구분 1점, 화면 근거 1점, 이유 연결 1점, 적용 한계 1점’으로 평가한다. 문법·문장 길이는 채점하지 않는다. 사람 검토를 우선하고 AI가 단독으로 학습 적격·투자 적합성을 판정하지 않는다. 문항은 가능한 한 다른 순서·숫자·상황을 사용한다.

엄격한 계정 비연결은 ‘서버에 주문을 안 보냄’보다 넓다. 로그인된 브라우저에서도 개인 정보를 화면에 끌어오지 않고, 계좌 선택·인증 토큰·학습 기록·관심종목 저장을 건드리지 않아야 한다.

### 10.2 구현 방향

현재 `SitePractice`가 `Layout` 본문만 감싸는 구조를 확장해야 한다. 권장안은 **공유 화면 컴포넌트를 사용하되 학습 진입에서는 실제 `AuthProvider` 부트스트랩과 개인화 헤더·전역 자산창을 실행하지 않는 별도 학습 셸**이다. 헤더의 위치·기본 디자인은 유지하되 사용자 이름 대신 ‘가상 실습’을 표시한다. UI를 복제한 별도 주문 폼을 만들지 않는다.

가상 리소스 제공자·주문 실행기·시나리오 시계는 명시적으로 주입한다. 화면이 특정 리소스를 지원하지 않으면 연습 불가 상태를 보여주며, 일반 API로 자동 전환하지 않는다. 실제 API 클라이언트의 쓰기 기능은 학습 셸에 주입하지 않는 구조를 권장한다.

학습 시작 시 진행 중인 개인 데이터 요청이 있다면 취소하거나 응답 반영을 차단하고, 가상 화면에 개인 캐시가 나타나지 않는지 검증한다. 일반 모드 복귀는 ‘가상 실습을 종료했어요’ 상태를 먼저 보여준 뒤 사용자의 별도 이동으로 처리한다. 실습 주문을 일반 주문에 복사하거나 제출하지 않는다. 로그인 상태 자체를 바꾸기 위해 로그아웃·토큰 삭제를 호출해서도 안 된다.

시나리오 URL에는 계좌·금액·개인정보를 넣지 않는다. 허용된 과정 ID와 버전만 해석한다. 알 수 없는 과정 ID는 일반 트레이딩으로 조용히 되돌리지 않고 학습 목록·오류 화면으로 이동한다.

## 12 기능과 콘텐츠의 연결 계약

### 12.1 최소 학습 정의

각 차시는 다음 정보를 가진다. 실제 스키마·API를 구현했다는 의미가 아니라 개발 계약 초안이다.

| 묶음 | 필드 |
|---|---|
| 식별 | lessonId, contentVersion, title, audience, estimatedMinutes |
| 목표 | prerequisiteIds, learningObjectives, misconceptions, riskLevel |
| 기능 연결 | requiredCapabilities, route, targetIds, supportedModes |
| 예시 | scenarioId, scenarioVersion, initialState, virtualClock, policyVersion, assumptions |
| 안내 | steps, eventConditions, stateAssertions, optionalHints, exitBehavior |
| 평가 | alternateQuestionIds, rubric, criticalItems, remediationLessonIds |
| 출처 | sourceUrls, checkedAt, effectiveAt, reviewer, nextReviewAt, licenseStatus |
| 공개 | conceptReady, practiceReady, evaluationReady, releaseStatus |

같은 `filled` 이벤트만으로 모든 학습이 끝나지 않도록 한다. 종목·수량·현금·주문 상태·계좌가 기대한 시나리오와 일치하는지도 확인한다. 정해진 수량을 주문했는지 보는 경우에는 ‘수량 확인 작업’이라는 과제 목적을 먼저 밝힌다. 자유 실습에서는 경제적으로 유효한 여러 행동을 허용한다.

### 12.2 완료 상태

상태는 ‘시작 전’, ‘개념 확인’, ‘안내 실습 완료’, ‘혼자 해보기 완료’, ‘이해 확인’, ‘복습 권장’으로 나눈다. 개념을 읽거나 ‘확인했어요’를 눌렀다는 이유만으로 이해 확인 상태를 주지 않는다. 필수 개념 2문항 정답과 독립 수행을 확인하되, 답을 외운 반복은 첫 수행 성공과 별도로 남긴다.

핵심 위험 문항 오답 시 심화 실습 진입 전에 짧은 재설명과 다른 문항을 제공한다. 개념 읽기·도움말·나가기·기초 복습은 항상 허용한다. 이 제한은 교육 흐름이지 투자 적합성 판정이 아니다.

### 12.3 화면 변경에 대한 대응

대상은 CSS 위치가 아닌 안정적인 의미 식별자(예: 기존 `account`, `order-fields`, `history`, `asset-holdings`)로 찾는다. 요소가 없거나 기능 버전이 다르면 다음 단계로 억지 진행하지 않고 ‘이 실습은 화면 변경으로 점검 중입니다’로 종료한다. 모바일에서 요소가 접혀 있으면 실제 펼침 조작을 안내한다.

말풍선이 주문 확인 정보·취소·종료 버튼을 가리지 않아야 한다. 포커스 이동은 예측 가능해야 하고 키보드로 설명과 동작을 왕복할 수 있어야 한다. 자동 스크롤·애니메이션은 최소화하며 동작 감소 설정을 지원한다. 오답·손실을 빨강 하나로만 표현하지 않는다.

### 14.1 이 기획에서 수행한 점검

현재 코드와 기존 문서를 비교하여 실제 화면 재사용 구조, 비용·주문 상태의 불일치, 전역 인증과 계정별 학습 기록의 분리 필요성을 확인했다. 공통 10개·선택 8개·보충 1개 차시를 학습목표·화면·평가·선행 기능에 대응시켰다. 제시한 계산 예시는 산술 검증하고, 법률·교육 연구는 원문 링크와 적용 한계를 표시한다.

실제 초보자 연구, 새 기능 구현, 앱 전체 개인정보 비연결 검증, 운영 배포 확인은 아직 수행하지 않았다. 따라서 이 문서는 **구현 가능한 기획과 검증 계획**이며 교육 효과나 서비스 전체 적법성 인증이 아니다.
