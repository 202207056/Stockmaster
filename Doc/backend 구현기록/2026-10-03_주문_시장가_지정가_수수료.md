# 2026-10-03 · 주문 시장가·지정가·수수료

백엔드 저장소 `gp-mock-inv`만 변경했다. 팀 프론트 코드와 팀 저장소 `Stockmaster`는 변경하지 않았다.

배포 주소: `https://gp-mock-inv.onrender.com` · 명세: `https://gp-mock-inv.onrender.com/docs`

이 기록은 주문 API 세 가지를 다룬다. 학습 진도 API, 인버스·레버리지·선물·미수 상품은 만들지 않았다.

## 변경 요약

| 항목 | 동작 |
|---|---|
| 가격 종류 | 요청 `price_type`. 없거나 `시장가`면 KIS 현재가로 바로 체결. `지정가`면 요청 `price`로 주문을 저장하고 상태는 `대기`. 지정가는 현금과 보유 수량을 바꾸지 않고, 나중에 자동으로 체결하지도 않는다. |
| 종목 표 | 주문 코드가 `item_master`에 없으면 한국 이름을 확인한 뒤 코드·이름만 한 줄 넣고 주문을 진행한다. 이름을 읽지 못하면 404이고 행을 넣지 않는다. 검색 API는 그대로다. |
| 비용 | 수수료 0.015%는 매수·매도 모두. 거래세 0.18%는 매도만. 원 단위 반올림. 시장가 매수 출금은 거래대금 + 수수료. 시장가 매도 입금은 거래대금 − 수수료 − 거래세. 응답에 `commission`, `tax`가 있다. |

기존 프론트는 `price_type`을 보내지 않아도 된다. 그러면 시장가로 처리되므로, 주문 전송을 켜면 이전과 같이 바로 체결되고 수수료만 추가된다.

평균단가는 체결가 기준이다. 수수료는 평균단가에 섞지 않고 현금에서만 뺀다.

지정가 매수도 수수료를 포함한 금액이 현금보다 크면 거절한다. 지정가 매도는 보유 수량보다 많으면 거절한다. 둘 다 잔고는 줄이지 않는다. 대기 주문 취소는 기존 `PUT /api/trading/orders/{order_id}/cancel` 이다. 체결된 주문은 취소할 수 없다.

## 요청과 응답

로그인 필요. 경로 `POST /api/trading/orders`.

```json
{
  "account_id": 1,
  "symbol_code": "373220",
  "order_type": "매수",
  "price_type": "시장가",
  "price": 400000,
  "quantity": 1
}
```

`373220`처럼 시드 30종목에 없는 코드도 이름을 확인하면 주문할 수 있다. 지정가는 `price_type`을 `지정가`로 보내고, `price`가 주문 가격이 된다.

응답에 기존 필드가 그대로 있고, `price_type`, `commission`, `tax`가 추가된다. 모르는 필드는 프론트가 무시해도 된다. `message`는 시장가면 수수료(매도는 거래세 포함)를 말하고, 지정가면 잔고가 아직 변하지 않았다고 말한다.

주문 목록 `GET /api/trading/orders?account_id=` 도 같은 비용 필드를 돌려준다. 예전 주문은 `price_type`이 `시장가`이고 수수료·세금은 0이다.

## 표 변경

`orders`에 세 칸을 추가한다.

| 칸 | 의미 |
|---|---|
| `price_type` | `시장가` 또는 `지정가`. 기본값 `시장가` |
| `commission` | 수수료(원). 기본값 0 |
| `tax` | 거래세(원). 기본값 0 |

Render 빌드는 `alembic upgrade head`를 실행한다. 버전 순서는 `2622474e79f5` 다음이 이미 데이터베이스에 적용된 `c20260930_cost_policy`이고, 그 다음이 오늘 리비전 `c4e8a1b27d90`이다. `c20260930_cost_policy` 파일을 저장소에서 빼면 빌드가 `Can't locate revision`으로 실패한다. 서버가 켜질 때도 `price_type`, `commission`, `tax` 칸이 없으면 같은 칸을 추가한다. `commission`은 9월 30일 버전에 이미 있을 수 있어, 없을 때만 만든다.

## 확인하지 않은 것

실제 계좌에 주문을 넣어 잔고가 바뀌는 호출은 하지 않았다. 배포 후 명세에서 시장가·지정가·없는 종목 코드를 각각 한 번씩 확인하면 된다. 지정가는 시간이 지나도 `대기`로 남는 것이 정상이다.
