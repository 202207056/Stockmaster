# 2026-09-11 · 시세·주문 검증·AI 코칭

백엔드 저장소 `gp-mock-inv`만 변경했다. 팀 프론트 코드는 변경하지 않았다.

배포 반영은 개인 GitHub `main` 푸시 후 Render 빌드가 끝난 뒤에 확인할 수 있다. 명세: `https://gp-mock-inv.onrender.com/docs`

## 변경 요약

| 영역 | 구현한 내용 |
|---|---|
| 종목 순위 | `volume`(평균거래량)과 `amount`(거래금액순)를 같은 TR에서 `FID_BLNG_CLS_CODE`만 다르게 호출. `change`는 기존 등락률 API 유지 |
| 주요 시세 | `GET /api/market/indices` 추가. 코스피 `0001`, 코스닥 `1001`만 KIS 실전 `inquire-index-price` 조회. 나스닥·S&P 500·금·달러는 `value: null` |
| 주문 | 요청 JSON `{account_id, symbol_code, order_type, price, quantity}` 유지. `price`/`quantity`는 0보다 커야 함. 체결가는 클라이언트가 보낸 값이 아니라 KIS 모의 현재가. 시세 없거나 0이면 400. 계좌·보유 행 `FOR UPDATE` |
| 설문 | 기존 `POST /api/ai/survey`가 답변 저장과 Gemini Flash 분석을 함께 수행. 별도 AI 서버 없음 |
| 코칭 | `GET /api/ai/coach?symbol=005930`이 없는 AI 서버 프록시를 그만 두고, 현재가·고가·저가·보유·투자성향 요약만 Gemini Flash에 보냄. 같은 사용자·종목은 3분 캐시 |

모델은 설문과 같은 무료 Gemini Flash(`GEMINI_MODEL`)를 사용한다. 차트 봉, 순위 전체, 뉴스 본문은 코칭 프롬프트에 넣지 않는다.

## 프론트가 부르면 되는 계약

주문 전송 코드는 기존 필드를 유지하면 된다. 서버가 체결가를 바꿔도 요청 키 이름은 그대로다.

```http
POST /api/trading/orders
{
  "account_id": 1,
  "symbol_code": "005930",
  "order_type": "매수",
  "price": 75000,
  "quantity": 1
}
```

`price`는 화면 표시용으로 받아 두지만 체결·잔고·평균단가 계산에는 쓰지 않는다.

```http
GET /api/market/indices
```

응답 예:

```json
[
  { "code": "kospi", "name": "코스피", "value": 2650.12, "change_rate": 0.85 },
  { "code": "kosdaq", "name": "코스닥", "value": 850.33, "change_rate": -0.42 },
  { "code": "nasdaq", "name": "나스닥", "value": null, "change_rate": null },
  { "code": "sp500", "name": "S&P 500", "value": null, "change_rate": null },
  { "code": "gold", "name": "금", "value": null, "change_rate": null },
  { "code": "usd", "name": "달러", "value": null, "change_rate": null }
]
```

로그인 없이 호출할 수 있다. `value`가 `null`이면 화면의 `준비 중`을 유지하면 된다.

```http
GET /api/ai/coach?symbol=005930
```

로그인(Bearer) 필요. `symbol` 기본값은 `005930`이다.

응답 예:

```json
{
  "facts": {
    "symbol_code": "005930",
    "name": "삼성전자",
    "current_price": 75000,
    "change_rate": 1.2,
    "investment_style": "안정추구형",
    "holding": { "quantity": 10, "avg_price": 72000, "return_rate": 4.17 }
  },
  "disclaimer": "모의투자 연습용 조언이며 투자 권유가 아닙니다.",
  "observation": "오늘 변동 폭이 크지 않습니다.",
  "advice": "한 종목에 수량을 몰아넣지 않고 나눠 보는 연습을 해 보세요.",
  "caution": "급등 직후 추격 매수는 신중히 보세요."
}
```

## 프론트 문서(2026-09-08) 요청 대비

| 당시 요청 | 이 작업에서의 처리 |
|---|---|
| CORS·테스트 환경 | CORS는 기존과 같이 `*`. 공통 테스트 계정은 만들지 않음 |
| 서버 체결가·수량 검증·트랜잭션 | 체결가·수량·행 잠금 반영. **멱등성과 수수료는 하지 않음.** 새 주문 JSON도 만들지 않음 |
| 자산 요약·시세 기준시각 | 하지 않음. 포트폴리오 평가는 프론트 계산 유지 |
| 공개 종목/뉴스/커뮤니티 | 종목·뉴스·종목순위는 비로그인 허용. 커뮤니티 목록은 로그인 유지 |
| 거래대금 순위 | `amount` 분리 완료 |
| 설문 단일 API | `POST /api/ai/survey`가 저장+분석. 프론트 화면 문구가 로컬 점수라고 안내하는 것과는 별개 |
| 학습 추천·진도 API | 하지 않음 |

당시 프론트가 주문을 끈 이유(클라이언트가 보낸 가격으로 체결)는 서버에서 고쳤다. 화면 플래그 `VITE_ENABLE_ORDER_SUBMISSION`은 프론트가 테스트 환경에서 켜면 된다.

홈 상단 `준비 중`은 당시 지표 API가 없어서였다. 백엔드 경로는 생겼고, 팀 프론트 `main`이 `/api/market/indices`를 부르기 전에는 화면에 숫자가 나오지 않는다.

## 검증

- 개인 저장소 `main`에 커밋 후 `origin`만 푸시했다. 팀 저장소(`Stockmaster`)에는 이 시점에 푸시하지 않았다.
- 로컬에서 지수 조회를 시도했으나, 이 PC의 실전 토큰 발급이 403이라 숫자 매핑은 Render(등록 IP)에서 확인해야 한다. 실패 시 `value: null`로 내려가도록 작성했다.
- 로컬 venv에는 `google` 패키지가 없어 uvicorn 기동은 이 PC에서 확인하지 못했다. Render 배포 환경에는 설문용 Gemini 의존성이 있다.
- Swagger에서 로그인 후 코치·주문·지수를 누르는 확인은 배포 완료 후 수행하면 된다. 이 문서 작성 시점에 브라우저 Execute 성공을 단정하지 않는다.

## 하지 않은 것

- 나스닥·S&P·금·달러 시세, 지수 미니 차트
- 현재가 응답의 `fetched_at`
- 주문 멱등 키, 수수료
- 관심종목 서버 저장, 학습 퀴즈 API
- `GET /api/ai/recommend`, `/pattern`, `/news-summary/{code}` — 여전히 별도 AI 서버(`AI_SERVER_URL`)를 호출하며 서버가 없으면 503
- `.env.example`의 `KIS_ACCOUNT_NO` 정리, 실전 키 항목 추가

## 다음 확인 순서

1. Render 배포 로그가 최신 커밋인지 확인한다.
2. `/docs`에서 로그인 → Authorize → `GET /api/market/indices`, `GET /api/ai/coach`, (소량) `POST /api/trading/orders`를 실행한다.
3. 프론트는 기존 주문 필드 유지, 지수 API 연결, 코치 API 연결만 하면 된다. 백엔드 폴더의 프론트 수정은 필요하지 않다.
