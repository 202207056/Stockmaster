## 1. 아키텍처 원칙

1. **KIS Open API는 "시세 소스"로만 사용한다.** 계좌·주문·체결·잔고는 100% 자체 구현. (현행도 이 원칙을 지키고 있음 ✅)
2. **외부 API 의존을 한 파일로 격리한다.** KIS 호출은 `services/kis_service.py` 밖으로 나가지 않는다. (현행 준수 ✅)
3. **모든 시세는 캐시를 거친다.** (현행 ❌ — 요청마다 KIS 직접 호출. 최우선 보강 대상)
4. **금액 계산은 전부 서버에서.** 클라이언트가 보낸 가격을 그대로 믿지 않는다. (현행 ❌ — `11` 문서 C-1)
5. **초보자 친화 = 응답이 항상 "설명 가능"해야 함.** 에러/거부 사유를 사람 말로 내려준다.
6. **동작하는 것을 깨지 않는다.** 이미 배포되어 돌아가는 구조를 갈아엎지 말고 증분 개선한다. ← 신규 원칙

### 최초 문서에서 제안했던 것 중 **철회**하는 항목

| `app/api/v1/endpoints/` 계층 | ❌ **철회** | 현행 `routers/`가 이미 같은 역할. 경로도 `/api/...`로 배포됨 |
| **비동기 SQLAlchemy(asyncpg)** | ❌ **철회** | 동기로 이미 동작 중. 전환 비용 대비 이득 없음 (§5 참고) |
| Redis 도입 | 🟡 **보류** | 1단계는 프로세스 내 메모리 캐시로 충분. Render 단일 인스턴스 |
| `db/init_data.py` 시드 | ✅ 유지 | `item_master_seed.sql`이 이미 있음. 학습·설문 시드 추가 |

### 레이어 규칙 (현행 유지)
- `routers`는 DTO 변환과 권한 확인만. 비즈니스 로직 금지.
- `services`는 ORM 모델을 다루되 HTTP를 모른다.
- KIS/LLM 등 외부 호출은 `services/*_service.py` 밖으로 새어나가지 않는다.

> 🟡 현행에서 이 규칙이 깨진 곳: `routers/ai.py`가 Pydantic 스키마 정의와 httpx 호출을 직접 갖고 있습니다.
> AI를 내부 모듈로 통합할 때 `schemas/ai.py` + `services/ai/`로 분리하세요.

## 5. 동기 vs 비동기 — 현행 구조의 알려진 문제

현행은 **동기 SQLAlchemy + 비동기 라우터가 혼재**합니다.

```python
# routers/securities.py
async def get_price(symbol_code: str, ...):      # async 라우터
    return await get_current_price(symbol_code)  # httpx 비동기 → OK ✅

# routers/orders.py
def place_order(..., db: Session = Depends(get_db)):  # sync 라우터
    ...                                                # 스레드풀에서 실행 → OK ✅
```

FastAPI는 `def`(동기) 라우터를 스레드풀에서 돌리므로 **현재 구조는 정상 동작합니다.**
다만 앞으로 지킬 규칙이 있습니다.

| 상황 | 규칙 |
|---|---|
| DB만 접근 | `def` (동기) 라우터 — 현행 그대로 |
| KIS/LLM만 호출 | `async def` 라우터 |
| **DB + KIS 둘 다** (예: 체결가 결정) | ⚠️ `async def` 안에서 동기 `db.query()`를 호출하면 **이벤트 루프가 막힙니다** |

**C-1 수정(체결가를 KIS로 결정) 시 이 문제를 반드시 만나게 됩니다.** 해결책:

```python
# 방법 A (권장) — 동기 라우터 유지 + KIS 호출만 동기 클라이언트로
def place_order(req, db: Session = Depends(get_db)):
    quote = kis_service.get_current_price_sync(req.symbol_code)  # httpx.Client (동기)
    ...

# 방법 B — 비동기 라우터 + DB는 스레드로 위임
async def place_order(...):
    quote = await kis_service.get_current_price(req.symbol_code)
    order = await run_in_threadpool(order_service.create_order, db, req, user_id, quote)
```
> **방법 A를 권장합니다.** `kis_service`에 동기 버전 함수를 하나 추가하는 것이 가장 간단하고,
> 캐시가 붙으면 대부분의 호출이 네트워크를 타지도 않습니다.

## 7. 인증 설계

### 현행 (구현 완료)

| 항목 | 현행 |
|---|---|
| 방식 | JWT 단일 토큰 (`python-jose`, HS256) |
| 만료 | **60분** (`ACCESS_TOKEN_EXPIRE_MINUTES`) |
| 페이로드 | `{"sub": str(user_id), "exp": ...}` |
| 비밀번호 | **bcrypt** (`passlib` + `bcrypt==4.0.1`) ✅ |
| 전달 | `Authorization: Bearer` (HTTPBearer) |
| 검증 | `utils/deps.py:get_current_user` — 토큰 디코딩 후 **DB에서 유저 재조회** ✅ |
| 소유권 | 모든 계좌·주문 조회에 `user_id` 필터 적용 ✅ |

### 보강할 것

| # | 항목 | 이유 |
|---|---|---|
| A-1 | **리프레시 토큰 + 로그아웃** | 현재 60분 뒤 재로그인만 가능하고, 서버 측 토큰 무효화 수단이 없음 |
| A-2 | `role` 컬럼 (USER/ADMIN) | 학습 콘텐츠 관리·게시글 신고 처리 |
| A-3 | 로그인 시도 rate limit | 무차별 대입 방어 |
| A-4 | 비밀번호 정책 (최소 길이 등) | 현재 `passwd: str` 무제한 |

> bcrypt는 충분히 안전하므로 **Argon2로 바꿀 필요 없습니다.** (최초 문서의 Argon2 권고는 철회)
> 이미 해싱된 비밀번호를 마이그레이션하는 비용만 발생합니다.

> 토큰 저장 위치: 현행 프론트는 `localStorage`를 씁니다. 졸업작품 수준에서 허용 가능하나,
> 리프레시 토큰을 도입한다면 그것만은 **httpOnly 쿠키**로 두고 "왜 그렇게 했는지" 설명할 수 있게 하세요.

### 에러 응답 — 현행 → 개선

```jsonc
// 현행 (FastAPI 기본)
{ "detail": "매수 가능 현금이 부족합니다." }

// 개선 목표 — 학습 연계를 위해 code와 help_concept_id 추가
{
  "error": {
    "code": "INSUFFICIENT_CASH",
    "message": "주문가능금액이 부족합니다.",
    "detail": "필요 3,270,490원 / 가능 1,500,000원",
    "help_concept_id": "cash_and_margin"
  }
}
```

`help_concept_id`를 넣어두면 **에러 화면에서 바로 학습 모듈로 연결**할 수 있습니다.
발표자료의 "도움말 아이콘" 요구사항을 API 레벨에서 지원하는 설계입니다.

**적용 방법** (기존 코드를 최소한으로 건드리는 방식)
```python
# app/utils/exceptions.py (신설)
class DomainError(HTTPException):
    def __init__(self, code, message, detail=None, help_concept_id=None, status_code=422):
        super().__init__(status_code=status_code, detail={
            "error": {"code": code, "message": message,
                      "detail": detail, "help_concept_id": help_concept_id}})

# 사용
raise DomainError("INSUFFICIENT_CASH", "주문가능금액이 부족합니다.",
                  f"필요 {need:,.0f}원 / 가능 {avail:,.0f}원", "cash_and_margin")
```
기존 `HTTPException`을 한꺼번에 바꿀 필요 없이 **거래 도메인부터 점진적으로** 교체하세요.

### 기타 규약
- 목록 응답은 `{items, total, page, size}` (현행 커뮤니티가 이미 유사한 형태 ✅)
- 시간 필드는 ISO-8601 + KST 오프셋. **현행은 `datetime.utcnow()` naive** → `TIMESTAMPTZ` 전환 필요
- 금액은 숫자로, 국내주식은 정수 원 단위
- CORS는 `["*"]` → 배포 시 프론트 도메인 화이트리스트로
