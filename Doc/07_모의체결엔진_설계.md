## 1. 왜 자체 구현인가 (변함없음)

| 항목 | KIS 모의투자 API 사용 시 | 자체 구현 (본 프로젝트) |
|---|---|---|
| 계정 | 사용자마다 증권사 계좌 필요 → **불가능** | 사이트 자체 회원 |
| 초기자금 | 증권사 정책에 종속 | 자유 (1,000만원, 리셋 가능) |
| 학습 기능 연계 | 체결 이벤트를 가로챌 수 없음 | **손실 → 학습 트리거 연결 가능** ★ |
| 시연 안정성 | 증권사 장애 시 전체 마비 | 시세만 폴백하면 계속 동작 |

→ 현행 구현이 이 원칙을 정확히 따르고 있습니다. **방향은 옳습니다.**

## 2. 현행 구현 분석 (`order_service.py`)

### 동작 방식: 즉시 체결

```python
def create_order(db, req, user_id) -> Order:
    account  = db.query(Account).filter(account_id, user_id).first()   # ① 계좌 확인
    security = db.query(ItemMaster).filter(symbol_code).first()        # ② 종목 확인
    total_amount = req.price * req.quantity                            # ③ 금액 계산
    if req.order_type == "매수":  _process_buy(...)
    elif req.order_type == "매도": _process_sell(...)
    order = Order(..., status="체결")                                   # ④ 즉시 체결로 기록
    db.add(order); db.commit()
```

| 항목 | 현행 |
|---|---|
| 주문 유형 | `"매수"` / `"매도"` (한글 문자열) |
| 주문 상태 | `"대기"` → 실제로는 항상 `"체결"`로 생성 |
| 체결 방식 | 요청받은 `price`로 100% 즉시 체결 |
| 평단 계산 | `(기존평단×기존수량 + 신규가×신규수량) / 총수량` ✅ 공식은 정확 |
| 전량 매도 | `portfolio` 행을 `db.delete()` |
| 트랜잭션 | `create_order` 전체가 하나의 커밋 ✅ |
| 소유권 검증 | `Account.user_id == user_id` ✅ |

### 🟢 잘한 점
- 계좌·종목 존재 확인, 잔고 부족·수량 부족 검증이 있음
- 평균단가 재계산 공식이 정확함
- 매수/매도를 `_process_buy` / `_process_sell`로 분리 (읽기 쉬움)
- 한 트랜잭션 안에서 커밋

### 🔴 치명적 결함 4건 (수정 순서 = 우선순위)

| # | 결함 | 현행 코드 | 결과 |
|:--:|---|---|---|
| C-1 | 체결가를 클라이언트가 지정 | `total_amount = req.price * req.quantity` | **무한 수익** |
| C-2 | 수량·가격 음수 검증 없음 | `quantity: int` (제약 없음) | **잔고 증식** |
| C-3 | 매수 시 `balance`도 차감 | `account.balance -= total_amount` | **랭킹 역순** |
| C-4 | 행 잠금 없음 | `.first()` (FOR UPDATE 없음) | **이중 지출** |

### 🟠 빠져 있는 것

| 항목 | 현행 | 필요성 |
|---|:--:|---|
| 체결 기록(`trades`) | ❌ | 실현손익·수수료·세금·거래내역·학습 트리거의 전제 |
| 수수료·세금 | ❌ | 리얼리티 + 교육 효과 |
| 장 운영시간 | ❌ | 새벽 3시에도 체결됨 |
| 호가 단위 | ❌ | 327,123원 주문 가능 |
| 상·하한가 | ❌ | ±30% 넘는 가격 주문 가능 |
| 지정가 대기(미체결) | ❌ | `status="대기"`가 사문화 |
| 예수금 잠금 | ❌ | 미체결 도입 시 필수 |
| 부분 체결 | ❌ | 선택 구현 |

### 4-2. 체결가를 서버가 결정 (C-1 해결) ★ 핵심

```python
def create_order(db: Session, req: OrderRequest, user_id: int) -> Order:
    # ── 장 운영시간 ─────────────────────────────
    if not market_calendar.is_market_open():
        raise DomainError("MARKET_CLOSED",
                          "지금은 거래 시간이 아니에요. (평일 09:00~15:30)",
                          help_concept_id="market_hours")

    # ── 계좌·종목 (행 잠금 포함, C-4 해결) ──────
    account = (db.query(Account)
                 .filter(Account.account_id == req.account_id,
                         Account.user_id == user_id)
                 .with_for_update()                       # ★ 추가
                 .first())
    if not account:
        raise HTTPException(404, "계좌를 찾을 수 없습니다.")

    stock = db.query(ItemMaster).filter(...).first()
    if not stock:
        raise HTTPException(404, "종목을 찾을 수 없습니다.")

    # ── 시세 조회 → 체결가 결정 (C-1 해결) ──────
    quote = market_provider.get_price_sync(req.symbol_code)   # 캐시 경유
    market_price = Decimal(quote["current_price"])
    if market_price <= 0:
        raise DomainError("QUOTE_UNAVAILABLE", "현재 시세를 가져올 수 없어 주문할 수 없습니다.")

    if req.order_kind == "시장가":
        fill_price = market_price
    else:  # 지정가
        _validate_tick_size(req.price)                        # 호가 단위
        _validate_price_limit(req.price, quote)               # 상·하한가
        # 1단계에서는 지정가도 즉시 체결. 단, 사용자에게 유리한 가격으로.
        fill_price = min(req.price, market_price) if req.order_type == "매수" \
                     else max(req.price, market_price)

    total_amount = fill_price * req.quantity
    ...
```

> **핵심은 `req.price`를 금액 계산에 직접 쓰지 않는 것**입니다.
> `req.price`는 "지정가 희망값"으로만 쓰고, 실제 체결가는 항상 시세에서 파생시킵니다.

### 4-3. 검증 유틸 (신설)

```python
# app/services/trading/tick_size.py
TICK_TABLE = [
    (2_000,     1),  (5_000,      5),  (20_000,   10), (50_000,   50),
    (200_000, 100),  (500_000,  500),  (10**12, 1000),
]

def tick_size(price: Decimal) -> int:
    for upper, tick in TICK_TABLE:
        if price < upper:
            return tick
    return 1000

def _validate_tick_size(price: Decimal):
    t = tick_size(price)
    if int(price) % t != 0:
        raise DomainError("INVALID_TICK_SIZE",
                          f"이 가격대는 {t:,}원 단위로만 주문할 수 있어요.",
                          help_concept_id="tick_size")

def _validate_price_limit(price: Decimal, quote: dict):
    upper = Decimal(quote.get("upper_limit") or 0)
    lower = Decimal(quote.get("lower_limit") or 0)
    if upper and not (lower <= price <= upper):
        raise DomainError("PRICE_OUT_OF_LIMIT",
                          "상한가~하한가 범위를 벗어났어요.",
                          f"{lower:,.0f}원 ~ {upper:,.0f}원",
                          help_concept_id="price_limit")
```

> 호가 단위·상하한가는 KIS 현재가 응답의 `stck_mxpr`/`stck_llam`을 수집해야 씁니다
> (`06` 문서 §4). 아직 수집 전이면 `upper == 0`으로 검증을 건너뛰도록 해두세요.
>
> ⚠️ 호가 단위 구간은 시장·시점에 따라 다를 수 있습니다. **상수로 박지 말고 위처럼 테이블로**
> 관리하고, 공식 자료로 확인 후 이 문서에 갱신하세요.
>
> 💡 프론트 주문 폼에서 **호가 단위 스텝 버튼(▲▼)** 을 제공하면 이 에러가 거의 안 납니다.

### 5-1. `trades` 테이블 연결

체결이 일어날 때마다 기록을 남깁니다. (`04` 문서 §4-1)

```python
def _execute(db, account, order, fill_price: Decimal, qty: int, stock):
    """이 함수 전체가 create_order의 트랜잭션 안에서 실행된다."""
    amount = fill_price * qty
    pos = _get_portfolio(db, account.account_id, order.symbol_code, for_update=True)

    if order.order_type == "매수":
        fee = fee_policy.buy_fee(amount)
        tax = Decimal(0)
        settled = -(amount + fee)
        new_total_buy = pos.total_buy_amount + amount + fee
        new_qty       = pos.hold_quantity + qty
        pos.avg_price = int((new_total_buy / new_qty).quantize(Decimal("1"), ROUND_HALF_UP))
        pos.total_buy_amount = new_total_buy
        pos.hold_quantity    = new_qty
        realized_pnl = realized_rate = Decimal(0)
    else:  # 매도
        fee = fee_policy.sell_fee(amount)
        tax = fee_policy.sell_tax(amount, stock.market)
        settled = amount - fee - tax
        cost = Decimal(pos.avg_price) * qty
        realized_pnl  = settled - cost                    # ★ 실현손익
        realized_rate = realized_pnl / cost * 100 if cost else Decimal(0)
        pos.hold_quantity    -= qty
        pos.total_buy_amount  = Decimal(pos.avg_price) * pos.hold_quantity
        pos.realized_pnl     += realized_pnl

    account.withdrawable_cash += settled

    trade = Trade(order_id=order.order_id, account_id=account.account_id,
                  symbol_code=order.symbol_code, order_type=order.order_type,
                  price=int(fill_price), quantity=qty, amount=amount,
                  fee=fee, tax=tax, settled_amount=settled,
                  realized_pnl=realized_pnl, realized_pnl_rate=realized_rate,
                  avg_price_before=pos.avg_price)
    db.add(trade)

    if pos.hold_quantity == 0:
        db.delete(pos)        # 전량 매도 — trades에 이력이 남으므로 삭제해도 안전

    return trade
```

## 6. 3단계 — 지정가 미체결 주문 (3일, SHOULD)

현행의 `status="대기"`를 실제로 살리는 단계입니다.

### 6-1. 주문 수명주기

```text
         ┌──────────────┐
 접수 →  │    대기      │ ── 조건 충족 ──→ 체결
         │ (예약금 잠금)│
         └──────┬───────┘
                │ 사용자 취소 → 취소   (예약금 반환)
                │ 장 마감      → 만료   (예약금 반환)
                │ 검증 실패    → 거부   (접수 시점에 즉시)
                ▼
```

| 상태 | 예약금 | 취소 가능 |
|---|---|:--:|
| `대기` | 잠금 | ✅ |
| `체결` | 해제 | ❌ |
| `취소` | 반환 | ❌ |
| `만료` | 반환 | ❌ |
| `거부` | 없음 | ❌ |

### 6-2. 접수 시 자금·수량 잠금

```python
if order_type == "매수":
    need = fill_price_estimate * qty + fee_estimate
    if need > account.withdrawable_cash - account.locked_cash:   # 주문가능금액
        raise DomainError("INSUFFICIENT_CASH", ...)
    account.locked_cash += need          # ★
    order.reserved_cash  = need
else:  # 매도
    available = pos.hold_quantity - pos.locked_quantity
    if qty > available:
        raise DomainError("INSUFFICIENT_QUANTITY", "보유 수량이 부족합니다.",
                          f"주문가능 {available}주")
    pos.locked_quantity += qty           # ★
```

> 🔴 **취소·체결 시 잠금 해제를 빼먹는 것이 가장 흔한 버그입니다.**
> 정합성 검증 쿼리(`04` 문서 §5)를 배치로 돌려 항상 확인하세요.

```python
# app/workers/jobs/order_matcher.py — 30초 주기
def scan_pending_orders():

        return
    symbols = [r[0] for r in db.query(distinct(Order.symbol_code))
                                .filter(Order.status == "대기").all()]
    quotes = {s: market_provider.get_price_sync(s) for s in symbols}   # 캐시 경유

    for order in open_orders(db):
        price = Decimal(quotes[order.symbol_code]["current_price"])
        if order.order_type == "매수" and price <= order.price:
            execute(order, fill_price=min(order.price, price))
        elif order.order_type == "매도" and price >= order.price:
            execute(order, fill_price=max(order.price, price))
```

### 체결가 결정 규칙 (사용자에게 유리하게)
- 매수 지정가 10,000원, 현재가 9,800원 → **9,800원 체결** (더 싸게 샀으므로)
- 매도 지정가 10,000원, 현재가 10,300원 → **10,300원 체결**
- 실제 시장과 동일한 규칙이며, 사용자 만족도도 높습니다.
