# 조회 캐시 규칙

새 기능의 HTTP 요청은 `src/api/client.js`의 공통 클라이언트를 사용한다.
GET 요청에는 기본적으로 5초 메모리 캐시가 적용된다. URL, 쿼리,
응답 형식, 헤더, 로그인 세션이 다른 요청은 공유하지 않는다.
최대 200개를 보관하며 만료된 응답이나 오류를 최신 데이터로 반환하지 않는다.

POST/PUT/PATCH/DELETE 요청은 캐시하지 않고 조회 캐시를 무효화한다.
로그인/로그아웃 및 `orders:changed`도 조회 캐시를 비운다.
주문 직전 가격·호가, 인증 확인 등 최신 응답이 필요한 요청은
`{ cache: false }`를 전달한다. `useRemote.reload()`도 캐시를 우회한다.

화면 재진입 시 이전 내용을 즉시 보여주려면 `useRemote`에 모든 조회
인자를 포함하는 `cacheKey`를 지정한다. 공개 데이터에만 `publicCache: true`를
사용한다. 이 화면 캐시는 기존처럼 최대 24시간 localStorage에 보관하며
표시 후 최신 데이터를 조회한다. 호가·체결·일별 탭도 이 방식을 사용한다.

공통 클라이언트를 거치지 않는 fetch/외부 SDK 요청에는 자동 적용되지 않는다.
