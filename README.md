# Stockmaster
유한대학교 컴소과 3-2 모의투자 ai 학습형 졸업작품프로젝트

실행 방법은 [팀원 연동 실행 가이드](./Doc/팀원_연동_실행가이드.md)를 참고하세요.
프론트만 실행해 팀 배포 백엔드에 연결하거나, 두 저장소를 각각 로컬에서 실행할 수 있습니다.

## 팀원 실행 가이드

**화면을 확인하려면 프론트만 실행하고 팀 배포 백엔드에 연결하면 됩니다.** 프론트 팀원에게 DB 비밀번호나 KIS API 키는 필요하지 않습니다. 실제 데이터 제공을 위한 설정은 백엔드 서버에 있어야 합니다.

| 실행 방식 | 용도 | 준비물 |
|---|---|---|
| 로컬 프론트 + 배포 백엔드 | 화면·API 연동 확인 | 이 저장소, Node.js/npm, 대상 서버 계정 |
| 로컬 프론트 + 로컬 백엔드 | 백엔드 수정까지 확인 | 위 항목 + 백엔드 저장소, Python, PostgreSQL 개발 DB, 기능별 API 설정 |

아래 명령은 **Windows PowerShell** 기준입니다. 상세 DB 설정과 오류 진단은 [팀원 API 연동 실행 가이드](./Doc/팀원_연동_실행가이드.md)에 있습니다.

### 1. 코드 받기

처음이라면 작업할 상위 폴더에서 실행합니다.

```powershell
git clone https://github.com/202207056/Stockmaster.git
cd Stockmaster
```

팀에서 전달한 브랜치로 이동합니다. 아래 브랜치명은 실제 이름으로 바꿉니다.

```powershell
git fetch origin
git switch 전달받은_브랜치명
git pull --ff-only
git log -1 --oneline
```

이미 코드를 받았다면 `git status --short`로 로컬 수정을 확인하고 보존한 뒤 최신 코드를 받습니다. **공유자가 커밋·push하지 않은 변경은 pull로 받을 수 없습니다.** 백엔드 코드 변경과 배포 서버 업데이트도 별개입니다.

### 2. 프론트 설치

현재 프론트 검사는 Node.js 24 환경에서 수행했습니다. Node.js와 npm을 준비한 뒤 저장소 루트에서 실행합니다.

```powershell
node --version
npm.cmd --version
cd frontend
npm.cmd ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

### 3. API 주소 설정

`frontend/.env`를 다음과 같이 맞춥니다. 기존 파일은 위 복사 명령으로 덮어쓰지 않으므로 직접 확인합니다.

```dotenv
VITE_API_BASE_URL=https://gp-mock-inv.onrender.com/api
VITE_ENABLE_ORDER_SUBMISSION=false
```

- API 주소 끝에는 `/api`를 포함합니다. `/docs`를 넣지 않습니다.
- `VITE_` 값은 브라우저에 공개됩니다. KIS 키·DB 접속 정보·JWT 서명키를 넣지 않습니다.
- 주문 전송은 현재 점검 때문에 기본 비활성화입니다.
- 환경변수가 없으면 코드의 기본 주소인 `http://localhost:8000/api`로 연결합니다.

### 4. 실행 및 가입

`frontend` 폴더에서 실행합니다.

```powershell
npm.cmd run dev
```

터미널의 `Local` 주소로 접속합니다. 보통 `http://localhost:5173`이며 포트가 사용 중이면 달라질 수 있습니다. 종료는 `Ctrl+C`입니다. `.env` 수정 후에는 개발 서버를 재시작합니다.

1. `/signup`에서 팀원별로 겹치지 않는 아이디·이메일로 가입하거나, 제공받은 계정으로 `/login`에서 로그인합니다. 미리 만들어져 있다고 확인된 공통 테스트 계정은 없습니다.
2. 가입 후 자동 로그인과 설문 이동을 확인합니다. 연결 점검부터 하려면 설문을 건너뜁니다.
3. `/mypage`에서 사용자 정보, `/assets`에서 본인 계좌를 확인합니다. 현재 백엔드는 신규 가입 시 초기 예수금 1,000만원의 모의 계좌를 생성합니다.

**가입·설문·게시글은 선택한 백엔드의 DB에 저장됩니다.** 배포 서버 계정과 별도 로컬 DB 계정은 자동으로 공유되지 않습니다.

### 5. 실제 데이터 확인

로그인한 상태에서 순서대로 확인합니다. 화면 실행과 로그인 성공만으로 시세 연동까지 성공한 것은 아닙니다.

| 확인할 화면 | 확인 방법 |
|---|---|
| 트레이딩 종목 검색 | `005930` 검색 → 삼성전자 선택 → 종목명 확인 |
| 현재가·차트 | 가격과 일봉 차트 표시 확인 |
| 관심종목 | 종목 담기 → 관심종목 화면에서 가격 조회 확인 |
| 홈 순위 | 거래대금·급상승·인기 종목 3개 영역, 각각 최대 5개 표시 확인 |
| 뉴스·커뮤니티 | API 목록 또는 실제 빈 응답 확인 |

현재 상태는 다음과 같습니다.

- 상단 주요 시세는 해당 API가 미구현되어 `— / 준비 중`으로 표시합니다.
- 현재가·차트는 KIS 모의투자 키, 순위는 별도의 실전투자 키를 사용합니다. 순위가 나와도 차트는 실패할 수 있습니다.
- 관심종목 목록은 계정별 브라우저 저장이며 다른 PC와 자동 동기화되지 않습니다.
- 보호된 데이터는 로그인 후 조회합니다. 주문 버튼은 기본 비활성화입니다.
- 빈 순위 응답은 백엔드 외부 API 오류일 수도 있어, 빈 목록만으로 정상 판정하지 않습니다.

## 로컬 백엔드에 연결하려면

[백엔드 저장소](https://github.com/202207048/gp-mock-inv)를 별도로 받고, [상세 가이드의 방법 B](./Doc/팀원_연동_실행가이드.md#8-방법-b--백엔드와-db까지-로컬-실행)를 따라 진행합니다.

1. Python 가상환경과 의존성을 설치합니다.
2. 독립 개발 PostgreSQL DB를 만들고 `backend/.env`에 접속 정보·서명키를 설정합니다.
3. 기존 Alembic 마이그레이션과 종목 시드를 적용합니다.
4. 백엔드를 8000번 포트로 실행하고 `/docs`에서 확인합니다.
5. `frontend/.env`를 아래와 같이 바꾸고 프론트를 재시작합니다.

```dotenv
VITE_API_BASE_URL=http://localhost:8000/api
VITE_ENABLE_ORDER_SUBMISSION=false
```

이전 서버에서 로그아웃한 뒤 로컬 DB에 가입·로그인합니다. 각자의 `localhost`는 자기 PC입니다. 다른 팀원의 백엔드에 접속하려면 접근 가능한 주소와 네트워크·CORS 설정이 필요합니다.

## 조회가 실패할 때

`F12` → **Network** → **Fetch/XHR**에서 실패한 요청을 선택하고 실제 URL, 상태 코드, Response를 확인합니다. 응답이 없다면 Console 오류도 확인합니다.

| 증상 | 먼저 확인 |
|---|---|
| `localhost:8000` 연결 실패 | 배포 주소 설정 누락 또는 로컬 백엔드 미실행 |
| 401 / 비로그인 403 | 대상 서버 계정으로 로그인, 인증 헤더 확인 |
| 종목 상세 404 | DB에 해당 종목이 있는지 확인 |
| 현재가·차트 500 | 백엔드 로그에서 KIS 모의 키·토큰·외부 응답 확인 |
| 서버에 연결할 수 없다는 문구 | 주소·서버 연결·CORS 확인. 사용자 인터넷 문제로 단정하지 않음 |
| 차트·순위가 빈 배열 | 서버 API 설정과 외부 응답 확인 |

배포 서버 상태는 `https://gp-mock-inv.onrender.com/`, 명세는 `https://gp-mock-inv.onrender.com/docs`에서 확인합니다. 상태 확인의 `200`은 DB·KIS 정상까지 보장하지 않습니다.

같은 서버의 Swagger에서 로그인·Authorize 후 동일한 종목의 `/price`, `/chart`를 실행해 프론트 결과와 비교합니다. 자세한 클릭 순서와 백엔드 전달 양식은 [상세 가이드](./Doc/팀원_연동_실행가이드.md)를 참고합니다. 실패 시각·요청 경로·상태 코드·오류 메시지를 기록하되 비밀번호나 토큰은 공유하지 않습니다.

## 코드 검사

`frontend` 폴더에서 실행합니다.

```powershell
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

자동 테스트는 로컬 응답 어댑터를 사용합니다. 테스트 통과는 실제 배포 서버의 로그인·시세 성공을 의미하지 않으므로 위 화면 점검을 별도로 수행합니다.
